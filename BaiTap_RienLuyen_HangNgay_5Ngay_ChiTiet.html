THỨ 2: MATH DERIVATION — HỆ ĐỆM TỪ (MAGLEV)

Thời lượng: ~35 phút | Mục tiêu: Tự tay giải phương trình vật lý phi tuyến ra ma trận A, B

BƯỚC 1: HÌNH DUNG VẬT LÝ (10 Phút)

Nam châm điện treo ở trên, hòn bi thép ở dưới. Khoảng cách giữa nam châm và bi là $x$ ($x > 0$).

┌────────────────────────┐ │ Nam châm điện quay góc │ └───────────┬────────────┘ │ Dòng điện i(t) ▼ ┌────────────────────────┐ │ Lực hút F_mag = k*i²/x²│ └───────────┬────────────┘ │ (hút BI lên trên) ▲ │ x (vị trí bi) ● Bi thép (khối lượng m) │ ▼ (hút BI xuống dưới) Trọng lực m*g

Cơ chế lực:

  • Trọng lực $m \cdot g$ kéo bi xuống dưới.
  • Lực từ $F_{\text{mag}} = k \frac{i^2}{x^2}$ hút bi lên trên. (Chú ý: $x$ càng nhỏ tức bi càng gần nam châm thì lực hút càng lớn mạnh gấp bội!).

Phương trình động lực học tổng tổng quát:

$$m \ddot{x} = m g - k \frac{i^2}{x^2}$$
BƯỚC 2: TÍNH TOÁN THEO HƯỚNG DẪN (15 Phút)
  1. Tìm dòng điện cân bằng $i_0$: Đặt $\ddot{x} = 0$, vị trí bi mong muốn là $x_0$. Rút $i_0$ ra theo $m, g, k, x_0$.
  2. Tuyến tính hóa $F(x, i) = k i^2 x^{-2}$ quanh $(x_0, i_0)$:

    Dùng công thức Taylor: $F(x, i) \approx F(x_0, i_0) + \left.\frac{\partial F}{\partial x}\right|_0 \Delta x + \left.\frac{\partial F}{\partial i}\right|_0 \Delta i$

    • Tính $\frac{\partial F}{\partial x} = -2k \frac{i^0}{x^0}^3$. Thay $k i_0^2 = m g x_0^2$ vào để rút gọn!
    • Tính $\frac{\partial F}{\partial i} = 2k \frac{i_0}{x_0^2}$.
  3. Ráp vào phương trình tuyến tính: Đặt $x_1 = \Delta x, x_2 = \Delta \dot{x}, u = \Delta i$. Viết phương trình cho $\dot{x}_1$ và $\dot{x}_2$.
BƯỚC 3: ĐỐI CHIẾU ĐÁP ÁN (10 Phút)

Hãy tự làm ra nháp trước, sau đó bấm nút bên dưới để kiểm tra kết quả!

✅ Lời Giải Từng Bước Bài Thứ 2:

1. Dòng điện cân bằng $i_0$:

$$m(0) = mg - k \frac{i_0^2}{x_0^2} \implies k \frac{i_0^2}{x_0^2} = mg \implies \mathbf{i_0 = x_0 \sqrt{\frac{mg}{k}}}$$

2. Đạo hàm riêng tại điểm cân bằng:

$$\left.\frac{\partial F}{\partial x}\right|_0 = -2k \frac{i_0^2}{x_0^3} = -2 \frac{(k i_0^2 / x_0^2)}{x_0} = \mathbf{-2 \frac{mg}{x_0}}$$ $$\left.\frac{\partial F}{\partial i}\right|_0 = 2k \frac{i_0}{x_0^2} = 2k \frac{x_0 \sqrt{mg/k}}{x_0^2} = \mathbf{2 \frac{\sqrt{kmg}}{x_0}}$$

3. Thay vào phương trình vi phân:

$$m \Delta \ddot{x} = mg - \left[ mg - 2\frac{mg}{x_0}\Delta x + 2\frac{\sqrt{kmg}}{x_0}\Delta i \right] = 2\frac{mg}{x_0}\Delta x - 2\frac{\sqrt{kmg}}{x_0}\Delta i$$ $$\Delta \ddot{x} = \left(\frac{2g}{x_0}\right) \Delta x - \left(\frac{2}{x_0}\sqrt{\frac{kg}{m}}\right) \Delta i$$

4. Ma trận State Space $A, B$:

$$\begin{bmatrix} \dot{x}_1 \\ \dot{x}_2 \end{bmatrix} = \underbrace{\begin{bmatrix} 0 & 1 \\ \frac{2g}{x_0} & 0 \end{bmatrix}}_{A} \begin{bmatrix} x_1 \\ x_2 \end{bmatrix} + \underbrace{\begin{bmatrix} 0 \\ -\frac{2}{x_0}\sqrt{\frac{kg}{m}} \end{bmatrix}}_{B} u$$

5. Trị riêng của $A$: $\lambda^2 - \frac{2g}{x_0} = 0 \implies \mathbf{\lambda_{1,2} = \pm \sqrt{\frac{2g}{x_0}}}$.

Trị riêng $\lambda_1 = +\sqrt{\frac{2g}{x_0}} > 0 \implies$ **Hệ mở MagLev BẤT ỔN ĐỊNH MẠNH!** Quá rõ ràng: nếu bi nhích xuống 1mm, lực hút giảm làm bi rơi; nếu bi nhích lên 1mm, lực hút tăng làm bi dính chặt vào nam châm!

THỨ 3: CODE RK4 SIMULATOR CON LẮC ĐƠN (C++ THUẦN)

Thời lượng: ~35 phút | Mục tiêu: Tự tay viết thuật toán tích phân số RK4 không phụ thuộc thư viện

BƯỚC 1: HIỂU THUẬT TOÁN RK4 TRONG 3 PHÚT (10 Phút)

Để dự đoán trạng thái tiếp theo $y_{k+1}$ từ $y_k$ với bước thời gian $dt$, phương pháp Euler đơn giản dùng: $y_{k+1} = y_k + f(y_k) \cdot dt$ (rất dễ bị sai số tích lũy!).

Runge-Kutta 4 (RK4) thông minh hơn: Nó lấy mẫu 4 điểm độ dốc ($k_1, k_2, k_3, k_4$) rồi lấy trung bình trọng số:

y_k ──► [k1: đầu bước] ──► [k2: giữa bước A] ──► [k3: giữa bước B] ──► [k4: cuối bước] │ ▼ y_{k+1} = y_k + (dt / 6) * (k1 + 2*k2 + 2*k3 + k4)
BƯỚC 2: CODE THEO SƯỜN MẪU (15 Phút)

Hãy tạo một file `main.cpp` trên máy tính hoặc trang gõ C++ online (như onlinegdb.com) và điền vào sườn code dưới đây:

#include <iostream>
#include <cmath>

struct State {
    double theta; // Góc (rad)
    double omega; // Vận tốc góc (rad/s)
};

// Đạo hàm: d/dt [theta, omega] = [omega, theta_double_dot]
State dynamics(const State& s, double u) {
    double g = 9.81, l = 0.4, b = 0.05, m = 0.5;
    State ds;
    ds.theta = s.omega;
    ds.omega = -(g/l)*std::sin(s.theta) - (b/(m*l*l))*s.omega + u;
    return ds;
}

BƯỚC 3: CHẠY CODE & ĐỐI CHIẾU (10 Phút)

Cho mô phỏng chạy 5 giây khi thả con lắc từ góc $\theta_0 = 45^\circ$. Bấm nút bên dưới để xem code hoàn chỉnh và đối chiếu kết quả!

✅ Code C++ RK4 Simulator Hoàn Chỉnh:

#include <iostream>
#include <cmath>
#include <iomanip>

struct State {
    double theta;
    double omega;
};

State dynamics(const State& s, double u) {
    double g = 9.81, l = 0.4, b = 0.05, m = 0.5;
    State ds;
    ds.theta = s.omega;
    ds.omega = -(g / l) * std::sin(s.theta) - (b / (m * l * l)) * s.omega + u;
    return ds;
}

State rk4_step(const State& s, double dt, double u) {
    State k1 = dynamics(s, u);
    
    State s2 = { s.theta + 0.5 * dt * k1.theta, s.omega + 0.5 * dt * k1.omega };
    State k2 = dynamics(s2, u);
    
    State s3 = { s.theta + 0.5 * dt * k2.theta, s.omega + 0.5 * dt * k2.omega };
    State k3 = dynamics(s3, u);
    
    State s4 = { s.theta + dt * k3.theta, s.omega + dt * k3.omega };
    State k4 = dynamics(s4, u);
    
    State next_s;
    next_s.theta = s.theta + (dt / 6.0) * (k1.theta + 2.0*k2.theta + 2.0*k3.theta + k4.theta);
    next_s.omega = s.omega + (dt / 6.0) * (k1.omega + 2.0*k2.omega + 2.0*k3.omega + k4.omega);
    return next_s;
}

int main() {
    State s = { 45.0 * M_PI / 180.0, 0.0 }; // Thả từ 45 độ
    double dt = 0.01; // 10ms
    
    std::cout << std::fixed << std::setprecision(3);
    std::cout << "Thoi Gian(s)\tGoc Theta(Do)\tToc Do Omega(rad/s)\n";
    std::cout << "--------------------------------------------------\n";
    
    for (double t = 0; t <= 3.0; t += dt) {
        if (std::fmod(t, 0.5) < dt) { // In ra console mỗi 0.5s
            std::cout << t << "\t\t" << s.theta * 180.0 / M_PI << "\t\t" << s.omega << "\n";
        }
        s = rk4_step(s, dt, 0.0);
    }
    return 0;
}

THỨ 4: FAULT INJECTION & TROUBLESHOOTING

Thời lượng: ~35 phút | Mục tiêu: Nhận diện 3 dạng đồ thị lỗi phổ biến nhất trên phần cứng

BƯỚC 1: QUAN SÁT 3 DẠNG ĐỒ THỊ LỖI (10 Phút)

Khi bạn chạy mô phỏng robot hoặc nạp code xuống STM32, nếu có sự cố xảy ra, đồ thị tín hiệu sẽ có 3 "hình dạng đặc trưng" sau đây:

DẠNG 1: DỒN RÁC NHIỄU HẠT (Tần số cực cao) u(t) ──┼─┼──┼─┼─┼──┼─┼───► Tín hiệu PWM giật liên tục lên xuống xé rách đồ thị! DẠNG 2: DAO ĐỘNG ĐIỀU HÒA TỰ DO (Phân kỳ 2-3Hz) θ(t) ───/\───/ \───/ \───► Biên độ sóng cứ sau mỗi 0.5s lại phình to ra cho đến khi ngã! DẠNG 3: BỊ BẸT PHẲNG NẰM NĂNG (Bão hòa Saturation) u(t) ─────────────── (+12V) ──► Tín hiệu bít chặt ở trần +12V hoặc sàn -12V không nhúc nhích!
BƯỚC 2: NỐI HIỆN TƯỢNG VỚI NGUYÊN NHÂN (15 Phút)

Hãy nối 3 **Hiện tượng Đồ thị** ở trên với 3 **Nguyên nhân Kỹ thuật** dưới đây:

  1. Nguyên nhân A: Trễ tín hiệu lấy mẫu (Delay 20ms). Làm sụt giảm Phase Margin của hệ vòng kín về 0°.
  2. Nguyên nhân B: Nhiễu cảm biến góc IMU bị khâu D (hoặc Gain $K_{\dot{\theta}}$) khuếch đại.
  3. Nguyên nhân C: Điện áp động cơ bị chạm ngưỡng bão hòa tối đa ($V_{\max} = 12\text{V}$). Bộ điều khiển yêu cầu $20\text{V}$ nhưng driver chỉ cấp được $12\text{V}$.
BƯỚC 3: ĐỐI CHIẾU KẾT QUẢ CHẨN ĐOÁN (10 Phút)

✅ Ghép Nối Đáp Án & Cách Sửa Sự Cố:

  • Dạng 1 (Đồ thị xé rách) $\rightarrow$ Nguyên nhân B (Nhiễu Cảm Biến): Khi cảm biến IMU bị rung, khâu vi phân $D = K_d \frac{\Delta \theta}{\Delta t}$ lấy đạo hàm nhiễu trắng sinh ra các đỉnh xung khổng lồ. Cách sửa: Cài đặt Complementary Filter hoặc Kalman Filter để làm mượt $\theta$ trước khi đưa vào bộ điều khiển.
  • Dạng 2 (Dao động 2-3Hz phình to) $\rightarrow$ Nguyên nhân A (Trễ Tín Hiệu Delay): Trễ $20\text{ms}$ tương đương với việc xoay ngược pha tín hiệu phản hồi. Bộ điều khiển phản ứng chậm nhịp, "cứu xe" trễ thời điểm làm dao động bùng nổ. Cách sửa: Tăng tần số lấy mẫu ngắt Timer từ 50Hz lên 200Hz ($T_s = 5\text{ms}$).
  • Dạng 3 (Bệt phẳng trần +12V) $\rightarrow$ Nguyên nhân C (Bão Hòa Saturation): Khi $u(t)$ bị xén ở $+12\text{V}$, vòng phản hồi bị ngắt đứt (Open-loop). Xe không còn chịu sự điều khiển của LQR nữa. Cách sửa: Tăng trọng số $R$ trong LQR để hạ Gain $K$, giúp LQR đòi lực vừa phải hơn.

THỨ 5: EMBEDDED C++ — CLASS PID ZERO-ALLOCATION

Thời lượng: ~35 phút | Mục tiêu: Viết C++ Class điều khiển chuẩn nhúng Real-Time không dùng heap memory

BƯỚC 1: TẠI SAO CẦN ZERO-ALLOCATION? (10 Phút)

Trong hệ thống nhúng Real-time (như ô tô, drone, robot), nếu bạn dùng `new`, `malloc` hoặc `std::vector` bên trong vòng lặp ngắt 200Hz:

  • Bộ nhớ vi điều khiển sẽ bị **phân mảnh (fragmentation)** sau vài giờ chạy.
  • Thời gian cấp phát bộ nhớ không cố định (Non-deterministic time) $\rightarrow$ Vi phạm chuẩn Real-time!

Giải pháp: Tất cả biến trạng thái (`integrator`, `prev_error`) phải khai báo sẵn trong struct/class cố định.

BƯỚC 2: VIẾT CODE C++ PID CLASS (15 Phút)

Tham khảo sườn code chuẩn C++17 và gõ lại vào máy của bạn:

namespace control {

class PIDController {
public:
    struct Config {
        float kp{0.0f}, ki{0.0f}, kd{0.0f};
        float u_min{-12.0f}, u_max{12.0f}; // Ngưỡng bão hòa
    };

    explicit PIDController(const Config& cfg) : cfg_(cfg) {}

    float update(float setpoint, float measurement, float dt) noexcept {
        float error = setpoint - measurement;
        float p_term = cfg_.kp * error;
        
        // Khâu D đơn giản
        float d_term = cfg_.kd * (error - prev_error_) / dt;
        
        // Khâu I
        integrator_ += cfg_.ki * error * dt;
        
        float u_raw = p_term + integrator_ + d_term;
        
        // Anti-Windup Clamping
        if (u_raw > cfg_.u_max) {
            u_raw = cfg_.u_max;
            integrator_ -= cfg_.ki * error * dt; // Dừng cộng dồn tích phân khi bão hòa!
        } else if (u_raw < cfg_.u_min) {
            u_raw = cfg_.u_min;
            integrator_ -= cfg_.ki * error * dt;
        }

        prev_error_ = error;
        return u_raw;
    }

private:
    Config cfg_;
    float integrator_{0.0f};
    float prev_error_{0.0f};
};

} // namespace control
BƯỚC 3: ĐỐI CHIẾU & CHẠY THỬ (10 Phút)

Bấm nút bên dưới để xem code giải lập hoàn chỉnh có khâu LPF lọc nhiễu D-term!

✅ Code C++ PID Controller Nhúng Tối Ưu:

#include <iostream>
#include <algorithm>

namespace control {

class PIDController {
public:
    struct Config {
        float kp{10.0f};
        float ki{2.0f};
        float kd{0.5f};
        float tf{0.01f};     // Hằng số lọc D-term (s)
        float u_min{-12.0f};
        float u_max{12.0f};
    };

    explicit PIDController(const Config& cfg) noexcept : cfg_(cfg) {}

    float update(float setpoint, float measurement, float dt) noexcept {
        if (dt <= 0.0f) return 0.0f;
        float error = setpoint - measurement;

        // 1. Khâu P
        float p_term = cfg_.kp * error;

        // 2. Khâu D với LPF lọc nhiễu
        float d_raw = (error - prev_error_) / dt;
        float alpha = dt / (dt + cfg_.tf);
        d_filtered_ += alpha * (d_raw - d_filtered_);
        float d_term = cfg_.kd * d_filtered_;

        // 3. Khâu I tạm tính
        float i_next = integrator_ + cfg_.ki * error * dt;

        // 4. Tổng đầu ra
        float u_raw = p_term + i_next + d_term;
        float u_sat = std::clamp(u_raw, cfg_.u_min, cfg_.u_max);

        // Anti-Windup Clamping
        if (u_raw == u_sat) {
            integrator_ = i_next;
        }

        prev_error_ = error;
        return u_sat;
    }

private:
    Config cfg_;
    float integrator_{0.0f};
    float prev_error_{0.0f};
    float d_filtered_{0.0f};
};

} // namespace control

int main() {
    control::PIDController pid({});
    float state = 0.0f;
    for (int i = 0; i < 5; ++i) {
        float u = pid.update(1.0f, state, 0.01f);
        std::cout << "Buoc " << i << " | Dien ap u = " << u << " V\n";
        state += u * 0.02f;
    }
    return 0;
}

THỨ 6: TUNING & ANALYSIS — LQR BÃO HÒA 12V

Thời lượng: ~35 phút | Mục tiêu: Nắm vững quy tắc Bryson's Rule để Tuning Q, R trên mô hình thật

BƯỚC 1: NẮM NGUYÊN TẮC BRYSON'S RULE TRONG 2 PHÚT (10 Phút)

Khi chọn ma trận phạt $Q$ và $R$ trong LQR, thay vì đoán mò ngẫu nhiên, ta áp dụng công thức Bryson's Rule:

$$Q_{ii} = \frac{1}{(\text{Sai lệch tối đa cho phép của trạng thái } x_i)^2}$$ $$R_{jj} = \frac{1}{(\text{Lực/Điện áp tối đa cho phép của } u_j)^2}$$
BƯỚC 2: TÍNH TOÁN THAM SỐ $Q, R$ CHO ROBOT (15 Phút)

Cho Robot Tự Cân Bằng với 4 trạng thái $x = [x, \dot{x}, \theta, \dot{\theta}]^T$ và nguồn pin $12\text{V}$ ($u_{\max} = 12\text{V}$):

  • Cho phép xe trôi tối đa $x_{\max} = 0.2\text{ m} \implies Q_{11} = \frac{1}{0.2^2} = \mathbf{25}$.
  • Cho phép vận tốc xe $x_{\dot{x},\max} = 1.0\text{ m/s} \implies Q_{22} = \frac{1}{1.0^2} = \mathbf{1.0}$.
  • Cho phép góc nghiêng tối đa $\theta_{\max} = 0.05\text{ rad} \approx 3^\circ \implies Q_{33} = \frac{1}{0.05^2} = \mathbf{400}$.
  • Cho phép tốc độ góc $\dot{\theta}_{\max} = 1.0\text{ rad/s} \implies Q_{44} = \frac{1}{1.0^2} = \mathbf{1.0}$.
  • Cho phép điện áp tối đa $u_{\max} = 12\text{V} \implies R = \frac{1}{12^2} = \mathbf{0.00694}$.
BƯỚC 3: ĐỐI CHIẾU VỚI CÁC TRƯỜNG HỢP TUNING SAI (10 Phút)

Bấm nút bên dưới để xem so sánh kết quả khi Tuning đúng vs Tuning sai!

✅ Phân Tích Kết Quả 3 Kịch Bản Tuning LQR:

Kịch bản TuningMa trận Q, RĐáp ứng thực tế trên Robot
1. Phạt góc quá bé $Q_{33} = 1, R = 0.007$ ❌ Robot bị ngã đổ ngay lập tức! Do Gain $K_\theta$ quá nhỏ, không đủ điện áp cứu xe khi bị nghiêng $3^\circ$.
2. Lái quá hung hãn $Q_{33} = 400, R = 0.00001$ ❌ Tín hiệu $u(t)$ bị đập mép $\pm 12\text{V}$ liên tục! Gain $K$ quá lớn làm LQR đòi điện áp $30\text{V}$, dẫn đến bão hòa mạch cầu H và làm xe bị giật rung lắc (Chattering).
