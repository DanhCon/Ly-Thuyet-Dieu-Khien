🎯 Vì sao C++ áp đảo tuyệt đối trong Robotics & Autonomous Vehicles?

Một chiếc xe tự hành chạy với tốc độ $80\text{ km/h}$ di chuyển khoảng 22.2 mét mỗi giây. Nếu thuật toán tránh vật cản bị chậm $50\text{ms}$ do trình thu gom rác (Garbage Collector của Python, Java hay Go) tạm dừng hệ thống để dọn bộ nhớ, hậu quả là va chạm không thể đảo ngược. C++ cung cấp 3 điều kiện tiên quyết mà không ngôn ngữ nào thay thế được:

  1. Deterministic Real-Time Performance (Tính xác định về thời gian): Không có Garbage Collector bất ngờ tạm dừng chương trình. Bộ nhớ được cấp phát và giải phóng chính xác tại thời điểm lập trình viên yêu cầu. Vòng lặp điều khiển $1000\text{ Hz}$ ($1\text{ms}$) luôn chạy đúng tiến độ.
  2. Hardware-Level Memory Control (Thao tác sát phần cứng): Đọc trực tiếp bộ nhớ CAN Bus xe, thanh ghi cảm biến IMU/Encoder qua I2C/SPI, bộ nhớ DMA với độ trễ microgiây ($\mu s$).
  3. Zero-Cost Abstractions (Trừu tượng hóa chi phí bằng 0): Lập trình Hướng đối tượng (OOP), Template, Lambda cực kỳ đẹp mắt và dễ đọc, nhưng khi biên dịch qua g++ -O3, trình biên dịch tối ưu thành mã máy cực nhanh hệt như C thuần hoặc Assembly.

0.1 Tối ưu CPU Cache Line & RAM Locality trong C++

Bộ nhớ RAM hiện đại hoạt động dựa trên cơ chế CPU Cache (L1, L2, L3 Cache Line size = 64 bytes). Khi CPU truy cập mảng phần tử nằm liên tục trong bộ nhớ (như std::vector hay std::array của C++), CPU Prefetcher sẽ tự động nạp sẵn 64-byte xung quanh vào L1 Cache với độ trễ chỉ 1ns. Ngược lại, các ngôn ngữ có Garbage Collection quản lý các đối tượng rải rác trên Heap, gây hiện tượng Cache Miss khiến CPU phải chờ nạp từ RAM mất 100ns (chậm hơn 100 lần!). Đây chính là chìa khóa giúp C++ xử lý 300,000 điểm mây LiDAR mỗi giây thời gian thực.

1.2 Con trỏ (*) vs Tham chiếu (&) vs Const Correctness

📌 Phân biệt 3 bản chất cốt lõi
  • Con trỏ (Pointer T*): Biến lưu địa chỉ bộ nhớ của biến khác. Có thể gán nullptr, có thể thay đổi địa chỉ trỏ tới. Kích thước hằng số ($8\text{ bytes}$ trên hệ 64-bit).
  • Tham chiếu (Reference T&): Bí danh (alias) trực tiếp của một biến đã tồn tại. Không thể null, không thể đổi sang trỏ biến khác sau khi khởi tạo.
  • Tham chiếu hằng (const T&): Truyền tham số không tốn chi phí copy, đồng thời bảo vệ biến không bị sửa đổi. Đây là chuẩn mực vàng truyền tham số trong C++ Robotics!

Ví dụ code 1: Phân biệt 4 cách truyền tham số mảng cảm biến LiDAR

#include <iostream>
#include <vector>
#include <chrono>

struct LidarScan {
    std::vector<double> ranges; // 360 tia quét LiDAR
    double timestamp;
};

// 1. Truyền bằng Pass-by-Value (Copy toàn bộ mảng): TẠO LỖI NGHỄN BỘ NHỚ!
void process_scan_bad(LidarScan scan) {
    // scan là bản sao độc lập! Copy 360 tia mất thời gian CPU.
}

// 2. Truyền bằng Pass-by-Reference (Tham chiếu): Nhanh, nhưng nguy cơ lỡ tay sửa mảng gốc
void process_scan_ref(LidarScan& scan) {
    scan.ranges[0] = 0.0; // ⚠️ Sửa trực tiếp dữ liệu bên ngoài!
}

// 3. Truyền bằng Pass-by-Const-Reference (CHUẨN ROBOTICS): Nhanh + An toàn
void process_scan_good(const LidarScan& scan) {
    // scan.ranges[0] = 0.0; // ❌ LỖI BIÊN DỊCH: Không cho phép sửa!
    std::cout << "So tia LiDAR: " << scan.ranges.size() << "\n";
}

// 4. Truyền bằng Con trỏ (Pointer): Dùng khi tham số có thể KHÔNG TỒN TẠI (null)
void process_scan_pointer(const LidarScan* scan_ptr) {
    if (scan_ptr == nullptr) { // 🔍 BẮT BUỘC CHECK NULLPTR!
        std::cout << "Lidar scan khong ton tai (NULL)\n";
        return;
    }
    std::cout << "Timestamp: " << scan_ptr->timestamp << "\n";
}

int main() {
    LidarScan my_scan;
    my_scan.ranges.resize(360, 5.2); // 360 tia khoảng cách 5.2m
    my_scan.timestamp = 100.25;

    process_scan_good(my_scan);       // Chi phí copy = 0ms!
    process_scan_pointer(&my_scan);   // Truyền địa chỉ
    process_scan_pointer(nullptr);    // Xử lý an toàn khi không có dữ liệu
    return 0;
}

BT1.1: Sửa lỗi Segfault trong đoạn code sau và giải thích nguyên nhân:

double* read_encoder() {

BT1.2: So sánh hai hàm swap_ptr(int* a, int* b) và swap_ref(int& a, int& b). Khi nào bắt buộc dùng Pointer?

✅ Lời giải BT1.2 
#include <iostream>

void swap_ptr(int* a, int* b) {
    if (!a || !b) return; // Phải check nullptr
    int tmp = *a; *a = *b; *b = tmp;
}

void swap_ref(int& a, int& b) {
    int tmp = a; a = b; b = tmp; // Không cần check null!
}

int main() {
    int x = 5, y = 10;
    swap_ref(x, y);
    std::cout << "Swap ref: x=" << x << ", y=" << y << "\n";
    return 0;
}

Khi nào bắt buộc dùng Pointer: Khi tham số có thể là nullptr (optional payload) hoặc khi bạn cần thay đổi chính địa chỉ mà con trỏ trỏ tới (re-pointing).

BT1.3: Kiểm tra tính Const Correctness trong phương thức get_speed() của class Motor. Tại sao thêm const ở cuối phương thức?

✅ Lời giải BT1.3 
#include <iostream>

class Motor {
private:
    double speed_ = 5.0;
public:
    // Thêm const ở cuối báo hiệu phương thức này READ-ONLY (không sửa đổi biến member speed_)
    double get_speed() const { return speed_; }
};

void print_motor_speed(const Motor& m) {
    // Bắt buộc get_speed() phải có const ở cuối mới gọi được tại đây!
    std::cout << "Speed: " << m.get_speed() << " m/s\n";
}

int main() {
    Motor my_motor;
    print_motor_speed(my_motor);
    return 0;
}

Tác dụng: Cho phép gọi get_speed() trên các đối tượng const Motor&.

2.3 Ví dụ 2: Thiết kế Controller Interface đa hình (Polymorphism)

#include <iostream>
#include <vector>
#include <cmath>
#include <memory>

struct RobotState { double x = 0.0, y = 0.0, yaw = 0.0, v = 0.0; };
struct ControlOutput { double steering_angle = 0.0, acceleration = 0.0; };

// --- CLASS CHA TRỪU TƯỢNG (INTERFACE CHUNG CHO MỌI CONTROLLER) ---
class AbstractController {
public:
    // Destructor ảo: BẮT BUỘC để tránh rò rỉ bộ nhớ khi xóa qua con trỏ lớp cha!
    virtual ~AbstractController() {
        std::cout << "[Base] Destructor AbstractController\n";
    }

    // Pure Virtual Function (= 0): Bắt buộc các thuật toán con phải tự triển khai
    virtual ControlOutput compute_control(const RobotState& current_state, 
                                         double target_x, double target_y) = 0;
};

// --- BỘ ĐIỀU KHIỂN 1: PURE PURSUIT ---
class PurePursuitController : public AbstractController {
private:
    double lookahead_distance_;
public:
    PurePursuitController(double L) : lookahead_distance_(L) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double dx = target_x - state.x;
        double dy = target_y - state.y;
        double alpha = std::atan2(dy, dx) - state.yaw;
        out.steering_angle = std::atan2(2.0 * 0.5 * std::sin(alpha), lookahead_distance_);
        out.acceleration = 0.5;
        std::cout << "[PurePursuit] Goc lai: " << out.steering_angle << " rad\n";
        return out;
    }
};

// --- BỘ ĐIỀU KHIỂN 2: STANLEY CONTROLLER ---
class StanleyController : public AbstractController {
private:
    double k_gain_;
public:
    StanleyController(double k) : k_gain_(k) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double cross_track_error = target_y - state.y;
        out.steering_angle = std::atan2(k_gain_ * cross_track_error, state.v + 0.1);
        out.acceleration = 0.2;
        std::cout << "[Stanley] Goc lai: " << out.steering_angle << " rad\n";
        return out;
    }
};

int main() {
    RobotState car{0.0, 0.0, 0.0, 2.0};
    
    // ĐA HÌNH (POLYMORPHISM): Con trỏ Interface quản lý nhiều thuật toán khác nhau
    std::vector<std::unique_ptr<AbstractController>> controllers;
    controllers.push_back(std::make_unique<PurePursuitController>(2.5));
    controllers.push_back(std::make_unique<StanleyController>(0.5));

    for (const auto& ctrl : controllers) {
        ctrl->compute_control(car, 10.0, 3.0);
    }
    return 0;
}

2.4 Ví dụ 3: Giới thiệu Rule of 5 (Quản lý tài nguyên chuẩn C++)

#include <iostream>
#include <cstring>

class HardwareBuffer {
private:
    size_t size_;
    uint8_t* data_;
public:
    // 1. Constructor
    HardwareBuffer(size_t size) : size_(size), data_(new uint8_t[size]) {}

    // 2. Destructor
    ~HardwareBuffer() { delete[] data_; }

    // 3. Copy Constructor (Deep Copy)
    HardwareBuffer(const HardwareBuffer& other) : size_(other.size_), data_(new uint8_t[other.size_]) {
        std::memcpy(data_, other.data_, size_);
    }

    // 4. Copy Assignment Operator
    HardwareBuffer& operator=(const HardwareBuffer& other) {
        if (this == &other) return *this;
        delete[] data_;
        size_ = other.size_;
        data_ = new uint8_t[size_];
        std::memcpy(data_, other.data_, size_);
        return *this;
    }

    // 5. Move Constructor (Move Semantics)
    HardwareBuffer(HardwareBuffer&& other) noexcept : size_(other.size_), data_(other.data_) {
        other.size_ = 0;
        other.data_ = nullptr;
    }
};

3.1 Ba loại Smart Pointers trong C++17

Loại Smart Pointer Quyền sở hữu (Ownership) Ứng dụng thực tế trong ROS 2 / Robotics
std::unique_ptr<T> Độc quyền (Unique): Chỉ duy nhất 1 con trỏ sở hữu. Không thể copy, chỉ có thể chuyển giao quyền sở hữu qua std::move. Dùng mặc định! Chi phí overhead bằng 0 ($0\text{ bytes}$ extra). Dùng cho Driver Cảm biến IMU, Controller Instance, Local Planner.
std::shared_ptr<T> Chia sẻ (Shared): Nhiều con trỏ cùng sở hữu. Vùng nhớ giải phóng khi con trỏ cuối cùng hủy (Reference Count = 0). Dùng khi dữ liệu được đọc bởi nhiều Thread/Node (vd: Bản đồ Costmap 2D được đọc bởi cả Global Planner và Local Planner).
std::weak_ptr<T> Không sở hữu (Weak): Tham chiếu tới shared_ptr mà không làm tăng Reference Count. Tránh vòng lặp tham chiếu (Circular Reference) gây rò rỉ bộ nhớ. Dùng cho Observer Pattern, Action Goal Handles.

#include <iostream>
#include <deque>
#include <numeric>

class MovingAverageIMU {
private:
    size_t window_size_;
    std::deque<double> buffer_;
public:
    MovingAverageIMU(size_t window_size) : window_size_(window_size) {}

    double add_measurement(double val) {
        buffer_.push_back(val);
        if (buffer_.size() > window_size_) {
            buffer_.pop_front();
        }
        double sum = std::accumulate(buffer_.begin(), buffer_.end(), 0.0);
        return sum / buffer_.size();
    }
};

    std::cout << "Filtered: " << filter.add_measurement(10.0) << "\n";
    std::cout << "Filtered: " << filter.add_measurement(12.0) << "\n";
    std::cout << "Filtered: " << filter.add_measurement(14.0) << "\n";

6.3 Class Template: Bộ lọc LowPassFilter dùng chung mọi kiểu dữ liệu

#include <iostream>

template <typename T>
class LowPassFilter {
private:
    T alpha_;
    T prev_output_;
    bool initialized_ = false;
public:
    LowPassFilter(T alpha) : alpha_(alpha), prev_output_(0) {}

    T filter(T input) {
        if (!initialized_) {
            prev_output_ = input;
            initialized_ = true;
            return input;
        }
        T output = alpha_ * input + (static_cast<T>(1.0) - alpha_) * prev_output_;
        prev_output_ = output;
        return output;
    }
};

int main() {
    LowPassFilter<double> vel_filter(0.2);
    std::cout << "Filtered: " << vel_filter.filter(10.0) << "\n";
    std::cout << "Filtered: " << vel_filter.filter(15.0) << "\n";
    return 0;
}

7.2 Mô phỏng Extended Kalman Filter (EKF 2D Localization) C++17

#include <iostream>
#include <optional>
#include <tuple>
#include <cmath>

// Struct lưu trữ trạng thái ước lượng vị trí 2D của Xe Tự Hành
struct State2D {
    double x = 0.0;     // Tọa độ X (mét)
    double y = 0.0;     // Tọa độ Y (mét)
    double yaw = 0.0;   // Góc hướng Robot Heading (radian)
};

// Lớp EKF Solver rút gọn sử dụng các tính năng C++17 hiện đại
class EKFEstimator {
private:
    State2D state_;
public:
    // Buớc Dự Đoán (Predict Step) dựa trên mô hình Động học Xe (Kinematics)
    void predict(double v, double omega, double dt) {
        state_.x += v * std::cos(state_.yaw) * dt;
        state_.y += v * std::sin(state_.yaw) * dt;
        state_.yaw += omega * dt;
    }

    // Bước Cập Nhật (Update Step) khi nhận được tín hiệu đo từ GPS/Landmark
    void update(std::optional<std::pair<double, double>> gps_meas) {
        if (!gps_meas.has_value()) return; // Không có tín hiệu GPS -> Bỏ qua update
        auto [meas_x, meas_y] = gps_meas.value(); // Unpack qua Structured Bindings C++17
        
        // Trọng số Kalman Gain mô phỏng đơn giản alpha blending
        double alpha = 0.4;
        state_.x = (1.0 - alpha) * state_.x + alpha * meas_x;
        state_.y = (1.0 - alpha) * state_.y + alpha * meas_y;
    }

    State2D get_state() const { return state_; }
};

int main() {
    EKFEstimator ekf;
    ekf.predict(1.0, 0.1, 0.1); // v = 1m/s, omega = 0.1 rad/s, dt = 0.1s
    ekf.update(std::make_pair(0.12, 0.01)); // Cập nhật GPS measurement

    auto s = ekf.get_state();
    std::cout << "[EKF Filter] Estimated State: x=" << s.x << ", y=" << s.y << ", yaw=" << s.yaw << "\n";
    return 0;
}

9.2 Lock-Free SPSC Queue Pattern cho Real-Time Threading

#include <iostream>
#include <atomic>
#include <array>

template <typename T, size_t Capacity>
class LockFreeSPSCQueue {
private:
    std::array<T, Capacity> buffer_;
    alignas(64) std::atomic<size_t> head_{0};
    alignas(64) std::atomic<size_t> tail_{0};

public:
    bool push(const T& item) {
        size_t current_tail = tail_.load(std::memory_order_relaxed);
        size_t next_tail = (current_tail + 1) % Capacity;
        if (next_tail == head_.load(std::memory_order_acquire)) {
            return false;
        }
        buffer_[current_tail] = item;
        tail_.store(next_tail, std::memory_order_release);
        return true;
    }

    bool pop(T& item) {
        size_t current_head = head_.load(std::memory_order_relaxed);
        if (current_head == tail_.load(std::memory_order_acquire)) {
            return false;
        }
        item = buffer_[current_head];
        head_.store((current_head + 1) % Capacity, std::memory_order_release);
        return true;
    }
};

int main() {
    LockFreeSPSCQueue<double, 100> imu_queue;
    imu_queue.push(9.81);
    double val;
    if (imu_queue.pop(val)) {
        std::cout << "[Real-Time Queue] Pop Accel Z: " << val << " m/s^2\n";
    }
    return 0;
}

9.3 Phân biệt Callback Group Types trong ROS 2 (MutuallyExclusive vs Reentrant)

Trong ROS 2 rclcpp, mặc định tất cả Callback của 1 Node nằm chung trong Single-Threaded Executor. Nếu một Callback Service tốn thời gian xử lý ($500\text{ms}$), toàn bộ các Timer hay Lidar Subscriber khác sẽ bị đơ (Block). Để khắc phục, ROS 2 sử dụng 2 loại Callback Group:

  • MutuallyExclusiveCallbackGroup: Các Callback trong nhóm này chỉ được thực thi từng cái một (Không bao giờ song song). Giúp tránh Race Condition mà không cần Mutex.
  • ReentrantCallbackGroup: Các Callback trong nhóm này có thể chạy song song đồng thời trên nhiều Thread trong MultiThreadedExecutor. Bắt buộc phải bảo vệ tài nguyên dùng chung bằng std::mutex!

#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>

// Bộ điều khiển PID tích hợp thuật toán bão hòa (Saturation) và chống phình tích phân (Anti-windup)
class PIDController {
private:
    double kp_, ki_, kd_, dt_;
    double min_out_, max_out_;
    double prev_error_ = 0.0;
    double integral_ = 0.0;

public:
    PIDController(double kp, double ki, double kd, double dt, double min_o, double max_o)
        : kp_(kp), ki_(ki), kd_(kd), dt_(dt), min_out_(min_o), max_out_(max_o) {}

    double compute(double setpoint, double measurement) {
        double error = setpoint - measurement;
        integral_ += error * dt_;
        double derivative = (error - prev_error_) / dt_;
        double output = kp_ * error + ki_ * integral_ + kd_ * derivative;
        
        // Bão hòa tín hiệu đầu ra (Saturation Limit)
        double clamped = std::clamp(output, min_out_, max_out_);
        
        // Anti-windup cho tích phân: Nếu đầu ra bị bão hòa, ngưng cộng dồn tích phân
        if (output != clamped && ki_ != 0.0) {
            integral_ -= error * dt_;
        }
        prev_error_ = error;
        return clamped;
    }
};

int main() {
    PIDController speed_pid(2.0, 0.1, 0.05, 0.05, -10.0, 10.0);
    double current_speed = 0.0;
    double target_speed = 5.0; // Vận tốc mục tiêu 5 m/s

    std::cout << "--- MÔ PHỎNG ĐIỀU KHIỂN VẬN TỐC ROBOT ENCODER (10 BƯỚC) ---\n";
    for (int t = 1; t <= 10; ++t) {
        double accel_cmd = speed_pid.compute(target_speed, current_speed);
        current_speed += accel_cmd * 0.05;
        std::printf("Step %2d | Target: %.1f m/s | Speed: %5.2f m/s | Accel Cmd: %5.2f m/s^2\n",
                    t, target_speed, current_speed, accel_cmd);
    }
    return 0;
}

Dự án 2: Pure Pursuit Trajectory Tracker Engine (Đọc CSV & Tính Góc Lái C++17)

#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>
#include <fstream>
#include <sstream>

struct Waypoint {
    double x, y, speed;
};

// Mô phỏng thuật toán bám đường Pure Pursuit trên xe mô hình F1TENTH
class PurePursuitTracker {
private:
    double lookahead_dist_; // Khoảng cách nhìn trước (Lookahead distance L)
    double wheel_base_;     // Chiều dài cơ sở xe (Wheelbase L_wb)
public:
    PurePursuitTracker(double L, double wb) : lookahead_dist_(L), wheel_base_(wb) {}

    // Tìm Waypoint mục tiêu gần khoảng cách L nhất trên quỹ đạo
    Waypoint find_target_waypoint(double rx, double ry, const std::vector<Waypoint>& path) {
        auto target_it = std::min_element(path.begin(), path.end(), [rx, ry, this](const Waypoint& a, const Waypoint& b) {
            double dist_a = std::abs(std::hypot(a.x - rx, a.y - ry) - lookahead_dist_);
            double dist_b = std::abs(std::hypot(b.x - rx, b.y - ry) - lookahead_dist_);
            return dist_a < dist_b;
        });
        return *target_it;
    }

    // Tính toán góc lái theo công thức Pure Pursuit: delta = atan2(2 * L_wb * sin(alpha), L)
    double compute_steering(double rx, double ry, double ryaw, const Waypoint& target) {
        double dx = target.x - rx;
        double dy = target.y - ry;
        double alpha = std::atan2(dy, dx) - ryaw;
        double delta = std::atan2(2.0 * wheel_base_ * std::sin(alpha), lookahead_dist_);
        return std::clamp(delta, -0.6, 0.6); // Kẹp góc lái max 35 độ
    }
};

int main() {
    std::vector<Waypoint> waypoints = {
        {0.0, 0.0, 2.0}, {2.0, 1.0, 2.0}, {4.0, 3.0, 2.0}, {6.0, 6.0, 2.0}
    };

    PurePursuitTracker tracker(2.0, 0.33); // L = 2m, Wheelbase = 0.33m (Xe F1TENTH)
    double robot_x = 0.0, robot_y = 0.0, robot_yaw = 0.1;

    Waypoint target_wp = tracker.find_target_waypoint(robot_x, robot_y, waypoints);
    double steer = tracker.compute_steering(robot_x, robot_y, robot_yaw, target_wp);

    std::cout << "Target Waypoint: (" << target_wp.x << ", " << target_wp.y << ")\n";
    std::cout << "Goc lai tinh duoc (Pure Pursuit): " << steer << " rad\n";
    return 0;
}

✅ Đáp án Chi Tiết

Truyền const T& giúp tránh tốn chi phí CPU copy mảng dữ liệu lớn ($0\text{ms}$ copy), đồng thời từ khóa const bảo vệ dữ liệu mảng không bị sửa đổi.

void process(const std::vector<double>& data); // Zero copy overhead

Q2: Sự khác nhau giữa std::unique_ptr và std::shared_ptr là gì? Loại nào có chi phí Overhead = 0?

✅ Đáp án Chi Tiết

unique_ptr sở hữu độc quyền (không copy được), chi phí Overhead = 0. shared_ptr cho phép chia sẻ quyền sở hữu bằng Reference Counting.

auto u = std::make_unique<Motor>(); // Zero overhead
auto s = std::make_shared<Costmap>(); // Shared reference count

Q3: Tại sao mọi lớp cha Interface trong C++ Hướng đối tượng bắt buộc phải có virtual ~BaseClass()?

✅ Đáp án Chi Tiết

Để đảm bảo khi hủy đối tượng lớp con qua con trỏ lớp cha, Destructor của lớp con vẫn được gọi đầy đủ, tránh rò rỉ bộ nhớ (Memory Leak).

class Base { public: virtual ~Base() = default; };

Q4: Việc gọi std::vector::reserve(N) trước khi đẩy dữ liệu vào vector có tác dụng gì đối với tính năng thời gian thực (Real-time)?

✅ Đáp án Chi Tiết

Nó cấp phát trước đúng dung lượng bộ nhớ Heap $N$ phần tử, loại bỏ hoàn toàn các lần tái cấp phát (Re-allocation) ngẫu nhiên làm giật lag vòng lặp điều khiển.

std::vector<Point> pts; pts.reserve(1000); // Heap allocated once!

Q5: Cú pháp Lambda capture [this] có ý nghĩa gì trong đăng ký Callback của ROS 2?

✅ Đáp án Chi Tiết

Cho phép hàm Lambda truy cập trực tiếp và an toàn các biến thành viên và phương thức của lớp Node hiện tại.

sub_ = create_sub([this](auto msg){ this->on_msg(msg); });

Q6: Tại sao std::array lại safe cho các vòng lặp Real-Time $1000\text{ Hz}$ trong khi std::vector lại có nguy cơ?

✅ Đáp án Chi Tiết

Vì std::array nằm hoàn toàn trên Stack (không xin bộ nhớ từ OS), trong khi std::vector xin bộ nhớ từ Heap (không xác định thời gian cấp phát).

std::array<double, 6> state; // Allocated on Stack (0ms delay)

Q7: Khi nào NÊN dùng std::deque thay vì std::vector?

✅ Đáp án Chi Tiết

Khi bạn cần thêm/xóa phần tử ở ĐẦU mảng (Pop Front / Push Front) trong độ phức tạp $O(1)$, ví dụ bộ lọc Sliding Window.

std::deque<double> buf; buf.pop_front(); // O(1) time complexity

Q8: Lợi ích của std::clamp(val, min_val, max_val) là gì?

✅ Đáp án Chi Tiết

Giới hạn trực tiếp giá trị trong dải an toàn (vận tốc, góc lái, PWM) chỉ với 1 dòng code ngắn gọn và tối ưu.

double u = std::clamp(raw_u, -1.0, 1.0);

Q9: Erase-Remove Idiom hoạt động thế nào để lọc phần tử trong std::vector?

✅ Đáp án Chi Tiết

std::remove_if dồn các phần tử cần giữ lên đầu và trả về iterator mới, sau đó v.erase() cắt bỏ phần đuôi thừa.

v.erase(std::remove_if(v.begin(), v.end(), pred), v.end());

Q10: std::optional<T> giải quyết vấn đề gì trong lập trình C++?

✅ Đáp án Chi Tiết

Thay thế việc dùng các cờ lỗi giả (vd: -1.0, nullptr) bằng một container an toàn thể hiện dữ liệu Có hoặc Không tồn tại.

std::optional<Path> plan_path(); // Safe return

Q11: std::string_view khác std::string ở điểm nào?

✅ Đáp án Chi Tiết

std::string_view chỉ là một con trỏ + độ dài quan sát chuỗi có sẵn (Zero-copy), không tự cấp phát bộ nhớ Heap mới.

void log_topic(std::string_view t); // Zero allocation

Q12: std::move thực chất thực hiện hành động gì?

✅ Đáp án Chi Tiết

Nó chỉ thực hiện Ép kiểu (Cast) một Lvalue thành Rvalue reference để kích hoạt Move Constructor / Move Assignment.

auto new_buf = std::move(old_buf); // Cast to Rvalue

Q13: Tại sao std::lock_guard lại an toàn hơn gõ mutex.lock() và mutex.unlock() thủ công?

✅ Đáp án Chi Tiết

Vì lock_guard sử dụng RAII tự động giải phóng (unlock) mutex khi thoát khỏi scope, kể cả khi có ngoại lệ (exception) xảy ra.

{ std::lock_guard<std::mutex> lock(mtx); } // Auto unlock

Q14: std::atomic<T> dùng khi nào?

✅ Đáp án Chi Tiết

Dùng cho các biến trạng thái đơn giản (bool, int) được đọc/ghi giữa nhiều thread mà không cần dùng Mutex (Lock-free).

std::atomic<bool> estop{false}; // Lock-free atomic flag

Q15: std::stringstream kết hợp std::getline được dùng làm gì trong xử lý dữ liệu Robot?

✅ Đáp án Chi Tiết

Dùng để parse (phân tích) từng dòng dữ liệu từ file CSV / Text phân cách bởi dấu phẩy hoặc khoảng trắng thành các giá trị biến số.

std::stringstream ss(line); std::getline(ss, val, ',');
