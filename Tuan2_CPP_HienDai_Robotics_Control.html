PHẦN 0 — VÌ SAO C++ LÀ NGÔN NGỮ CỐT LÕI CỦA ROBOTICS?

Giải mã lý do 8/11 Job Descriptions xe tự hành & robot gọi tên C++ hiện đại

🎯 Vì sao C++ áp đảo trong Robotics & Autonomous Vehicles?

Một chiếc xe tự hành chạy với tốc độ 80 km/h di chuyển khoảng 22 mét mỗi giây. Nếu thuật toán tránh vật cản bị chậm 50ms do trình thu gom rác (Garbage Collector của Python/Java) tạm dừng hệ thống, hậu quả là va chạm. C++ cung cấp 3 điều kiện tiên quyết:

  1. Deterministic Performance (Tính xác định về thời gian): Không có Garbage Collector bất ngờ tạm dừng chương trình. Bộ nhớ cấp phát và giải phóng chính xác khi lập trình viên yêu cầu.
  2. Hardware-Level Control (Thao tác sát phần cứng): Đọc trực tiếp bộ nhớ CAN bus, thanh ghi cảm biến IMU/Encoder, bộ nhớ DMA với độ trễ tính bằng microgiây ($\mu s$).
  3. Zero-Cost Abstractions (Trừu tượng hóa chi phí bằng 0): Viết code Hướng đối tượng (OOP), Template, Lambda cực kỳ đẹp mắt nhưng khi biên dịch qua g++ -O3, máy tính thực thi nhanh hệt như C thuần hoặc Assembly.
🔎 Ẩn dụ: Python là xe số tự động du lịch, C++ là xe đua Công thức 1 (F1)

Python giúp bạn dựng prototype nhanh chóng (lái xe tự động đi siêu thị). Nhưng C++ là chiếc xe đua F1: không có trợ lực lái tự động cản trở tay lái, phản ứng tức thì với từng cú nhấn ga. Để điều khiển hệ thống robot thời gian thực (Real-time Control), bạn phải làm chủ tay lái C++.

PHẦN 1 — NGÀY 8–9: BỘ NHỚ, CON TRỎ, THAM CHIẾU & CONST

Hiểu sâu Stack vs Heap · Con trỏ (*) · Tham chiếu (&) · const correctness 🔬 CẦN HIỂU SÂU

🎯 Mục đích: 80% câu hỏi phỏng vấn C++ và 90% lỗi crash (Segmentation Fault) bắt nguồn từ con trỏ & quản lý bộ nhớ. Hiểu rõ Stack vs Heap giúp bạn tối ưu bộ nhớ cho vi điều khiển STM32/ESP32 và tránh rò rỉ bộ nhớ trên Linux ROS2 node.

1.1 Bản đồ bộ nhớ: Stack vs Heap

Tiêu chí Vùng nhớ Stack (Ngăn xếp) Vùng nhớ Heap (Đống)
Đặc điểm Cấp phát tự động, kích thước nhỏ (thường 2MB–8MB) Cấp phát thủ công qua new / malloc, kích thước lớn (bằng RAM)
Tốc độ Cực kỳ nhanh (chỉ cần dịch chuyển con trỏ Stack Pointer) Chậm hơn (phải tìm khoảng trống bộ nhớ phù hợp)
Quản lý Tự động thu hồi khi ra khỏi Scope {} Phải thu hồi thủ công (delete/free) hoặc dùng Smart Pointer
Ứng dụng Robot Lưu biến cục bộ, ma trận PID kích thước cố định $3 \times 3$ Lưu mảng mây điểm LiDAR ($100,000$ điểm), bản đồ Costmap Nav2

1.2 Con trỏ (*) vs Tham chiếu (&) vs Const

📌 Phân biệt bản chất
  • Con trỏ (Pointer T*): Là một biến lưu địa chỉ bộ nhớ của biến khác. Có thể trỏ tới nullptr, có thể thay đổi địa chỉ trỏ tới.
  • Tham chiếu (Reference T&): Là một bí danh (alias) cho một biến đã tồn tại. Không thể null, không thể đổi sang tham chiếu biến khác sau khi khởi tạo.
  • Tham chiếu hằng (const T&): Cho phép truyền biến vào hàm không tốn chi phí copy, đồng thời bảo vệ biến không bị hàm sửa đổi. Đây là chuẩn mực truyền tham số trong Robotics!
1

Ví dụ gõ tay: So sánh các cách truyền tham số

#include <iostream>
#include <vector>

// 1. Truyền bằng Value (Copy): Tốn thời gian copy mảng lớn!
void process_map_copy(std::vector<double> data) {
    // data là bản sao độc lập
}

// 2. Truyền bằng Reference: Nhanh, nhưng có thể lỡ tay sửa mảng gốc
void process_map_ref(std::vector<double>& data) {
    data[0] = 999.0; // Sửa trực tiếp biến bên ngoài!
}

// 3. Truyền bằng Const Reference (CHUẨN ROBOTICS): Nhanh + An toàn tuyệt đối
void process_map_const_ref(const std::vector<double>& data) {
    // data[0] = 999.0; // LỖI BIÊN DỊCH: Không cho sửa!
    std::cout << "Kich thuoc may diem: " << data.size() << std::endl;
}

int main() {
    std::vector<double> lidar_points(100000, 1.5); // 100,000 điểm LiDAR
    
    process_map_const_ref(lidar_points); // Truyền tham chiếu hằng: 0ms copy!
    return 0;
}

PHẦN 2 — NGÀY 10–11: OOP THỰC CHIẾN CHO ROBOTICS

Class · Interface · Polymorphism · Virtual Destructor 🔬 CẦN HIỂU SÂU

🎯 Mục đích: Kiến trúc phần mềm Nav2 và ROS2 được xây dựng hoàn toàn trên kế thừa và đa hình (Polymorphism). Học cách tạo Interface chung cho các bộ điều khiển (Controller Base Class) giúp bạn hoán đổi giữa Pure Pursuit, Stanley, LQR và MPC mà không cần sửa code hệ thống chính.

2.1 Xây dựng Controller Interface với Virtual Functions

Giả sử bạn thiết kế hệ thống xe tự hành. Bạn cần một lớp cha chung AbstractController để mọi thuật toán điều khiển tuân theo:

#include <iostream>
#include <cmath>

// Struct lưu trạng thái robot: x, y, yaw (góc hướng), v (vận tốc)
struct RobotState {
    double x = 0.0;
    double y = 0.0;
    double yaw = 0.0;
    double v = 0.0;
};

// Struct lưu lệnh điều khiển: góc lái (steering) & gia tốc (accel)
struct ControlOutput {
    double steering_angle = 0.0;
    double acceleration = 0.0;
};

// --- CLASS CHA TRỪU TƯỢNG (INTERFACE) ---
class AbstractController {
public:
    // Destructor ảo: BẮT BUỘC để tránh rò rỉ bộ nhớ khi xóa qua con trỏ lớp cha
    virtual ~AbstractController() {
        std::cout << "[Base] Destructor AbstractController\n";
    }

    // Hàm thuần ảo (Pure Virtual Function): Bắt buộc lớp con phải Override
    virtual ControlOutput compute_control(const RobotState& current_state, 
                                         double target_x, double target_y) = 0;
};

// --- LỚP CON 1: BỘ ĐIỀU KHIỂN PURE PURSUIT ---
class PurePursuitController : public AbstractController {
private:
    double lookahead_distance_;
public:
    PurePursuitController(double L) : lookahead_distance_(L) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double dx = target_x - state.x;
        double dy = target_y - state.y;
        double alpha = std::atan2(dy, dx) - state.yaw;
        out.steering_angle = std::atan2(2.0 * 0.5 * std::sin(alpha), lookahead_distance_);
        out.acceleration = 0.5; // Gia tốc hằng số
        std::cout << "[PurePursuit] Tinh goc lai: " << out.steering_angle << " rad\n";
        return out;
    }
};

// --- LỚP CON 2: BỘ ĐIỀU KHIỂN PID PHAN HỒI ---
class PIDVelocityController : public AbstractController {
private:
    double kp_, ki_, kd_;
    double prev_error_ = 0.0;
    double integral_ = 0.0;
public:
    PIDVelocityController(double kp, double ki, double kd) 
        : kp_(kp), ki_(ki), kd_(kd) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double distance_error = std::sqrt(std::pow(target_x - state.x, 2) + 
                                          std::pow(target_y - state.y, 2));
        integral_ += distance_error;
        double derivative = distance_error - prev_error_;
        out.acceleration = kp_ * distance_error + ki_ * integral_ + kd_ * derivative;
        out.steering_angle = 0.0;
        prev_error_ = distance_error;
        std::cout << "[PID] Tinh gia toc: " << out.acceleration << " m/s^2\n";
        return out;
    }
};

int main() {
    RobotState robot{0.0, 0.0, 0.0, 1.0};
    
    // ĐA HÌNH (POLYMORPHISM): Dùng con trỏ lớp cha trỏ tới đối tượng lớp con
    AbstractController* controller = new PurePursuitController(2.0);
    controller->compute_control(robot, 5.0, 2.0);
    delete controller; // Gọi đúng destructor nhờ Virtual Destructor!

    controller = new PIDVelocityController(1.2, 0.01, 0.1);
    controller->compute_control(robot, 5.0, 2.0);
    delete controller;

    return 0;
}
⚠️ Quy tắc sinh tử: Cần có Virtual Destructor `virtual ~BaseClass()`

Nếu lớp cha có hàm ảo mà không có Virtual Destructor, khi bạn gọi delete controller; qua con trỏ lớp cha, chỉ có Destructor lớp cha được gọi! Destructor lớp con bị bỏ qua, dẫn đến tài nguyên cấp phát trong lớp con (như file handle, socket, RAM) bị rò rỉ nghiêm trọng (Memory Leak).

PHẦN 3 — NGÀY 12: RAII & SMART POINTERS

Quản lý tài nguyên tự động · unique_ptr · shared_ptr · weak_ptr 🔬 CẦN HIỂU SÂU

🎯 Mục đích: Trong C++ hiện đại (C++11 trở lên), bạn hạn chế tối đa gõ từ khóa `new` và `delete` thủ công. Kỹ thuật RAII (Resource Acquisition Is Initialization) kết hợp với Smart Pointers giúp chương trình robot tự động giải phóng bộ nhớ ngay khi đối tượng ra khỏi scope, chống Memory Leak 100%.

3.1 Ba loại Smart Pointers trong C++17

Loại Smart Pointer Quyền sở hữu Khi nào dùng trong Robotics?
std::unique_ptr<T> Độc quyền (Unique): Chỉ có 1 con trỏ duy nhất sở hữu vùng nhớ. Không thể copy, chỉ có thể move. Dùng mặc định! (vd: Node điều khiển sở hữu duy nhất 1 đối tượng Cảm biến IMU hay Driver Động cơ). Zero cost overhead!
std::shared_ptr<T> Chia sẻ (Shared): Nhiều con trỏ cùng sở hữu. Vùng nhớ giải phóng khi con trỏ cuối cùng hủy (Reference Count = 0). Dùng khi dữ liệu cần chia sẻ giữa nhiều Thread/Node (vd: Bản đồ Slam Map được đọc bởi cả Node Global Planner và Local Planner).
std::weak_ptr<T> Không sở hữu (Weak): Tham chiếu tới shared_ptr mà không tăng Reference Count. Tránh hiện tượng "Vòng lặp tham chiếu" (Circular Reference) gây rò rỉ bộ nhớ. Biến quan sát không nắm giữ lifetime.

3.2 Thực hành code RAII với Smart Pointers

#include <iostream>
#include <memory>

class IMUSensor {
public:
    IMUSensor() { std::cout << "--> [IMU] Khoi tao phan cung IMU (MPU6050/ICM20948)\n"; }
    ~IMUSensor() { std::cout << "<-- [IMU] Ngắt ket noi & Giai phong IMU\n"; }
    
    void read_accel() {
        std::cout << "    [IMU] Doc gia toc: ax = 0.02 m/s^2, ay = -0.1 m/s^2\n";
    }
};

void run_control_loop() {
    std::cout << "--- Bat dau Control Loop Scope ---\n";
    
    // Tạo unique_ptr bằng std::make_unique (C++14/17 Standard)
    auto imu = std::make_unique<IMUSensor>();
    imu->read_accel();
    
    // Không cần gõ delete imu! 
    std::cout << "--- Ket thuc Control Loop Scope ---\n";
} // imu tự động bị hủy TẠI ĐÂY!

int main() {
    run_control_loop();
    std::cout << "Chuong trinh hoan tat an toan.\n";
    return 0;
}

PHẦN 4 — NGÀY 13: CẤU TRÚC DỮ LIỆU STL & TỐI ƯU

std::vector · std::unordered_map · reserve() · std::sort 🔧 CHỈ CẦN CÔNG THỨC

🎯 Mục đích: Thư viện chuẩn STL cung cấp các cấu trúc dữ liệu cực kỳ tối ưu. Trong lập trình robot, việc sử dụng std::vector::reserve() là bắt buộc để tránh vi phạm tính thời gian thực (re-allocation làm chậm chương trình).

4.1 Mẹo tối ưu bộ nhớ bắt buộc: `reserve()` trong `std::vector`

Khi bạn push_back() vào vector mà chưa reserve, vector phải liên tục cấp phát lại mảng mới có kích thước gấp đôi, copy dữ liệu cũ sang và xóa mảng cũ. Trong vòng lặp $100\text{ Hz}$ của Robot, việc này gây giật lag ngẫu nhiên (Latency Spikes).

#include <iostream>
#include <vector>
#include <chrono>

struct Waypoint {
    double x, y, speed;
};

int main() {
    const int N = 1000000; // 1 triệu waypoint quỹ đạo
    
    // KHÔNG RESERVE: Tốn thời gian re-allocation
    std::vector<Waypoint> path1;
    auto t1 = std::chrono::high_resolution_clock::now();
    for(int i=0; i<N; ++i) {
        path1.push_back({i * 0.1, i * 0.2, 5.0});
    }
    auto t2 = std::chrono::high_resolution_clock::now();
    
    // CÓ RESERVE: Cấp phát 1 lần duy nhất!
    std::vector<Waypoint> path2;
    path2.reserve(N); // Xóa bỏ hoàn toàn chi phí re-allocate
    auto t3 = std::chrono::high_resolution_clock::now();
    for(int i=0; i<N; ++i) {
        path2.push_back({i * 0.1, i * 0.2, 5.0});
    }
    auto t4 = std::chrono::high_resolution_clock::now();

    std::cout << "Thoi gian khong reserve: " 
              << std::chrono::duration_cast<std::chrono::milliseconds>(t2 - t1).count() << " ms\n";
    std::cout << "Thoi gian CO reserve:    " 
              << std::chrono::duration_cast<std::chrono::milliseconds>(t4 - t3).count() << " ms\n";

    return 0;
}

PHẦN 5 — NGÀY 14: TEMPLATE & LAMBDA EXPRESSIONS

Đập tan điểm yếu · Template Class · Lambda Syntax · ROS2 Callback 🔬 CẦN HIỂU SÂU

🎯 Mục đích: Đẩy lùi rào cản Template và Lambda! Lambda xuất hiện ở mọi nơi trong ROS2 (Callback đăng ký Subscriber, Timer Callback, Service Handler). Nắm vững Lambda giúp bạn viết code ROS2 cực kỳ ngắn gọn và dễ bảo trì.

5.1 Cú pháp Lambda Expression từng bước

📐 Cấu trúc tổng quát của Lambda: 
auto my_lambda = [ capture_list ] ( parameters ) -> return_type {
    // Body của lambda
};
  • [ ] Capture List (Danh sách bắt biến ngoài):
    • []: Không bắt biến nào từ scope bên ngoài.
    • [&]: Bắt TẤT CẢ các biến ngoài bằng Tham chiếu (sửa được biến ngoài).
    • [=]: Bắt TẤT CẢ các biến ngoài bằng Bản sao (Copy) (read-only).
    • [this]: Bắt con trỏ this của class hiện tại (dùng cực nhiều trong ROS2 Callback!).
  • ( parameters ): Tham số nhận vào hệt như hàm bình thường.
  • -> return_type: Kiểu trả về (thường trình biên dịch tự suy luận được, có thể bỏ qua).

5.2 Ứng dụng Lambda làm Callback trong ROS2 Subscriber

#include <iostream>
#include <functional>
#include <string>

// Mô phỏng ROS2 Subscription Callback bằng std::function
class ROS2NodeSimulator {
private:
    std::string node_name_;
    double target_speed_ = 0.0;
public:
    ROS2NodeSimulator(const std::string& name) : node_name_(name) {}

    // Đăng ký Callback lắng nghe tin nhắn vế tốc độ
    void subscribe_cmd_vel(std::functional<void(double)> callback) {
        std::cout << "[" << node_name_ << "] Nhan tin nhan cmd_vel moi: 2.5 m/s\n";
        callback(2.5); // Gọi callback function
    }

    void setup_subscribers() {
        // LAMBDA DÙNG [this] ĐỂ CẬP NHẬT BIẾN THÀNH VIÊN CỦA CLASS!
        subscribe_cmd_vel([this](double msg_speed) {
            this->target_speed_ = msg_speed;
            std::cout << "  --> Callback thuc thi! Cap nhat target_speed = " 
                      << this->target_speed_ << " m/s trong node " << node_name_ << "\n";
        });
    }
};

int main() {
    ROS2NodeSimulator node("motion_controller_node");
    node.setup_subscribers();
    return 0;
}

5.3 Class Template: Bộ lọc LowPassFilter dùng chung mọi kiểu dữ liệu

#include <iostream>

// Class Template cho phép lọc cả float, double, hoặc Vector3D
template <typename T>
class LowPassFilter {
private:
    T alpha_;      // Hệ số lọc (0.0 < alpha < 1.0)
    T prev_output_;
    bool initialized_ = false;
public:
    LowPassFilter(T alpha) : alpha_(alpha), prev_output_(0) {}

    T filter(T input) {
        if (!initialized_) {
            prev_output_ = input;
            initialized_ = true;
            return input;
        }
        // Công thức bộ lọc thông thấp: y[k] = alpha * x[k] + (1 - alpha) * y[k-1]
        T output = alpha_ * input + (static_cast<T>(1.0) - alpha_) * prev_output_;
        prev_output_ = output;
        return output;
    }
};

int main() {
    // Dùng cho kiểu double (đọc cảm biến vận tốc)
    LowPassFilter<double> vel_filter(0.2); // alpha = 0.2
    
    std::cout << "Doc nhieu IMU: 10.0 -> Filtered: " << vel_filter.filter(10.0) << std::endl;
    std::cout << "Doc nhieu IMU: 15.0 -> Filtered: " << vel_filter.filter(15.0) << std::endl;
    std::cout << "Doc nhieu IMU: 12.0 -> Filtered: " << vel_filter.filter(12.0) << std::endl;

    return 0;
}

PHẦN 6 — DỰ ÁN THỰC HÀNH TUẦN 2

Viết Bộ Điều Khiển PID Hoàn Chỉnh Bằng C++17 Chuẩn Kỹ Thuật (Clean Code)

🛠️

Dự án nhỏ: Module PIDController chuẩn C++17 dùng cho Robot thật

#include <iostream>
#include <algorithm>

class PIDController {
private:
    double kp_, ki_, kd_;
    double dt_;
    double min_output_, max_output_;
    double prev_error_ = 0.0;
    double integral_ = 0.0;

public:
    PIDController(double kp, double ki, double kd, double dt, 
                  double min_out, double max_out)
        : kp_(kp), ki_(ki), kd_(kd), dt_(dt), 
          min_output_(min_out), max_output_(max_out) {}

    // Reset bộ tích phân khi chuyển chế độ
    void reset() {
        prev_error_ = 0.0;
        integral_ = 0.0;
    }

    double compute(double setpoint, double measurement) {
        double error = setpoint - measurement;
        
        // Tích phân
        integral_ += error * dt_;
        
        // Vi phân
        double derivative = (error - prev_error_) / dt_;
        
        // Tính tổng tín hiệu điều khiển U
        double output = kp_ * error + ki_ * integral_ + kd_ * derivative;
        
        // Bão hòa tín hiệu đầu ra (Saturation Limit) để bảo vệ động cơ
        double clamped_output = std::clamp(output, min_output_, max_output_);
        
        // Chống bão hòa bộ tích phân (Anti-windup cơ bản)
        if (output != clamped_output && ki_ != 0.0) {
            integral_ -= error * dt_; // Khôi phục trạng thái tích phân
        }

        prev_error_ = error;
        return clamped_output;
    }
};

int main() {
    // Khởi tạo PID điều khiển vận tốc xe: Kp=1.5, Ki=0.2, Kd=0.05, dt=0.01s (100Hz)
    // Output giới hạn từ -12V đến +12V
    PIDController speed_pid(1.5, 0.2, 0.05, 0.01, -12.0, 12.0);

    double target_speed = 5.0; // m/s
    double current_speed = 0.0; // m/s

    std::cout << "--- MO PHONG VÒNG LẶP ĐIỀU KHIỂN ENCODER (10 BƯỚC) ---\n";
    for (int step = 1; step <= 10; ++step) {
        double u_voltage = speed_pid.compute(target_speed, current_speed);
        
        // Mô phỏng đáp ứng động cơ (Vật lý đơn giản)
        current_speed += (u_voltage * 0.4) * 0.01;

        std::printf("Step %2d | Target: %.2f m/s | Current: %.2f m/s | Output U: %6.2f V\n", 
                    step, target_speed, current_speed, u_voltage);
    }
    return 0;
}

Q2.1 Trong C++, sự khác biệt giữa unique_ptr và shared_ptr là gì? Khi nào NÊN dùng unique_ptr mặc định?

✅ Đáp án giải thích

unique_ptr quản lý độc quyền đối tượng (không copy được, chỉ move). shared_ptr cho phép nhiều con trỏ chia sẻ quyền sở hữu bằng Reference Counting. NÊN dùng unique_ptr làm mặc định vì nó có Zero Overhead (hiệu năng bằng hệt con trỏ thô), an toàn và thể hiện rõ quyền sở hữu duy nhất.

Q2.2 Tại sao mọi destructor của Base Class trong Hướng đối tượng C++ bắt buộc phải có từ khóa virtual?

✅ Đáp án giải thích

Khi ta xóa một đối tượng lớp con thông qua con trỏ lớp cha (vd: AbstractController* ptr = new PIDController(); delete ptr;), nếu destructor không phải virtual, chương trình chỉ gọi destructor của AbstractController. Destructor của PIDController bị bỏ qua, gây rò rỉ bộ nhớ (Memory Leak) các tài nguyên mà lớp con đang nắm giữ.

Q2.3 Lambda capture [this] và [&] khác nhau thế nào trong ngữ cảnh đăng ký Callback ROS2?

✅ Đáp án giải thích

[this] chỉ bắt con trỏ đại diện cho đối tượng class hiện tại, cho phép Lambda truy cập biến thành viên và phương thức của class một cách an toàn. [&] bắt TẤT CẢ các biến cục bộ trong scope theo tham chiếu — nguy hiểm nếu Callback được thực thi bất đồng bộ sau khi các biến cục bộ đó đã bị hủy khỏi Stack.

Q2.4 Việc không gọi reserve() trước khi push_back() hàng triệu phần tử vào std::vector gây ra nguy cơ gì cho hệ thống điều khiển Real-time?

✅ Đáp án giải thích

Khi vector vượt quá sức chứa (capacity), nó phải xin hệ điều hành cấp phát một vùng nhớ mới lớn hơn, copy toàn bộ phần tử cũ sang và xóa vùng nhớ cũ. Quá trình này làm mất tính xác định thời gian, gây ra các cú giật lag ngẫu nhiên (Latency Spikes) vi phạm điều kiện thời gian thực (Real-time Requirement).
