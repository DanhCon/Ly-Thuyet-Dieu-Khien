🎯 Vì sao C++ áp đảo tuyệt đối trong Robotics & Autonomous Vehicles?

Một chiếc xe tự hành chạy với tốc độ $80\text{ km/h}$ di chuyển khoảng 22.2 mét mỗi giây. Nếu thuật toán tránh vật cản bị chậm $50\text{ms}$ do trình thu gom rác (Garbage Collector của Python, Java hay Go) tạm dừng hệ thống để dọn bộ nhớ, hậu quả là va chạm không thể đảo ngược. C++ cung cấp 3 điều kiện tiên quyết mà không ngôn ngữ nào thay thế được:

  1. Deterministic Real-Time Performance (Tính xác định về thời gian): Không có Garbage Collector bất ngờ tạm dừng chương trình. Bộ nhớ được cấp phát và giải phóng chính xác tại thời điểm lập trình viên yêu cầu. Vòng lặp điều khiển $1000\text{ Hz}$ ($1\text{ms}$) luôn chạy đúng tiến độ.
  2. Hardware-Level Memory Control (Thao tác sát phần cứng): Đọc trực tiếp bộ nhớ CAN Bus xe, thanh ghi cảm biến IMU/Encoder qua I2C/SPI, bộ nhớ DMA với độ trễ microgiây ($\mu s$).
  3. Zero-Cost Abstractions (Trừu tượng hóa chi phí bằng 0): Lập trình Hướng đối tượng (OOP), Template, Lambda cực kỳ đẹp mắt và dễ đọc, nhưng khi biên dịch qua g++ -O3, trình biên dịch tối ưu thành mã máy cực nhanh hệt như C thuần hoặc Assembly.

PHẦN 1 — BỘ NHỚ, CON TRỎ, THAM CHIẾU & CONST CORRECTNESS

Hiểu sâu Stack vs Heap · Memory Layout · Dangling Pointers · const correctness 🔬 CẦN HIỂU SÂU

🎯 Mục đích: 80% câu hỏi phỏng vấn C++ và 90% lỗi crash (Segmentation Fault) bắt nguồn từ con trỏ & quản lý bộ nhớ sai. Hiểu rõ Stack vs Heap giúp bạn tối ưu bộ nhớ cho vi điều khiển STM32/ESP32 và tránh rò rỉ bộ nhớ trên Linux ROS 2 node.

1.1 Bản đồ bộ nhớ của chương trình C++ (Memory Layout)

+-------------------------------------------------------+ Địa chỉ cao (0xFFFFFFFF) | STACK | (Tự động mở rộng XUỐNG) | - Biến cục bộ (int x, double v) | - Cực kỳ nhanh | - Con trỏ Stack Pointer (SP) | - Giới hạn 2MB - 8MB | | | | v | | ^ | | | | | HEAP | (Cấp phát mở rộng LÊN) | - Cấp phát động (new, malloc, std::vector data) | - Dung lượng bằng RAM | - Phải quản lý cẩn thận (tránh Memory Leak) | - Chậm hơn Stack +-------------------------------------------------------+ | BSS Segment (Biến toàn cục chưa khởi tạo = 0) | +-------------------------------------------------------+ | Data Segment (Biến toàn cục / static đã khởi tạo) | +-------------------------------------------------------+ | Text / Code Segment (Mã máy thực thi - Read Only) | Địa chỉ thấp (0x00000000) +-------------------------------------------------------+

1.2 Con trỏ (*) vs Tham chiếu (&) vs Const Correctness

📌 Phân biệt 3 bản chất cốt lõi
  • Con trỏ (Pointer T*): Biến lưu địa chỉ bộ nhớ của biến khác. Có thể gán nullptr, có thể thay đổi địa chỉ trỏ tới. Kích thước hằng số ($8\text{ bytes}$ trên hệ 64-bit).
  • Tham chiếu (Reference T&): Bí danh (alias) trực tiếp của một biến đã tồn tại. Không thể null, không thể đổi sang trỏ biến khác sau khi khởi tạo.
  • Tham chiếu hằng (const T&): Truyền tham số không tốn chi phí copy, đồng thời bảo vệ biến không bị sửa đổi. Đây là chuẩn mực vàng truyền tham số trong C++ Robotics!
1

Ví dụ code: Phân biệt 4 cách truyền tham số mảng cảm biến LiDAR

#include <iostream>
#include <vector>
#include <chrono>

struct LidarScan {
    std::vector<double> ranges; // 360 tia quét LiDAR
    double timestamp;
};

// 1. Truyền bằng Pass-by-Value (Copy toàn bộ mảng): TẠO LỖI NGHẼN BỘ NHỚ!
void process_scan_bad(LidarScan scan) {
    // scan là bản sao độc lập! Copy 360 tia mất thời gian CPU.
}

// 2. Truyền bằng Pass-by-Reference (Tham chiếu): Nhanh, nhưng nguy cơ lỡ tay sửa mảng gốc
void process_scan_ref(LidarScan& scan) {
    scan.ranges[0] = 0.0; // ⚠️ Sửa trực tiếp dữ liệu bên ngoài!
}

// 3. Truyền bằng Pass-by-Const-Reference (CHUẨN ROBOTICS): Nhanh + An toàn
void process_scan_good(const LidarScan& scan) {
    // scan.ranges[0] = 0.0; // ❌ LỖI BIÊN DỊCH: Không cho phép sửa!
    std::cout << "So tia LiDAR: " << scan.ranges.size() << "\n";
}

// 4. Truyền bằng Con trỏ (Pointer): Dùng khi tham số có thể KHÔNG TỒN TẠI (null)
void process_scan_pointer(const LidarScan* scan_ptr) {
    if (scan_ptr == nullptr) { // 🔍 BẮT BUỘC CHECK NULLPTR!
        std::cout << "Lidar scan khong ton tai (NULL)\n";
        return;
    }
    std::cout << "Timestamp: " << scan_ptr->timestamp << "\n";
}

int main() {
    LidarScan my_scan;
    my_scan.ranges.resize(360, 5.2); // 360 tia khoảng cách 5.2m
    my_scan.timestamp = 100.25;

    process_scan_good(my_scan);       // Chi phí copy = 0ms!
    process_scan_pointer(&my_scan);   // Truyền địa chỉ
    process_scan_pointer(nullptr);    // Xử lý an toàn khi không có dữ liệu
    return 0;
}
⚠️ Lỗi kinh điển: Dangling Pointer (Con trỏ hoang quải)

Dangling pointer xảy ra khi bạn trả về địa chỉ của một biến cục bộ nằm trên Stack. Khi hàm kết thúc, vùng nhớ Stack bị giải phóng nhưng con trỏ vẫn giữ địa chỉ cũ → Đọc/ghi vào đây gây Segmentation Fault ngay lập tức!

int* get_sensor_value_BAD() {
    int sensor_raw = 1024; // Biến cục bộ trên Stack
    return &sensor_raw;    // ❌ DANGER! sensor_raw bị hủy ngay khi thoát hàm!
} // Vùng nhớ bị thu hồi. Trả về địa chỉ ma!

💪 Bài Tập Thực Hành Phần 1

BT1.1: Viết hàm void swap(int* a, int* b) và hàm void swap(int& a, int& b). Giải thích tại sao cách dùng tham chiếu & lại an toàn và ngắn gọn hơn con trỏ.

✅ Đáp án & Giải thích 
void swap_ptr(int* a, int* b) {
    if (!a || !b) return; // Phải check null
    int temp = *a; *a = *b; *b = temp;
}
void swap_ref(int& a, int& b) {
    int temp = a; a = b; b = temp; // Ngắn gọn, không lo null!
}

PHẦN 2 — LẬP TRÌNH HƯỚNG ĐỐI TƯỢNG (OOP) THỰC CHIẾN FOR ROBOTICS

Encapsulation · Struct vs Class · Interface · Polymorphism · Virtual Destructor 🔬 CẦN HIỂU SÂU

🎯 Mục đích: Kiến trúc Nav2 và ROS 2 (rclcpp) dựa hoàn toàn trên kế thừa và đa hình (Polymorphism). Học cách tạo Interface chung cho bộ điều khiển (Controller Base Class) giúp bạn hoán đổi giữa Pure Pursuit, Stanley, LQR, MPC mà không cần sửa code hệ thống chính.

2.1 Struct vs Class trong C++: Khi nào dùng cái nào?

📌 Điểm khác biệt duy nhất

Trong C++, struct và class giống hệt nhau về khả năng (đều có phương thức, constructor, kế thừa). Điểm khác duy nhất là Access Modifier mặc định:

  • struct: Mặc định là public. Dùng làm **Data Holder (Container dữ liệu)** đơn thuần (vd: Point2D, ControlCommand, Message ROS).
  • class: Mặc định là private. Dùng cho **Logic Engine & Hardware Controllers** cần đóng gói dữ liệu (Encapsulation) để bảo vệ trạng thái bên trong.

2.2 Thiết kế Controller Interface với Virtual Functions

#include <iostream>
#include <vector>
#include <cmath>
#include <memory>

// Struct lưu trạng thái robot: x, y, yaw (góc hướng), v (vận tốc)
struct RobotState {
    double x = 0.0;
    double y = 0.0;
    double yaw = 0.0;
    double v = 0.0;
};

// Struct lưu lệnh điều khiển: góc lái (steering) & gia tốc (accel)
struct ControlOutput {
    double steering_angle = 0.0;
    double acceleration = 0.0;
};

// --- CLASS CHA TRỪU TƯỢNG (INTERFACE CHUNG CHO MỌI CONTROLLER) ---
class AbstractController {
public:
    // Destructor ảo: BẮT BUỘC để tránh rò rỉ bộ nhớ khi xóa qua con trỏ lớp cha!
    virtual ~AbstractController() {
        std::cout << "[Base] Destructor AbstractController\n";
    }

    // Pure Virtual Function (= 0): Bắt buộc các thuật toán con phải tự triển khai
    virtual ControlOutput compute_control(const RobotState& current_state, 
                                         double target_x, double target_y) = 0;
};

// --- BỘ ĐIỀU KHIỂN 1: PURE PURSUIT (BÁM QUỸ ĐẠO HÌNH HỌC) ---
class PurePursuitController : public AbstractController {
private:
    double lookahead_distance_;
public:
    PurePursuitController(double L) : lookahead_distance_(L) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double dx = target_x - state.x;
        double dy = target_y - state.y;
        double alpha = std::atan2(dy, dx) - state.yaw;
        out.steering_angle = std::atan2(2.0 * 0.5 * std::sin(alpha), lookahead_distance_);
        out.acceleration = 0.5;
        std::cout << "[PurePursuit] Goc lai: " << out.steering_angle << " rad\n";
        return out;
    }
};

// --- BỘ ĐIỀU KHIỂN 2: STANLEY CONTROLLER (BÁM THEO SAI SỐ TRỤC TRƯỚC) ---
class StanleyController : public AbstractController {
private:
    double k_gain_; // Hệ số tăng cường
public:
    StanleyController(double k) : k_gain_(k) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double cross_track_error = target_y - state.y;
        out.steering_angle = std::atan2(k_gain_ * cross_track_error, state.v + 0.1);
        out.acceleration = 0.2;
        std::cout << "[Stanley] Goc lai: " << out.steering_angle << " rad\n";
        return out;
    }
};

int main() {
    RobotState car{0.0, 0.0, 0.0, 2.0}; // Xe đang chạy 2m/s
    
    // ĐA HÌNH (POLYMORPHISM): Dùng con trỏ Interface quản lý nhiều thuật toán
    std::vector<std::unique_ptr<AbstractController>> controllers;
    controllers.push_back(std::make_unique<PurePursuitController>(2.5));
    controllers.push_back(std::make_unique<StanleyController>(0.5));

    std::cout << "--- CHẠY THỬ CÁC BỘ ĐIỀU KHIỂN ---\n";
    for (const auto& ctrl : controllers) {
        ctrl->compute_control(car, 10.0, 3.0);
    }
    return 0; // Tự động gọi destructor an toàn!
}
⚠️ Quy tắc sinh tử: Bắt buộc Virtual Destructor `virtual ~BaseClass()`

Nếu lớp cha có phương thức ảo nhưng không có Virtual Destructor, khi xóa đối tượng con thông qua con trỏ lớp cha (delete ptr;), chỉ có Destructor lớp cha được gọi! Destructor lớp con bị bỏ qua, gây rò rỉ bộ nhớ nghiêm trọng các tài nguyên lớp con đang quản lý (File handles, Socket, Cấp phát RAM).

PHẦN 3 — QUẢN LÝ TÀI NGUYÊN RAII & SMART POINTERS

RAII Pattern · std::unique_ptr · std::shared_ptr · std::weak_ptr · shared_from_this 🔬 CẦN HIỂU SÂU

🎯 Mục đích: Trong C++ hiện đại (C++17 trở lên), bạn hạn chế tối đa gõ từ khóa `new` và `delete` thủ công. Kỹ thuật RAII (Resource Acquisition Is Initialization) kết hợp với Smart Pointers giúp chương trình robot tự động giải phóng bộ nhớ ngay khi đối tượng ra khỏi scope, chống Memory Leak 100%.

3.1 Ba loại Smart Pointers trong C++17

Loại Smart Pointer Quyền sở hữu (Ownership) Ứng dụng thực tế trong ROS 2 / Robotics
std::unique_ptr<T> Độc quyền (Unique): Chỉ duy nhất 1 con trỏ sở hữu. Không thể copy, chỉ có thể chuyển giao quyền sở hữu qua std::move. Dùng mặc định! Chi phí overhead bằng 0 ($0\text{ bytes}$ extra). Dùng cho Driver Cảm biến IMU, Controller Instance, Local Planner.
std::shared_ptr<T> Chia sẻ (Shared): Nhiều con trỏ cùng sở hữu. Vùng nhớ giải phóng khi con trỏ cuối cùng hủy (Reference Count = 0). Dùng khi dữ liệu được đọc bởi nhiều Thread/Node (vd: Bản đồ Costmap 2D được đọc bởi cả Global Planner và Local Planner).
std::weak_ptr<T> Không sở hữu (Weak): Tham chiếu tới shared_ptr mà không làm tăng Reference Count. Tránh vòng lặp tham chiếu (Circular Reference) gây rò rỉ bộ nhớ. Dùng cho Observer Pattern, Action Goal Handles.

3.2 Pattern ROS 2 Kinh điển: `std::enable_shared_from_this`

Trong ROS 2 (rclcpp), các Node kế thừa từ rclcpp::Node và cần truyền con trỏ shared_ptr của chính mình vào Subscriber/Timer Callback. Ta sử dụng shared_from_this():

#include <iostream>
#include <memory>

class RobotNode : public std::enable_shared_from_this<RobotNode> {
public:
    RobotNode() {
        std::cout << "[Node] Dang khoi tao...\n";
        // ⚠️ DANGER: KHÔNG ĐƯỢC gọi shared_from_this() trong Constructor!
        // Vì lúc này đối tượng chưa nằm trong shared_ptr nào cả -> Crash (std::bad_weak_ptr)!
    }

    void init_subscribers() {
        // ✅ CHUẨN ROS 2: Tạo shared_ptr trỏ tới chính mình để đăng ký callback
        std::shared_ptr<RobotNode> self = shared_from_this();
        std::cout << "[Node] Cap nhat thanh cong Subscriber voi shared_ptr reference count = " 
                  << self.use_count() << "\n";
    }
};

int main() {
    // BẮT BUỘC khởi tạo Node qua std::make_shared
    auto node = std::make_shared<RobotNode>();
    node->init_subscribers();
    return 0;
}

PHẦN 4 — CẤU TRÚC DỮ LIỆU STL CONTAINERS TOÀN DIỆN

std::array · std::vector · std::deque · std::unordered_map · std::priority_queue 🔧 CHỈ CẦN CÔNG THỨC

🎯 Mục đích: Chọn sai cấu trúc dữ liệu khiến thuật toán robot bị chậm hàng chục lần. Phần này hướng dẫn bạn chọn đúng Container cho từng bài toán cụ thể (Lidar, Costmap, Path planning A*).

4.1 Bảng so sánh các STL Containers trong Lập Trình Robot

Container Cấu trúc bộ nhớ Độ phức tạp Lookup / Insert Ứng dụng Robotics tiêu biểu
std::array<T, N> Mảng tĩnh trên Stack $O(1)$ ngẫu nhiên State vector $[x, y, \theta, v_x, v_y, \omega]$, Ma trận Covariance $6\times 6$
std::vector<T> Mảng động liên tục trên Heap Lookup $O(1)$, Insert end $O(1)$ Mây điểm LiDAR, Quỹ đạo Waypoint, Costmap 1D-flattened grid
std::deque<T> Các block bộ nhớ liên kết Push/Pop Front & Back $O(1)$ Sliding Window Filter (Bộ lọc trung bình động 100 mẫu IMU gần nhất)
std::priority_queue<T> Binary Heap (Heap tree) Top $O(1)$, Push/Pop $O(\log N)$ Open List trong thuật toán tìm đường A*, Dijkstra, Hybrid-A*
std::unordered_map<K,V> Hash Table (Bảng băm) Lookup trung bình $O(1)$ Bảng tra tham số robot theo tên (YAML config), Voxel Hash grid

4.2 Thực hành code: Priority Queue cho thuật toán A* Search

#include <iostream>
#include <queue>
#include <vector>

struct NodeAStar {
    int x, y;
    double f_cost; // f = g (chi phi da đi) + h (dieu huong)

    // Struct so sanh de Min-Heap luon dua Node chi phi nho nhat len dau
    bool operator>(const NodeAStar& other) const {
        return f_cost > other.f_cost;
    }
};

int main() {
    // Khởi tạo Min-Priority-Queue cho thuật toán A*
    std::priority_queue<NodeAStar, std::vector<NodeAStar>, std::greater<NodeAStar>> open_list;

    open_list.push({0, 0, 10.5});
    open_list.push({1, 2, 3.2}); // Node chi phí nhỏ nhất
    open_list.push({2, 1, 7.8});

    std::cout << "--- A* OPEN LIST POP ORDER ---\n";
    while (!open_list.empty()) {
        NodeAStar current = open_list.top();
        std::cout << "Node (" << current.x << ", " << current.y << ") | f_cost = " << current.f_cost << "\n";
        open_list.pop();
    }
    return 0;
}

#include <iostream>
#include <vector>
#include <algorithm>
#include <numeric>
#include <cmath>

struct Obstacle {
    int id;
    double distance; // Khoảng cách tới xe (m)
};

int main() {
    std::vector<double> lidar_ranges = {2.5, 0.4, 12.0, NAN, 1.8, -0.5, 5.0};

    // 1. std::clamp: Giới hạn góc lái trong khoảng [-0.5 rad, +0.5 rad]
    double raw_steering = 0.85;
    double safe_steering = std::clamp(raw_steering, -0.5, 0.5);
    std::cout << "Goc lai sau clamp: " << safe_steering << " rad\n";

    // 2. Erase-Remove Idiom: Lọc bỏ các tia LiDAR bị lỗi (NaN hoặc âm)
    lidar_ranges.erase(
        std::remove_if(lidar_ranges.begin(), lidar_ranges.end(), [](double r) {
            return std::isnan(r) || r < 0.0;
        }),
        lidar_ranges.end()
    );

    // 3. std::min_element: Tìm tia LiDAR có khoảng cách nhỏ nhất (Vật cản gần nhất)
    auto min_it = std::min_element(lidar_ranges.begin(), lidar_ranges.end());
    if (min_it != lidar_ranges.end()) {
        std::cout << "Vat can gan nhat: " << *min_it << " m\n";
    }

    // 4. std::accumulate: Tính tổng / trung bình khoảng cách các tia
    double sum = std::accumulate(lidar_ranges.begin(), lidar_ranges.end(), 0.0);
    double avg = sum / lidar_ranges.size();
    std::cout << "Khoang cach trung binh: " << avg << " m\n";

    // 5. std::sort với Lambda: Sắp xếp danh sách Vật cản theo khoảng cách tăng dần
    std::vector<Obstacle> obstacles = {{1, 8.5}, {2, 1.2}, {3, 4.0}};
    std::sort(obstacles.begin(), obstacles.end(), [](const Obstacle& a, const Obstacle& b) {
        return a.distance < b.distance;
    });
    std::cout << "Obstacle gan nhat ID: " << obstacles[0].id << " (" << obstacles[0].distance << "m)\n";

    // 6. std::lower_bound: Tìm kiếm nhị phân Waypoint gần mốc thời gian t = 2.0s nhất
    std::vector<double> timestamps = {0.0, 0.5, 1.0, 1.5, 2.0, 2.5, 3.0};
    auto target_it = std::lower_bound(timestamps.begin(), timestamps.end(), 2.0);
    std::cout << "Tim thay timestamp: " << *target_it << "s tai index " 
              << std::distance(timestamps.begin(), target_it) << "\n";

    return 0;
}

6.1 Cú pháp Lambda Expression từng bước

📐 Cấu trúc tổng quát của Lambda: 
auto my_lambda = [ capture_list ] ( parameters ) -> return_type {
    // Body thực thi của Lambda
};
  • [ ] Capture List (Danh sách bắt biến ngoài):
    • []: Không bắt biến nào từ scope bên ngoài.
    • [&]: Bắt TẤT CẢ biến ngoài bằng Tham chiếu (có thể sửa biến ngoài).
    • [=]: Bắt TẤT CẢ biến ngoài bằng Bản sao (Copy) (read-only).
    • [this]: Bắt con trỏ this của class (chuẩn mực ROS 2 Callback!).

6.2 ROS 2 Pattern: `std::bind` vs Lambda Callback

#include <iostream>
#include <functional>
#include <string>

class SimpleROS2Node {
private:
    std::string node_name_;
    double current_velocity_ = 0.0;
public:
    SimpleROS2Node(const std::string& name) : node_name_(name) {}

    // Hàm nhận callback mô phỏng ROS 2 Subscriber
    void register_callback(std::functional<void(double)> cb) {
        cb(3.5); // Giả lập tin nhắn tốc độ mới = 3.5 m/s
    }

    void member_function_callback(double speed) {
        this->current_velocity_ = speed;
        std::cout << "[" << node_name_ << "] (std::bind) Cap nhat velocity: " << current_velocity_ << "\n";
    }

    void setup() {
        // CÁCH 1: Dùng std::bind (Cú pháp ROS 2 truyền thống)
        using std::placeholders::_1;
        register_callback(std::bind(&SimpleROS2Node::member_function_callback, this, _1));

        // CÁCH 2: Dùng Lambda [this] (Cú pháp C++ hiện đại - KHUYÊN DÙNG!)
        register_callback([this](double speed) {
            this->current_velocity_ = speed;
            std::cout << "[" << node_name_ << "] (Lambda) Cap nhat velocity: " << current_velocity_ << "\n";
        });
    }
};

int main() {
    SimpleROS2Node node("planner_node");
    node.setup();
    return 0;
}

🎯 Mục đích: Hệ thống xe tự hành chạy hàng chục luồng song song (Luồng đọc LiDAR, luồng chạy EKF SLAM, luồng vòng lặp điều khiển $100\text{ Hz}$). Học cách bảo vệ dữ liệu dùng chung (Shared Data) chống Race Condition. 
#include <iostream>
#include <thread>
#include <mutex>
#include <atomic>
#include <chrono>

// Biến atomic an toàn luồng cho cờ Dừng Khẩn Cấp (Lock-free!)
std::atomic<bool> g_emergency_stop{false};

std::mutex g_imu_mutex;
double g_latest_pitch = 0.0; // Biến chia sẻ giữa 2 thread

// THREAD 1: Đọc cảm biến IMU liên tục ở tần số 100Hz
void imu_sensor_thread() {
    for (int i = 0; i < 5; ++i) {
        {
            std::lock_guard<std::mutex> lock(g_imu_mutex); // Khóa mutex an toàn RAII
            g_latest_pitch += 0.1;
            std::cout << "[IMU Thread] Cap nhat Pitch: " << g_latest_pitch << "\n";
        }
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
}

// THREAD 2: Vòng lặp điều khiển xe (Control Loop)
void control_loop_thread() {
    for (int i = 0; i < 5; ++i) {
        if (g_emergency_stop.load()) {
            std::cout << "[Control Thread] DỪNG KHẨN CẤP!\n";
            break;
        }
        {
            std::lock_guard<std::mutex> lock(g_imu_mutex);
            std::cout << "  --> [Control Loop] Doc Pitch tinh u: " << g_latest_pitch << "\n";
        }
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
}

int main() {
    std::thread t1(imu_sensor_thread);
    std::thread t2(control_loop_thread);

    t1.join(); // Chờ thread 1 hoàn tất
    t2.join(); // Chờ thread 2 hoàn tất

#include <iostream>
#include <vector>
#include <cmath>
#include <algorithm>

class PIDController {
private:
    double kp_, ki_, kd_, dt_;
    double min_out_, max_out_;
    double prev_error_ = 0.0;
    double integral_ = 0.0;
public:
    PIDController(double kp, double ki, double kd, double dt, double min_o, double max_o)
        : kp_(kp), ki_(ki), kd_(kd), dt_(dt), min_out_(min_o), max_out_(max_o) {}

    double compute(double setpoint, double measurement) {
        double error = setpoint - measurement;
        integral_ += error * dt_;
        double derivative = (error - prev_error_) / dt_;
        double output = kp_ * error + ki_ * integral_ + kd_ * derivative;
        double clamped = std::clamp(output, min_out_, max_out_);
        if (output != clamped && ki_ != 0.0) integral_ -= error * dt_; // Anti-windup
        prev_error_ = error;
        return clamped;
    }
};

int main() {
    PIDController speed_pid(2.0, 0.1, 0.05, 0.05, -10.0, 10.0);
    double current_speed = 0.0;
    double target_speed = 5.0; // 5 m/s

    std::cout << "--- CHẠY MÔ PHỎNG ĐIỀU KHIỂN TỐC ĐỘ XE ROBOT (10 STEP) ---\n";
    for (int t = 1; t <= 10; ++t) {
        double accel_cmd = speed_pid.compute(target_speed, current_speed);
        current_speed += accel_cmd * 0.05; // dt = 0.05s
        std::printf("Step %2d | Target: %.1f m/s | Speed: %5.2f m/s | Accel Cmd: %5.2f m/s^2\n",
                    t, target_speed, current_speed, accel_cmd);
    }
    return 0;
}

Q1: Vì sao trong code C++ Robotics, ta luôn ưu tiên dùng const T& khi truyền mảng điểm LiDAR thay vì truyền trực tiếp T?

✅ Đáp án

Q2: Sự khác nhau giữa std::unique_ptr và std::shared_ptr là gì? Loại nào có chi phí Overhead = 0?

✅ Đáp án

unique_ptr sở hữu độc quyền (không copy được), chi phí Overhead = 0 (hiệu năng bằng con trỏ thô). shared_ptr cho phép chia sẻ quyền sở hữu bằng Reference Counting (có thêm chi phí bộ nhớ & atomic count).

Q3: Tại sao mọi lớp cha Interface trong C++ Hướng đối tượng bắt buộc phải có virtual ~BaseClass()?

✅ Đáp án

Để đảm bảo khi hủy đối tượng lớp con qua con trỏ lớp cha, Destructor của lớp con vẫn được gọi đầy đủ, tránh rò rỉ bộ nhớ (Memory Leak).

Q4: Việc gọi std::vector::reserve(N) trước khi đẩy dữ liệu vào vector có tác dụng gì đối với tính năng thời gian thực (Real-time)?

✅ Đáp án

Nó cấp phát trước đúng dung lượng bộ nhớ Heap $N$ phần tử, loại bỏ hoàn toàn các lần tái cấp phát (Re-allocation) ngẫu nhiên làm giật lag vòng lặp điều khiển.

Q5: Cú pháp Lambda capture [this] có ý nghĩa gì trong đăng ký Callback của ROS 2?

✅ Đáp án

Cho phép hàm Lambda truy cập trực tiếp và an toàn các biến thành viên và phương thức của lớp Node hiện tại.
