🧠 TƯ DUY NỀN TẢNG: BẢN CHẤT THỜI GIAN THỰC (REAL-TIME DETERMINISM)

Khái niệm cốt lõi: Tính thời gian thực (Real-time) trong Robotics KHÔNG PHẢI LÀ CHẠY NHANH NHẤT, mà là CHẠY ĐÚNG THỜI ĐIỂM (DETERMINISTIC). Nếu một thuật toán yêu cầu chạy mỗi $1\text{ms}$ ($1000\text{Hz}$), nó bắt buộc phải hoàn thành đúng trong $1\text{ms}$.

Vì sao Python/Java bị loại khỏi vòng lặp điều khiển xe? Các ngôn ngữ như Python, Java, Go sử dụng bộ thu gom rác (Garbage Collector - GC). Khi RAM đầy, GC sẽ ngầm dừng tạm thời (Pause) toàn bộ chương trình trong $20\text{ms} - 100\text{ms}$ để dọn bộ nhớ. Với chiếc xe đang chạy $80\text{km/h}$, $50\text{ms}$ gián đoạn đồng nghĩa với xe lao tự do 1.1 mét mà không hề được phanh hay đánh lái! C++ cho phép giải phóng bộ nhớ tức thì, loại bỏ 100% rủi ro này.

🎯 Vì sao C++ áp đảo tuyệt đối trong Robotics & Autonomous Vehicles?

Một chiếc xe tự hành chạy với tốc độ $80\text{ km/h}$ di chuyển khoảng 22.2 mét mỗi giây. Nếu thuật toán tránh vật cản bị chậm $50\text{ms}$ do trình thu gom rác (Garbage Collector của Python, Java hay Go) tạm dừng hệ thống để dọn bộ nhớ, hậu quả là va chạm không thể đảo ngược. C++ cung cấp 3 điều kiện tiên quyết mà không ngôn ngữ nào thay thế được:

  1. Deterministic Real-Time Performance (Tính xác định về thời gian): Không có Garbage Collector bất ngờ tạm dừng chương trình. Bộ nhớ được cấp phát và giải phóng chính xác tại thời điểm lập trình viên yêu cầu. Vòng lặp điều khiển $1000\text{ Hz}$ ($1\text{ms}$) luôn chạy đúng tiến độ.
  2. Hardware-Level Memory Control (Thao tác sát phần cứng): Đọc trực tiếp bộ nhớ CAN Bus xe, thanh ghi cảm biến IMU/Encoder qua I2C/SPI, bộ nhớ DMA với độ trễ microgiây ($\mu s$).
  3. Zero-Cost Abstractions (Trừu tượng hóa chi phí bằng 0): Lập trình Hướng đối tượng (OOP), Template, Lambda cực kỳ đẹp mắt và dễ đọc, nhưng khi biên dịch qua g++ -O3, trình biên dịch tối ưu thành mã máy cực nhanh hệt như C thuần hoặc Assembly.

0.1 Tối ưu CPU Cache Line & RAM Locality trong C++

Bộ nhớ RAM hiện đại hoạt động dựa trên cơ chế CPU Cache (L1, L2, L3 Cache Line size = 64 bytes). Khi CPU truy cập mảng phần tử nằm liên tục trong bộ nhớ (như std::vector hay std::array của C++), CPU Prefetcher sẽ tự động nạp sẵn 64-byte xung quanh vào L1 Cache với độ trễ chỉ 1ns. Ngược lại, các ngôn ngữ có Garbage Collection quản lý các đối tượng rải rác trên Heap, gây hiện tượng Cache Miss khiến CPU phải chờ nạp từ RAM mất 100ns (chậm hơn 100 lần!). Đây chính là chìa khóa giúp C++ xử lý 300,000 điểm mây LiDAR mỗi giây thời gian thực.

  • 🎯 Học để làm gì? Quản lý bộ nhớ RAM trực tiếp, làm chủ ranh giới giữa Stack vs Heap và quy tắc vàng const T& khi truyền tham số.
  • 🚗 Ứng dụng thực tế: Truyền mảng dữ liệu quét 360 tia LiDAR vào hàm xử lý mà không tốn chi phí CPU copy mảng ($0\text{ms}$ copy time), diệt sạch bug rò rỉ bộ nhớ.

🧠 TƯ DUY NỀN TẢNG: BẢN CHẤT BỘ NHỚ STACK VS HEAP QUA ẨN DỤ THỰC TẾ

Để lập trình C++ không bị "ngợp", hãy hình dung bộ nhớ RAM như hai khu vực làm việc:

  • Bộ nhớ Stack (Tủ đồ ngăn nắp): Giống như đĩa xếp chồng trong bếp. Khi bạn khai báo double speed = 5.0;, C++ đặt nó vào Stack. Hàm chạy xong, đĩa tự động dọn sạch. Cực kỳ nhanh ($1\text{ns}$ access), nhưng dung lượng nhỏ ($\sim 8\text{MB}$).
  • Bộ nhớ Heap (Bãi đỗ xe công cộng): Dung lượng khổng lồ bằng dung lượng RAM máy tính ($16\text{GB} - 64\text{GB}$). Dùng khi cần lưu dữ liệu kích thước lớn hoặc thay đổi linh hoạt (mây điểm LiDAR $100,000$ điểm). Bạn phải tự xin vé (khai báo cấp phát) và phải trả vé (giải phóng) khi dùng xong.
  • Quy tắc vàng const T&: Giống như cho người khác xem ảnh chụp cuốn sách qua điện thoại thay vì photo toàn bộ cuốn sách 1,000 trang gửi cho họ. Bạn tiết kiệm được $100\%$ CPU copy time!
🎯 Mục đích: 80% câu hỏi phỏng vấn C++ và 90% lỗi crash (Segmentation Fault) bắt nguồn từ con trỏ & quản lý bộ nhớ sai. Hiểu rõ Stack vs Heap giúp bạn tối ưu bộ nhớ cho vi điều khiển STM32/ESP32 và tránh rò rỉ bộ nhớ trên Linux ROS 2 node.

1.2 Con trỏ (*) vs Tham chiếu (&) vs Const Correctness

📌 Phân biệt 3 bản chất cốt lõi
  • Con trỏ (Pointer T*): Biến lưu địa chỉ bộ nhớ của biến khác. Có thể gán nullptr, có thể thay đổi địa chỉ trỏ tới. Kích thước hằng số ($8\text{ bytes}$ trên hệ 64-bit).
  • Tham chiếu (Reference T&): Bí danh (alias) trực tiếp của một biến đã tồn tại. Không thể null, không thể đổi sang trỏ biến khác sau khi khởi tạo.
  • Tham chiếu hằng (const T&): Truyền tham số không tốn chi phí copy, đồng thời bảo vệ biến không bị sửa đổi. Đây là chuẩn mực vàng truyền tham số trong C++ Robotics!

Ví dụ code 1: Phân biệt 4 cách truyền tham số mảng cảm biến LiDAR

#include <iostream>
#include <vector>
#include <chrono>

struct LidarScan {
    std::vector<double> ranges; // 360 tia quét LiDAR
    double timestamp;
};

// 1. Truyền bằng Pass-by-Value (Copy toàn bộ mảng): TẠO LỖI NGHỄN BỘ NHỚ!
void process_scan_bad(LidarScan scan) {
    // scan là bản sao độc lập! Copy 360 tia mất thời gian CPU.
}

// 2. Truyền bằng Pass-by-Reference (Tham chiếu): Nhanh, nhưng nguy cơ lỡ tay sửa mảng gốc
void process_scan_ref(LidarScan& scan) {
    scan.ranges[0] = 0.0; // ⚠️ Sửa trực tiếp dữ liệu bên ngoài!
}

// 3. Truyền bằng Pass-by-Const-Reference (CHUẨN ROBOTICS): Nhanh + An toàn
void process_scan_good(const LidarScan& scan) {
    // scan.ranges[0] = 0.0; // ❌ LỖI BIÊN DỊCH: Không cho phép sửa!
    std::cout << "So tia LiDAR: " << scan.ranges.size() << "\n";
}

// 4. Truyền bằng Con trỏ (Pointer): Dùng khi tham số có thể KHÔNG TỒN TẠI (null)
void process_scan_pointer(const LidarScan* scan_ptr) {
    if (scan_ptr == nullptr) { // 🔍 BẮT BUỘC CHECK NULLPTR!
        std::cout << "Lidar scan khong ton tai (NULL)\n";
        return;
    }
    std::cout << "Timestamp: " << scan_ptr->timestamp << "\n";
}

int main() {
    LidarScan my_scan;
    my_scan.ranges.resize(360, 5.2); // 360 tia khoảng cách 5.2m
    my_scan.timestamp = 100.25;

    process_scan_good(my_scan);       // Chi phí copy = 0ms!
    process_scan_pointer(&my_scan);   // Truyền địa chỉ
    process_scan_pointer(nullptr);    // Xử lý an toàn khi không có dữ liệu
    return 0;
}

BT1.1: Sửa lỗi Segfault trong đoạn code sau và giải thích nguyên nhân:

double* read_encoder() {

    double* p = read_encoder();

✅ Lời giải BT1.1

Nguyên nhân: Biến ticks nằm trên Stack của hàm read_encoder. Khi hàm kết thúc, Stack bị giải phóng nhưng p vẫn trỏ vào địa chỉ cũ (Dangling Pointer).

#include <iostream>

void read_encoder(double& out_ticks) { 
    out_ticks = 4096.0; 
}

int main() {

}

2.1 Struct vs Class trong C++: Khi nào dùng cái nào?

📌 Điểm khác biệt duy nhất

Trong C++, struct và class giống hệt nhau về khả năng (đều có phương thức, constructor, kế thừa). Điểm khác duy nhất là Access Modifier mặc định:

2.3 Ví dụ 2: Thiết kế Controller Interface đa hình (Polymorphism)

#include <iostream>
#include <vector>
#include <cmath>
#include <memory>

struct RobotState { double x = 0.0, y = 0.0, yaw = 0.0, v = 0.0; };
struct ControlOutput { double steering_angle = 0.0, acceleration = 0.0; };

// --- CLASS CHA TRỪU TƯỢNG (INTERFACE CHUNG CHO MỌI CONTROLLER) ---
class AbstractController {
public:
    // Destructor ảo: BẮT BUỘC để tránh rò rỉ bộ nhớ khi xóa qua con trỏ lớp cha!
    virtual ~AbstractController() {
        std::cout << "[Base] Destructor AbstractController\n";
    }

    // Pure Virtual Function (= 0): Bắt buộc các thuật toán con phải tự triển khai
    virtual ControlOutput compute_control(const RobotState& current_state, 
                                         double target_x, double target_y) = 0;
};

// --- BỘ ĐIỀU KHIỂN 1: PURE PURSUIT ---
class PurePursuitController : public AbstractController {
private:
    double lookahead_distance_;
public:
    PurePursuitController(double L) : lookahead_distance_(L) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double dx = target_x - state.x;
        double dy = target_y - state.y;
        double alpha = std::atan2(dy, dx) - state.yaw;
        out.steering_angle = std::atan2(2.0 * 0.5 * std::sin(alpha), lookahead_distance_);
        out.acceleration = 0.5;
        std::cout << "[PurePursuit] Goc lai: " << out.steering_angle << " rad\n";
        return out;
    }
};

// --- BỘ ĐIỀU KHIỂN 2: STANLEY CONTROLLER ---
class StanleyController : public AbstractController {
private:
    double k_gain_;
public:
    StanleyController(double k) : k_gain_(k) {}

    ControlOutput compute_control(const RobotState& state, 
                                 double target_x, double target_y) override {
        ControlOutput out;
        double cross_track_error = target_y - state.y;
        out.steering_angle = std::atan2(k_gain_ * cross_track_error, state.v + 0.1);
        out.acceleration = 0.2;
        std::cout << "[Stanley] Goc lai: " << out.steering_angle << " rad\n";
        return out;
    }
};

int main() {
    RobotState car{0.0, 0.0, 0.0, 2.0};
    
    // ĐA HÌNH (POLYMORPHISM): Con trỏ Interface quản lý nhiều thuật toán khác nhau
    std::vector<std::unique_ptr<AbstractController>> controllers;
    controllers.push_back(std::make_unique<PurePursuitController>(2.5));
    controllers.push_back(std::make_unique<StanleyController>(0.5));

    for (const auto& ctrl : controllers) {
        ctrl->compute_control(car, 10.0, 3.0);
    }
    return 0;
}

2.4 Ví dụ 3: Giới thiệu Rule of 5 (Quản lý tài nguyên chuẩn C++)

#include <iostream>
#include <cstring>

class HardwareBuffer {
private:
    size_t size_;
    uint8_t* data_;
public:
    // 1. Constructor
    HardwareBuffer(size_t size) : size_(size), data_(new uint8_t[size]) {}

    // 2. Destructor
    ~HardwareBuffer() { delete[] data_; }

    // 3. Copy Constructor (Deep Copy)
    HardwareBuffer(const HardwareBuffer& other) : size_(other.size_), data_(new uint8_t[other.size_]) {
        std::memcpy(data_, other.data_, size_);
    }

    // 4. Copy Assignment Operator
    HardwareBuffer& operator=(const HardwareBuffer& other) {
        if (this == &other) return *this;
        delete[] data_;
        size_ = other.size_;
        data_ = new uint8_t[size_];
        std::memcpy(data_, other.data_, size_);
        return *this;
    }

    // 5. Move Constructor (Move Semantics)
    HardwareBuffer(HardwareBuffer&& other) noexcept : size_(other.size_), data_(other.data_) {
        other.size_ = 0;
        other.data_ = nullptr;
    }
};

PHẦN 3 — QUẢN LÝ TÀI NGUYÊN RAII & SMART POINTERS

RAII Pattern · std::unique_ptr · std::shared_ptr · std::weak_ptr · shared_from_this · Lifecycle Node Pattern 🔬 CẦN HIỂU SÂU

💡 Ý NGHĨA & MỤC ĐÍCH HỌC PHẦN 3: RAII & SMART POINTERS CHUẨN ROS 2
  • 🎯 Học để làm gì? Tự động hóa quản lý bộ nhớ, loại bỏ hoàn toàn việc gõ từ khóa new và delete thủ công bằng RAII và Smart Pointers (C++17).
  • 🚗 Ứng dụng thực tế: Viết các ROS 2 Nodes (`rclcpp::Node`), chia sẻ dữ liệu Costmap 2D giữa Global Planner và Local Planner bằng `std::shared_ptr`, và triển khai Lifecycle Node State Machine.
  • ⚠️ Nếu không biết phần này: Phần mềm robot chạy liên tục vài tiếng sẽ bị rò rỉ bộ nhớ (Memory Leak), làm kiệt huệ dung lượng RAM và khiến hệ điều hành sập hoàn toàn (OS Out-Of-Memory Crash).
🧠 TƯ DUY NỀN TẢNG: GIẢI MÃ SMART POINTERS VÀ VÌ SAO PHẢI BỎ `new`/`delete`

Trong C++ cũ, gõ new mà quên gõ delete sẽ gây ra hiện tượng Rò rỉ bộ nhớ (Memory Leak) — RAM cứ bị chiếm dụng dần cho tới khi máy tính bị treo sập. C++17 giải quyết triệt để bằng Smart Pointers với nguyên lý RAII (Vừa khởi tạo là sở hữu, ra khỏi scope là tự hủy):

  • `std::unique_ptr` (Chìa khóa xe duy nhất): Chỉ có duy nhất 1 người cầm chìa khóa sở hữu chiếc xe. Muốn đưa cho người khác phải dùng std::move() để trao hẳn chìa khóa đi. Chi phí Overhead = 0 bytes!
  • `std::shared_ptr` (Sổ hồng nhà chung đứng tên 3 người): Vùng nhớ chỉ bị đập bỏ (hủy RAM) khi người đứng tên cuối cùng rút lui (Reference Count = 0). Dùng khi dữ liệu Costmap được cả 2 Node Global Planner & Local Planner cùng đọc.
  • `std::weak_ptr` (Khách tham quan): Chỉ đứng ngoài nhìn mà không đứng tên sổ hồng, giúp tránh hiện tượng 2 người giữ chìa khóa của nhau gây khóa chết (Circular Reference).
🎯 Mục đích: Trong C++ hiện đại (C++17 trở lên), bạn hạn chế tối đa gõ từ khóa `new` và `delete` thủ công. Kỹ thuật RAII (Resource Acquisition Is Initialization) kết hợp với Smart Pointers giúp chương trình robot tự động giải phóng bộ nhớ ngay khi đối tượng ra khỏi scope, chống Memory Leak 100%.

3.1 Ba loại Smart Pointers trong C++17

Loại Smart Pointer Quyền sở hữu (Ownership) Ứng dụng thực tế trong ROS 2 / Robotics
std::unique_ptr<T> Độc quyền (Unique): Chỉ duy nhất 1 con trỏ sở hữu. Không thể copy, chỉ có thể chuyển giao quyền sở hữu qua std::move. Dùng mặc định! Chi phí overhead bằng 0 ($0\text{ bytes}$ extra). Dùng cho Driver Cảm biến IMU, Controller Instance, Local Planner.
std::shared_ptr<T> Chia sẻ (Shared): Nhiều con trỏ cùng sở hữu. Vùng nhớ giải phóng khi con trỏ cuối cùng hủy (Reference Count = 0). Dùng khi dữ liệu được đọc bởi nhiều Thread/Node (vd: Bản đồ Costmap 2D được đọc bởi cả Global Planner và Local Planner).
std::weak_ptr<T> Không sở hữu (Weak): Tham chiếu tới shared_ptr mà không làm tăng Reference Count. Tránh vòng lặp tham chiếu (Circular Reference) gây rò rỉ bộ nhớ. Dùng cho Observer Pattern, Action Goal Handles.

4.3 Ví dụ 2: `std::deque` — Sliding Window Filter cho Cảm biến IMU

#include <iostream>
#include <deque>
#include <numeric>

class MovingAverageIMU {
private:
    size_t window_size_;
    std::deque<double> buffer_;
public:
    MovingAverageIMU(size_t window_size) : window_size_(window_size) {}

    double add_measurement(double val) {
        buffer_.push_back(val);
        if (buffer_.size() > window_size_) {
            buffer_.pop_front();
        }
        double sum = std::accumulate(buffer_.begin(), buffer_.end(), 0.0);
        return sum / buffer_.size();
    }
};

int main() {
    MovingAverageIMU filter(3);
    std::cout << "Filtered: " << filter.add_measurement(10.0) << "\n";
    std::cout << "Filtered: " << filter.add_measurement(12.0) << "\n";
    std::cout << "Filtered: " << filter.add_measurement(14.0) << "\n";
    return 0;
}

};

        open_set.pop();
        std::cout << "Duyet Node (" << current.x << ", " << current.y << ") | f_cost = " << current.f_cost() << "\n";

}

#include <vector>
#include <algorithm>
#include <numeric>
#include <cmath>

struct Obstacle {
    int id;
    double distance;
};

int main() {
    std::vector<double> lidar_ranges = {2.5, 0.4, 12.0, NAN, 1.8, -0.5, 5.0};

    // 1. std::clamp: Giới hạn góc lái trong khoảng [-0.5 rad, +0.5 rad]
    double raw_steering = 0.85;
    double safe_steering = std::clamp(raw_steering, -0.5, 0.5);
    std::cout << "Goc lai sau clamp: " << safe_steering << " rad\n";

    // 2. Erase-Remove Idiom: Lọc bỏ các tia LiDAR bị lỗi (NaN hoặc âm)
    lidar_ranges.erase(
        std::remove_if(lidar_ranges.begin(), lidar_ranges.end(), [](double r) {
            return std::isnan(r) || r < 0.0;
        }),
        lidar_ranges.end()
    );

    // 3. std::min_element: Tìm tia LiDAR có khoảng cách nhỏ nhất
    auto min_it = std::min_element(lidar_ranges.begin(), lidar_ranges.end());
    if (min_it != lidar_ranges.end()) {
        std::cout << "Vat can gan nhat: " << *min_it << " m\n";
    }

    // 4. std::accumulate: Tính tổng / trung bình khoảng cách các tia
    double sum = std::accumulate(lidar_ranges.begin(), lidar_ranges.end(), 0.0);
    double avg = sum / lidar_ranges.size();
    std::cout << "Khoang cach trung binh: " << avg << " m\n";

    // 5. std::sort với Lambda: Sắp xếp danh sách Vật cản theo khoảng cách tăng dần
    std::vector<Obstacle> obstacles = {{1, 8.5}, {2, 1.2}, {3, 4.0}};
    std::sort(obstacles.begin(), obstacles.end(), [](const Obstacle& a, const Obstacle& b) {
        return a.distance < b.distance;
    });
    std::cout << "Obstacle gan nhat ID: " << obstacles[0].id << " (" << obstacles[0].distance << "m)\n";

    // 6. std::lower_bound: Tìm kiếm nhị phân Waypoint gần mốc thời gian t = 2.0s nhất
    std::vector<double> timestamps = {0.0, 0.5, 1.0, 1.5, 2.0, 2.5, 3.0};
    auto target_it = std::lower_bound(timestamps.begin(), timestamps.end(), 2.0);
    std::cout << "Tim thay timestamp: " << *target_it << "s tai index " 
              << std::distance(timestamps.begin(), target_it) << "\n";

    // 7. std::transform: Biến đổi tọa độ batch
    std::vector<double> raw_encoder = {100, 200, 300};
    std::vector<double> meters(raw_encoder.size());
    std::transform(raw_encoder.begin(), raw_encoder.end(), meters.begin(), [](double ticks) {
        return ticks * 0.001;
    });
    std::cout << "Encoder index 0 sang meters: " << meters[0] << " m\n";

    // 8. std::find_if: Tìm xem có vật cản nào nguy hiểm (< 0.5m) không
    auto danger_it = std::find_if(obstacles.begin(), obstacles.end(), [](const Obstacle& obs) {
        return obs.distance < 0.5;
    });
    if (danger_it == obstacles.end()) {
        std::cout << "Khong co vat can trong vung nguy hiem.\n";
    }

    return 0;

6.3 Class Template: Bộ lọc LowPassFilter dùng chung mọi kiểu dữ liệu

#include <iostream>

template <typename T>
class LowPassFilter {
private:
    T alpha_;
    T prev_output_;
    bool initialized_ = false;
public:
    LowPassFilter(T alpha) : alpha_(alpha), prev_output_(0) {}

    T filter(T input) {
        if (!initialized_) {
            prev_output_ = input;
            initialized_ = true;
            return input;
        }
        T output = alpha_ * input + (static_cast<T>(1.0) - alpha_) * prev_output_;
        prev_output_ = output;
        return output;
    }
};

int main() {
    LowPassFilter<double> vel_filter(0.2);
    std::cout << "Filtered: " << vel_filter.filter(10.0) << "\n";
    std::cout << "Filtered: " << vel_filter.filter(15.0) << "\n";
    return 0;
}

7.3 Mô Phỏng Extended Kalman Filter (EKF 2D Localization) C++17 Chi Tiết

Bộ lọc Kalman mở rộng (EKF) là trái tim của hệ thống định vị Robot (Localization) kết hợp giữa mô hình Động học (Kinematics Prediction) và số liệu đo Cảm biến (Sensor Measurement Update). Dưới đây là lớp EKF Solver viết bằng C++17 hoàn chỉnh.

3

Code EKF 2D State Estimator C++17 hoàn chỉnh

#include <iostream>
#include <optional>
#include <tuple>
#include <cmath>
#include <array>

// Struct lưu trữ trạng thái ước lượng Robot 2D [x, y, yaw]
struct RobotState2D {
    double x = 0.0;     // Tọa độ X (mét)
    double y = 0.0;     // Tọa độ Y (mét)
    double yaw = 0.0;   // Góc Hướng Heading (radian)
};

class EKF2DSolver {
private:
    RobotState2D state_;
    // Ma trận hiệp phương sai sai số Covariance Matrix P (3x3 đơn giản hóa diagonal)
    std::array<double, 3> P_{0.1, 0.1, 0.05}; 
    // Độ nhiễu mô hình Predict Noise Q
    const std::array<double, 3> Q_{0.02, 0.02, 0.01};
    // Độ nhiễu đo cảm biến GPS Noise R
    const std::array<double, 2> R_{0.5, 0.5};

public:
    EKF2DSolver(double init_x, double init_y, double init_yaw) 
        : state_{init_x, init_y, init_yaw} {}

    // 1. Bước PREDICT: Dựa trên Odometry Vận tốc v (m/s) và Tốc độ góc omega (rad/s)
    void predict(double v, double omega, double dt) {
        // Cập nhật trạng thái theo Mô hình Động học Xe Unicycle Model
        state_.x += v * std::cos(state_.yaw) * dt;
        state_.y += v * std::sin(state_.yaw) * dt;
        state_.yaw += omega * dt;

        // Chuẩn hóa góc yaw trong dải [-PI, +PI]
        state_.yaw = std::atan2(std::sin(state_.yaw), std::cos(state_.yaw));

        // Cập nhật ma trận sai số P = P + Q
        P_[0] += Q_[0];
        P_[1] += Q_[1];
        P_[2] += Q_[2];
    }

    // 2. Bước UPDATE: Cập nhật số liệu đo GPS (x_gps, y_gps) nếu có tín hiệu (std::optional)
    void update(std::optional<std::pair<double, double>> gps_measurement) {
        if (!gps_measurement.has_value()) {
            // Không có GPS (mất sóng) -> Bỏ qua bước update, giữ nguyên kết quả predict
            return;
        }

        // Structured Bindings C++17 unpack dữ liệu GPS
        auto [z_x, z_y] = gps_measurement.value();

        // Tính Innovation (Sai số giữa số đo cảm biến và dự đoán)
        double y_x = z_x - state_.x;
        double y_y = z_y - state_.y;

        // Tính Kalman Gain K = P / (P + R)
        double K_x = P_[0] / (P_[0] + R_[0]);
        double K_y = P_[1] / (P_[1] + R_[1]);

        // Cập nhật Trạng thái Ước lượng mới State = State + K * Innovation
        state_.x += K_x * y_x;
        state_.y += K_y * y_y;

        // Cập nhật Hiệp phương sai P = (1 - K) * P
        P_[0] = (1.0 - K_x) * P_[0];
        P_[1] = (1.0 - K_y) * P_[1];
    }

    RobotState2D get_state() const { return state_; }
};

int main() {
    EKF2DSolver ekf(0.0, 0.0, 0.0);

    std::cout << "--- MÔ PHỎNG VÒNG LẶP EKF LOCALIZATION 5 BƯỚC ---
";
    for (int step = 1; step <= 5; ++step) {
        // Step predict: v = 1.0 m/s, omega = 0.1 rad/s, dt = 0.1s
        ekf.predict(1.0, 0.1, 0.1);

        // Mô phỏng GPS chỉ phát tín hiệu ở bước 3 và 5
        std::optional<std::pair<double, double>> gps_data = std::nullopt;
        if (step == 3) gps_data = std::make_pair(0.28, 0.02);
        if (step == 5) gps_data = std::make_pair(0.49, 0.09);

        ekf.update(gps_data);

        auto s = ekf.get_state();
        std::printf("Step %d | State: x=%5.3f m, y=%5.3f m, yaw=%5.3f rad | GPS Status: %s
",
                    step, s.x, s.y, s.yaw, gps_data.has_value() ? "UPDATED GPS" : "NO GPS");
    }
    return 0;
}

  • Thao tác MOVE / ZERO-COPY (Tức thời $0\text{ms}$): Bạn cầm đúng cuốn tài liệu gốc đưa tận tay cho Subscriber và bảo: "Từ giờ cuốn sách này thuộc về bạn!" (chuyển giao con trỏ std::unique_ptr qua std::move()). Không một byte dữ liệu nào bị copy!

8.1 Bản Chất Lvalue vs Rvalue Reference & `std::move`

Trong C++ truyền thống (C++03), khi bạn gán hoặc truyền một mảng dữ liệu lớn vào hàm, C++ bắt buộc phải **COPY TOÀN BỘ BỘ NHỚ HEAP** từ đối tượng nguồn sang đối tượng đích. Với Move Semantics (C++11/17):

  • Lvalue (Left Value): Đối tượng có định danh tên rõ ràng, có địa chỉ bộ nhớ cố định (vd: std::vector<float> scan1).
  • Rvalue (Right Value): Giá trị tạm thời sắp bị hủy (Temporary object), biểu diễn bằng cú pháp T&&.
  • `std::move(x)`: Không hề di chuyển bất kỳ byte dữ liệu nào! Nó chỉ đơn thuần **ÉP KIỂU (Cast)** biến `x` thành Rvalue reference T&& để kích hoạt Move Constructor cướp con trỏ bộ nhớ internal buffer trong $0.0001 ext{ms}$.

8.2 Cơ Chế Zero-Copy IPC Trong ROS 2 (`rclcpp`)

🔎 Mô hình Zero-Copy Inter-Process Communication (IPC) ROS 2

Khi Publisher và Subscriber nằm trong cùng một Process (Intra-process Communication), thay vì Serialize tin nhắn ra chuẩn CDR và Copy qua mạng, ROS 2 sử dụng std::unique_ptr. Publisher cấp phát bộ nhớ Shared Memory, nạp dữ liệu PointCloud2, sau đó **"chuyển giao quyền sở hữu con trỏ"** sang Subscriber bằng publish(std::move(msg)). Chi phí copy bộ nhớ = 0 bytes!

9.1 Đa Luồng C++ & Bảo Vệ Shared Data với `std::scoped_lock`

Khi hai hay nhiều Thread cùng đọc và ghi vào một biến số dùng chung (shared variable) tại một thời điểm, hiện tượng **Race Condition** sẽ xảy ra làm dữ liệu bị sai hỏng. C++17 cung cấp std::scoped_lock giúp khóa đồng thời nhiều Mutex một cách an toàn mà không bao giờ bị Deadlock.

9.2 Phân Tích Chuyên Sâu ROS 2 Executors & Callback Groups

📌 Phân biệt 2 loại Callback Groups trong ROS 2 (`rclcpp`)
  • `MutuallyExclusiveCallbackGroup`: Các Callback thuộc nhóm này chỉ được thực thi từng cái một (Tuần tự). Dù Executor có bao nhiêu Thread đi nữa, các Callback này KHÔNG BAO GIỜ chạy song song. Dùng mặc định để bảo vệ biến thành viên của Node không cần dùng Mutex.
  • `ReentrantCallbackGroup`: Các Callback thuộc nhóm này được phép thực thi **SONG SONG ĐỒNG THỜI** trên nhiều Worker Threads của MultiThreadedExecutor. Bắt buộc phải dùng `std::mutex` hoặc `std::atomic` bảo vệ dữ liệu shared!

        // Vòng lặp điều khiển chạy cực kỳ mượt mà 100Hz không bị ảnh hưởng bởi task nặng
        // RCLCPP_INFO(this->get_logger(), "[100Hz Loop] Read Sensor: %.2f", latest_sensor_value_);

        return CallbackReturn::SUCCESS;
    }

    // 3. Transition: Active -> Inactive
    CallbackReturn on_deactivate(const rclcpp_lifecycle::State &) override {
        RCLCPP_WARN(get_logger(), "[Lifecycle] On Deactivate: Ngung phat motor_cmd de an toan!");
        cmd_pub_->on_deactivate();
        return CallbackReturn::SUCCESS;
    }

    // 4. Transition: Inactive -> Unconfigured
    CallbackReturn on_cleanup(const rclcpp_lifecycle::State &) override {
        RCLCPP_INFO(get_logger(), "[Lifecycle] On Cleanup: Giai phong con tro Publisher");
        cmd_pub_.reset();
        return CallbackReturn::SUCCESS;
    }

    double compute_pid(double setpoint, double measurement) {
        double error = setpoint - measurement;
        integral_ += error * dt_;
        double derivative = (error - prev_error_) / dt_;
        double output = kp_ * error + ki_ * integral_ + kd_ * derivative;
        double clamped = std::clamp(output, min_out_, max_out_);
        if (output != clamped && ki_ != 0.0) integral_ -= error * dt_; // Anti-windup
        prev_error_ = error;
        return clamped;
    }
};

int main(int argc, char ** argv) {
    rclcpp::init(argc, argv);
    auto node = std::make_shared<LifecyclePIDNode>();
    rclcpp::spin(node->get_node_base_interface());
    rclcpp::shutdown();
    return 0;
}

11.2 Dự Án 2: Complete ROS 2 Pure Pursuit Trajectory Tracking Node

Node ROS 2 Pure Pursuit Controller Bám Đường F1TENTH

#include <memory>
#include <vector>
#include <cmath>
#include <algorithm>
#include "rclcpp/rclcpp.hpp"
#include "geometry_msgs/msg/twist.hpp"
#include "nav_msgs/msg/odometry.hpp"

struct Waypoint { double x, y, speed; };

class PurePursuitNode : public rclcpp::Node {
private:
    double lookahead_dist_ = 2.0;
    double wheelbase_ = 0.33; // Xe F1TENTH 1/10 scale
    std::vector<Waypoint> waypoints_;

    rclcpp::Subscription<nav_msgs::msg::Odometry>::SharedPtr odom_sub_;
    rclcpp::Publisher<geometry_msgs::msg::Twist>::SharedPtr cmd_pub_;

public:
    PurePursuitNode() : Node("pure_pursuit_node") {
        // Nạp danh sách Waypoint quỹ đạo
        waypoints_ = {{0.0,0.0,2.0}, {2.0,0.5,2.0}, {4.0,2.0,2.5}, {6.0,5.0,2.5}};

        cmd_pub_ = this->create_publisher<geometry_msgs::msg::Twist>("/cmd_vel", 10);

        odom_sub_ = this->create_subscription<nav_msgs::msg::Odometry>(
            "/odom", 10, std::bind(&PurePursuitNode::odom_callback, this, std::placeholders::_1));
        
        RCLCPP_INFO(this->get_logger(), "Pure Pursuit Node khoi tao thanh cong!");
    }

private:
    void odom_callback(const nav_msgs::msg::Odometry::SharedPtr msg) {
        double rx = msg->pose.pose.position.x;
        double ry = msg->pose.pose.position.y;

        // Trích xuất góc Yaw từ Quaternion
        double qz = msg->pose.pose.orientation.z;
        double qw = msg->pose.pose.orientation.w;
        double ryaw = 2.0 * std::atan2(qz, qw);

        // 1. Tìm Target Waypoint gần mốc Lookahead L nhất
        auto target_it = std::min_element(waypoints_.begin(), waypoints_.end(),
            [rx, ry, this](const Waypoint& a, const Waypoint& b) {
                return std::abs(std::hypot(a.x - rx, a.y - ry) - lookahead_dist_) <
                       std::abs(std::hypot(b.x - rx, b.y - ry) - lookahead_dist_);
            });

        // 2. Tính góc lái Pure Pursuit: delta = atan2(2 * L_wb * sin(alpha), L)
        double dx = target_it->x - rx;
        double dy = target_it->y - ry;
        double alpha = std::atan2(dy, dx) - ryaw;
        double steering_angle = std::atan2(2.0 * wheelbase_ * std::sin(alpha), lookahead_dist_);

        // 3. Publish Twist msg
        geometry_msgs::msg::Twist cmd;
        cmd.linear.x = target_it->speed;
        cmd.angular.z = std::clamp(steering_angle, -0.6, 0.6);
        cmd_pub_->publish(cmd);
    }
};

int main(int argc, char ** argv) {
    rclcpp::init(argc, argv);
    rclcpp::spin(std::make_shared<PurePursuitNode>());
    rclcpp::shutdown();
    return 0;
}

🚦 Bộ Quiz Kiểm Tra Toàn Bộ Kiến Thức C++ ROS 2 (15 Câu)

Q1: Vì sao trong code C++ ROS 2, ta luôn ưu tiên dùng `const T&` khi truyền mảng điểm LiDAR thay vì truyền trực tiếp `T`?

✅ Đáp án Chi Tiết

Truyền `const T&` giúp tránh tốn chi phí CPU copy mảng dữ liệu lớn ($0 ext{ms}$ copy), đồng thời từ khóa `const` bảo vệ dữ liệu mảng không bị sửa đổi.

Q2: Sự khác nhau giữa `std::unique_ptr` và `std::shared_ptr` là gì? Loại nào dùng trong Zero-Copy ROS 2 IPC?

✅ Đáp án Chi Tiết

`std::unique_ptr` sở hữu độc quyền (không copy được), chi phí Overhead = 0 và được ROS 2 dùng để thực hiện Zero-Copy IPC khi `publish(std::move(msg))`.

Q3: Khác biệt cốt lõi giữa `MutuallyExclusiveCallbackGroup` và `ReentrantCallbackGroup` trong ROS 2 Executor là gì?

✅ Đáp án Chi Tiết

`MutuallyExclusive` chỉ cho phép 1 callback chạy tại một thời điểm (tuần tự). `Reentrant` cho phép các callback chạy song song đồng thời trên nhiều thread (cần Mutex bảo vệ shared data).

Q4: `std::move` thực chất thực hiện hành động gì ở mức trình biên dịch?

✅ Đáp án Chi Tiết

`std::move` không di chuyển byte dữ liệu nào! Nó chỉ ép kiểu (cast) Lvalue thành Rvalue reference (`T&&`) để kích hoạt Move Constructor cướp quyền sở hữu con trỏ internal buffer.

Q5: Lợi ích của việc dùng `std::optional` thay vì trả về `-1.0` khi hàm tính toán bị lỗi?

✅ Đáp án Chi Tiết

`std::optional` thể hiện an toàn trạng thái Có hoặc Không tồn tại giá trị (`std::nullopt`), loại bỏ nguy cơ vô tình dùng nhầm giá trị âm rác `-1.0` vào bộ lọc Kalman.
