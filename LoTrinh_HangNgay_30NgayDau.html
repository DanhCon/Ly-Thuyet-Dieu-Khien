Ngày 1 — Cài Ubuntu + làm quen terminal

🎯 Mục đích: ROS2 Humble chạy trên Ubuntu 22.04 — không có nó, tuần 7 không thể bắt đầu. Terminal là nơi bạn sống: mỗi lệnh cài đặt, mỗi lần xem log robot đều qua đây. Hôm nay cài xong môi trường = hết cả tháng sắp tới không mất thời gian "sửa máy".
  • Cách cài (chọn 1): (a) Ubuntu 22.04 song song Windows — khuyến nghị, vì GPU/sim sau này chạy mượt; (b) WSL2 nếu máy yếu; (c) Docker Desktop + image ubuntu:22.04 nếu chưa muốn đụng ổ cứng.
  • Học 10 lệnh đầu đời: pwd, ls, cd, mkdir, touch, cp, mv, rm, cat, nano (hoặc vim). Tạo cây thư mục ~/dev/ cho toàn bộ dự án sau này.
  • Thử thách: tạo file hello.txt, ghi dòng chữ bằng nano, xem lại bằng cat, copy sang tên khác, xóa bản gốc. Làm xong = biết 50% terminal.

Ngày 2 — Hệ thống file Linux + quyền + cài phần mềm

🎯 Mục đích: 90% lỗi người mới gặp là "permission denied" và "command not found". Hiểu quyền (chmod), sudo, PATH = tự xử lý 80% lỗi cài đặt ROS2 sau này mà không cần hỏi ai. Cài đặt phần mềm bằng apt là kỹ năng bạn dùng 20 lần/tuần.
  • Cấu trúc thư mục Linux: /home, /usr, /etc, /var, /tmp — mỗi cái để làm gì (chỉ cần hiểu ý tưởng).
  • Quyền: chmod 755/644 nghĩa là gì (r/w/x cho user/group/other), sudo khi nào cần, biến môi trường export PATH=$PATH:....
  • Thực hành: sudo apt update → sudo apt install git curl build-essential gdb. Cài xong = bạn đã có toàn bộ công cụ của tuần này và tuần sau.
  • Kiểm tra: g++ --version hiện bản 11+ — nếu chưa có, cài g++ qua apt.
✅ Checklist ngày 2 ☐ Giải thích được chmod 755 vs 644 bằng lời · ☐ apt update/install chạy sạch không lỗi · ☐ g++/git/gdb đã cài, phiên bản hiển thị đúng · ☐ Ghi nhật ký

Ngày 3 — Git: lệnh cơ bản + commit đầu tiên

🎯 Mục đích — kiến thức bổ trợ số 1: Không JD nào ghi "Git" ngoài Phenikaa-X, nhưng Git là ngôn ngữ làm việc của mọi đội kỹ thuật. Quan trọng hơn với riêng bạn: lộ trình 24 tuần đếm bằng commit — "không commit trong 1 tuần = tuần đó không học đúng thứ cần". Git cũng là cơ chế lưu trữ bằng chứng: mỗi commit là một viên gạch của CV. Hôm nay biến lịch sử học tập của bạn thành lịch sử commit.
  • Học: git init, git add, git commit -m, git status, git log, git diff. Khái niệm staging area = "bàn trung chuyển" trước khi đóng gói.
  • Tạo repo đầu tiên: ~/dev/notes/ — ghi chú kỹ thuật của bạn. Commit đầu tiên với 1 file README.md.
  • Viết README đầu tiên theo chuẩn: tiêu đề + 2 câu mô tả + cách dùng. Đây là mẫu cho mọi repo sau (chuẩn kỹ thuật người ta đọc đầu tiên).
✅ Checklist ngày 3 ☐ git config user.name/email đã đặt · ☐ Repo notes có ≥ 2 commit · ☐ Viết được README 5 dòng · ☐ Nhật ký

Ngày 4 — GitHub: push repo + branch + merge

🎯 Mục đích: Repo trên máy bạn = không ai thấy. Repo trên GitHub = CV kỹ thuật sống mà recruiter mở ra đọc. Branch/merge là cách đội ngũ 10 người làm chung một codebase mà không đè lên nhau — bạn sẽ cần ngay từ đồ án nhóm hoặc dự án công ty. Học hôm nay còn dễ, học khi đang làm việc nhóm là áp lực.
  • Tạo tài khoản GitHub (nếu chưa có), push repo notes lên: git remote add origin + git push -u origin main.
  • Branch: tạo git branch dev, chuyển qua, sửa file, commit, merge về main bằng git merge. Xem git log --graph thấy lịch sử.
  • Học Markdown đủ dùng: tiêu đề, list, code block, bảng, link — ghi lại 1 trang cheat-sheet Markdown vào notes.
  • Thử thách: sửa README trên GitHub bằng web → pull về máy → push 1 thay đổi khác từ máy → giải quyết nếu có conflict (thử tạo conflict thật để biết nó trông ra sao).
✅ Checklist ngày 4 ☐ Repo notes có trên GitHub (public) · ☐ Tự tạo + merge 1 branch · ☐ Biết Markdown viết bảng · ☐ Trải qua 1 conflict và hiểu cách sửa

Ngày 5 — Docker căn bản

🎯 Mục đích: Phenikaa-X ghi thẳng "Sử dụng thành thạo Docker, Git, RViz2, Foxglove". Docker cho phép cài ROS2 mà không sợ phá hệ điều hành — bạn sẽ tận dụng ngay ở tuần 7–8. Khái niệm image/container = "bản vẽ" và "căn hộ được xây từ bản vẽ": cùng một bản vẽ, mở bao nhiêu căn hộ cũng được, phá căn hộ không ảnh hưởng bản vẽ.
  • Cài Docker Engine + Docker Desktop (Ubuntu). Chạy container đầu tiên: docker run -it ubuntu:22.04 bash — bạn đang ở trong một Linux sạch hoàn toàn.
  • Học: docker pull, docker run, docker exec, docker ps, docker stop/rm, -v (mount thư mục), -it.
  • Viết Dockerfile đơn giản: FROM ubuntu:22.04 → RUN apt update && apt install -y build-essential → COPY → CMD. Build và chạy image của chính mình.
  • Mẹo chống nản: mount -v ~/dev:/workspace để code trên máy hiện ngay trong container.
✅ Checklist ngày 5 ☐ Chạy được container ubuntu tương tác · ☐ Tự viết + build Dockerfile đầu tiên · ☐ Hiểu image vs container (giải thích được bằng lời) · ☐ Mount thư mục hoạt động

Ngày 8 — Phần 1: nền tảng — biến, con trỏ, tham chiếu, const

🎯 Mục đích: Con trỏ và tham chiếu là thứ làm C++ khác mọi ngôn ngữ khác — và là nơi 80% lỗi phỏng vấn C++ nằm. Vì sao phải hiểu sâu? Vì bạn sẽ đọc code Nav2/F1TENTH: toàn con trỏ, tham chiếu, const. Không hiểu 3 khái niệm này = đọc code người khác như đọc chữ tượng hình.
  • Đọc Phần 1 tài liệu C++: biến, kiểu dữ liệu, int* p = &x, int& r = x, const int& — 3 khái niệm này khác nhau thế nào, dùng khi nào.
  • Gõ lại các ví dụ trong tài liệu. Biên dịch: g++ -std=c++17 file.cpp -o file rồi chạy.
  • Bài tập tự nghĩ: viết hàm nhận tham chiếu và sửa biến bên ngoài; viết hàm nhận con trỏ nullptr và xử lý an toàn. Đây là 2 mẫu cực phổ biến trong code robot.
  • Dự đoán kết quả trước khi chạy từng đoạn — sai cũng được, quan trọng là đối chiếu.
