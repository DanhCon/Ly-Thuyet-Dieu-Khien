1 · What Is the Kalman Filter?

I first ran into the Kalman Filter as an undergraduate. I was building a drone, and I needed to estimate its tilt angle from a handful of cheap, noisy sensors. With no background in estimation, I did what everyone does — I searched for "Kalman Filter." What came back was a wall of bewildering matrix equations that left me completely clueless.

It took years of projects before I could finally appreciate how beautiful and how important the Kalman Filter really is. It guided the Apollo spacecraft to the Moon: the craft had to follow a strict trajectory, which demanded an accurate estimate of its position even as noise and interference corrupted every sensor reading. The filter handled it. More than sixty years later, it is still everywhere — robots, drones, self-driving cars, phones, satellites — quietly withstanding the test of time.

So what is the Kalman Filter? The honest answer depends on your background. From an engineering perspective, it is a data fusion algorithm: every real sensor reports its true measurement plus noise. No single sensor is trustworthy on its own. The Kalman Filter combines several imperfect sources — and a model of how things move — into one estimate that is better than any of them alone.

To get there, we build up the ideas systematically, from easy to hard. First, random variables and variance to quantify noise. Then the Gaussian distribution, and a simple data fusion rule. That gives us the one-dimensional Kalman Filter. From there we add covariance and matrices to reach the full linear Kalman Filter in two dimensions.

2 · Why Do We Need Random Variables?

In a perfectly deterministic world we would not need random variables. The temperature would be exactly $30^\circ C$, an exam score would be exactly 90, and a sensor would report the exact truth every time.

But the real world is noisy. Every real sensor — GPS, an encoder, an accelerometer — returns a value that is close to the truth, but never exactly the truth.

To describe the real world correctly, we need random variables. The single most important one for the Kalman Filter is the Gaussian (normal) distribution.

3 · The Gaussian Distribution and Sensor Noise

A Gaussian distribution describes how likely each value of a random variable is. It is fully defined by just two numbers: the mean $\mu$ (where the bell is centered) and the variance $\sigma^2$ (how wide it spreads). Its probability density function is:

$$p(x) = \frac{1}{\sqrt{2\pi\sigma^2}}\; \exp\!\left(-\frac{(x-\mu)^2}{2\sigma^2}\right)$$

In practice we almost never plug numbers into it directly. What matters is the simplicity hidden behind it: a Gaussian is completely described by just two numbers — its mean $\mu$ and variance $\sigma^2$. To model the noise of any real sensor, that is all we need.

Here $\sigma$ is the standard deviation and $\sigma^2$ the variance. A useful rule of thumb:

  • About 68% of all samples fall within $\pm 1\sigma$ of the mean
  • About 95% fall within $\pm 2\sigma$

There is a second reason Gaussians are so convenient: they combine with almost no effort. If you add independent random variables, their means and variances simply add up:

$$\mathbb{E}[x_1 + x_2] = \mathbb{E}[x_1] + \mathbb{E}[x_2] \qquad \operatorname{Var}(x_1 + x_2) = \operatorname{Var}(x_1) + \operatorname{Var}(x_2)$$

And scaling a variable by a constant $a$ scales its variance by $a^2$:

$$\operatorname{Var}(a\,x) = a^2\,\operatorname{Var}(x)$$
These few rules are essentially the entire algebra we will need. Every step of the Kalman Filter — predicting the state forward, fusing two sensors — turns out to be nothing more than these simple manipulations of means and variances.

4 · Variance and Sensor Quality

Every measurement is the true value plus some noise: $y = x + e$, where the noise $e \sim \mathcal{N}(0,\,\sigma^2)$ is a zero-mean Gaussian. The variance of that noise is exactly what tells us how much to trust the sensor.

  • A high-quality sensor has a small variance — its readings cluster tightly around the truth (narrow, tall bell curve).
  • A low-quality sensor has a large variance — its readings are spread out and unreliable (wide, flat bell curve).

Both sensors are centered on the same true value $\mu$, so on average they are both correct. But the narrow, tall curve is far more certain about any single reading. When we combine sensors, we should lean toward the one we trust more. This is the whole game.

5 · Data Fusion: Combining Noisy Sensor Measurements

Suppose two sensors measure the same quantity at the same moment:

$$y_1 = x + e_1,\quad e_1 \sim \mathcal{N}(0,\sigma_1^2) \qquad y_2 = x + e_2,\quad e_2 \sim \mathcal{N}(0,\sigma_2^2)$$

What single number is our best estimate of the truth $x$? Not the simple average — that would trust a bad sensor as much as a good one. Instead we use a weighted average, giving more weight to the sensor with the smaller variance. We define the gain $K$ and nudge the first reading toward the second:

$$K = \frac{\sigma_1^2}{\sigma_1^2 + \sigma_2^2}, \qquad \hat{x} = y_1 + K\,(y_2 - y_1)$$

The fused estimate has smaller variance than either sensor alone:

$$\operatorname{Var}(\hat{x}) = \sigma_1^2\,(1 - K)$$

The cleanest way to see why is to flip it over. Precisions add:

$$\frac{1}{\operatorname{Var}(\hat{x})} = \frac{1}{\sigma_1^2} + \frac{1}{\sigma_2^2}$$

Each sensor adds its information to the pile, so the combined precision is always larger than either sensor's — adding an independent measurement can never make you less certain.

Worked Example · Fusing two thermometers

Two thermometers read the same room. The cheap one says $y_1 = 10°$ with variance $\sigma_1^2 = 4$ (σ = 2°); the better one says $y_2 = 16°$ with variance $\sigma_2^2 = 1$ (σ = 1°).

Gain:

$$K = \frac{\sigma_1^2}{\sigma_1^2 + \sigma_2^2} = \frac{4}{4 + 1} = 0.8$$

Fused estimate — move 80% of the way from 10° toward 16°:

$$\hat{x} = 10 + 0.8\,(16 - 10) = 14.8°$$

Fused variance:

$$\operatorname{Var}(\hat{x}) = \sigma_1^2\,(1 - K) = 4\,(1 - 0.8) = 0.8$$

The estimate 14.8° leans toward the more precise thermometer, just as it should. The fused variance 0.8 is smaller than both inputs — even the good sensor's 1.0. Check: precisions add, $\tfrac14 + \tfrac11 = \tfrac54$, and $1/\tfrac54 = 0.8$. ✓

6 · The One-Dimensional Kalman Filter

Now we add time. A robot drives along a line, carrying two noisy sensors: an encoder that measures velocity, and a GPS that measures position directly.

Encoder only: the estimate drifts

With just the encoder, we use dead reckoning: start at a known position and keep adding the measured velocity, step after step.

$$x_{\text{pred}}[n] = \hat{x}[n-1] + v[n]\,\Delta t \qquad \sigma_{\text{pred}}^2[n] = \sigma^2[n-1] + \sigma_{\text{enc}}^2$$

The problem: every velocity reading carries noise, and we are summing those errors. They accumulate — the variance grows without bound and the estimate slowly drifts away from the truth.

GPS only: accurate but jumpy

The GPS measures position directly, so it never drifts — on average it is always right. But each reading is corrupted by noise:

$$x_{\text{meas}}[n] = x_{\text{true}}[n] + \omega[n], \qquad \omega[n] \sim \mathcal{N}(0,\,\sigma_{\text{gps}}^2)$$

Each reading could be far off. The encoder is smooth but drifts; the GPS is accurate on average but jumpy. The Kalman Filter combines them.

The Kalman Filter: predict then correct

Each timestep runs in two phases.

Predict (with the encoder, like dead reckoning):

$$x_{\text{pred}} = \hat{x}[n-1] + v[n]\,\Delta t \qquad \sigma_{\text{pred}}^2 = \sigma^2[n-1] + \sigma_{\text{enc}}^2$$

Correct (fuse prediction and GPS using the data-fusion formula):

$$K = \frac{\sigma_{\text{pred}}^2}{\sigma_{\text{pred}}^2 + \sigma_{\text{gps}}^2}$$
$$\hat{x}[n] = x_{\text{pred}} + K\,\big(x_{\text{meas}} - x_{\text{pred}}\big) \qquad \sigma^2[n] = \sigma_{\text{pred}}^2\,(1 - K)$$
Worked Example · One update with real numbers

Last estimate: $\hat{x} = 30$ m, $\sigma^2 = 4$. Encoder: $v = 5$ m/step, $\sigma_{\text{enc}}^2 = 1$. GPS reads $x_{\text{meas}} = 38$ m, $\sigma_{\text{gps}}^2 = 9$.

1. Predict:

$$x_{\text{pred}} = 30 + 5 = 35 \qquad \sigma_{\text{pred}}^2 = 4 + 1 = 5$$

2. Gain:

$$K = \frac{5}{5 + 9} = \frac{5}{14} \approx 0.36$$

3. Correct:

$$\hat{x} = 35 + 0.36\,(38 - 35) \approx 36.07 \qquad \sigma^2 = 5\,(1 - 0.36) \approx 3.21$$

The estimate moved 36% of the way from the prediction (35) toward the GPS (38) — because the prediction and GPS were comparably trustworthy. The variance dropped from 5 to 3.21: fusing made us more certain.

7 · The Covariance Matrix Explained

In the 1D filter, uncertainty was a single number — the variance $\sigma^2$. In the real world, we track several quantities at once. Individual variances tell you how much each variable spreads on its own, but miss something important: two variables can be correlated. The covariance matrix captures that joint information.

Covariance between two variables

$$\sigma_{x_1 x_2} = \frac{1}{N}\sum_{k=1}^{N}\bigl(x_1[k] - \mu_{x_1}\bigr)\bigl(x_2[k] - \mu_{x_2}\bigr)$$
  • $\sigma_{x_1 x_2} > 0$: positively correlated — when one is high, the other tends to be high too
  • $\sigma_{x_1 x_2} < 0$: negatively correlated — they move in opposite directions
  • $\sigma_{x_1 x_2} \approx 0$: independent

The covariance matrix

$$\boldsymbol{\Sigma} = \begin{bmatrix} \sigma_{x_1}^2 & \sigma_{x_1 x_2} \\ \sigma_{x_2 x_1} & \sigma_{x_2}^2 \end{bmatrix}$$
  • Diagonal: individual variances — how much each variable spreads on its own
  • Off-diagonal: covariance — correlation between the pair
  • Always symmetric: $\sigma_{x_1 x_2} = \sigma_{x_2 x_1}$

We write $\mathbf{x} \sim \mathcal{N}(\boldsymbol{\mu},\, \boldsymbol{\Sigma})$ to say the whole vector follows a multivariate Gaussian. This structure scales to any number of variables — the Kalman Filter handles them all with exactly the same equations.

How a covariance matrix transforms

If we build a new random vector by a linear transformation $\mathbf{y} = \mathbf{A}\mathbf{x} + \mathbf{b}$, the mean and covariance of $\mathbf{y}$ are:

$$\boldsymbol{\mu}_\mathbf{y} = \mathbf{A}\,\boldsymbol{\mu}_\mathbf{x} + \mathbf{b} \qquad \boldsymbol{\Sigma}_\mathbf{y} = \mathbf{A}\,\boldsymbol{\Sigma}_\mathbf{x}\,\mathbf{A}^{\!\top}$$

Compare with the scalar rule: scaling by $a$ gives variance $a^2\sigma^2$; transforming by $\mathbf{A}$ gives $\mathbf{A}\boldsymbol{\Sigma}\mathbf{A}^{\!\top}$ — the same structure, lifted to matrices. This is the rule the Kalman Filter uses in every prediction step.

8 · State-Space Representation

The Kalman Filter does two things every tick: it predicts where the system will be next, and then it corrects that prediction with a sensor reading. The prediction step requires a model of how the system evolves.

What is the state?

The state is the smallest set of variables you need right now to predict what happens next. For a robot moving along a line, knowing its position is not enough — you need position and velocity: $\mathbf{x} = [\,x,\, v\,]^\top$.

  • Robot on a line: $\mathbf{x} = [\,x,\, v\,]^\top$ (2 variables)
  • Drone in 3D: position + velocity in x, y, z = 6 variables; add orientation = 12 variables
  • Weather model: potentially millions of variables — same equations, bigger matrices

The discrete state-space model

$$\mathbf{x}_k = \mathbf{F}\,\mathbf{x}_{k-1} + \mathbf{G}\,\mathbf{u}_{k-1} \qquad \mathbf{y}_k = \mathbf{H}\,\mathbf{x}_k$$
  • F — transition matrix: steps the state forward one tick
  • G — input matrix: maps external control inputs (motor, force) into the state
  • H — measurement matrix: selects which parts of the state a sensor can see

Example: constant-velocity model

$$\begin{bmatrix} x \\ v \end{bmatrix}_k = \underbrace{\begin{bmatrix} 1 & \Delta t \\ 0 & 1 \end{bmatrix}}_{\mathbf{F}}\begin{bmatrix} x \\ v \end{bmatrix}_{k-1}$$

This $\mathbf{F}$ encodes one physical fact: in one tick, position changes by $v \cdot \Delta t$. A GPS that measures position but not velocity uses $\mathbf{H} = [\,1\ \ 0\,]$ — it keeps only the first component of the state.

9 · The Multivariate Linear Kalman Filter

We have everything we need. The only thing that changes from 1D is that scalars become matrices.

The state-space model with noise terms added:

$$\mathbf{x}_k = \mathbf{F}\,\mathbf{x}_{k-1} + \mathbf{G}\,\mathbf{u}_{k-1} + \mathbf{w}_k, \quad \mathbf{w}_k \sim \mathcal{N}(\mathbf{0},\,\mathbf{Q})$$
$$\mathbf{z}_k = \mathbf{H}\,\mathbf{x}_k + \mathbf{v}_k, \quad \mathbf{v}_k \sim \mathcal{N}(\mathbf{0},\,\mathbf{R})$$
  • $\mathbf{w}$: process noise — small random disturbances the model ignores; $\mathbf{Q}$ is its covariance (counterpart of $\sigma_{\text{enc}}^2$)
  • $\mathbf{v}$: measurement noise; $\mathbf{R}$ is its covariance (counterpart of $\sigma_{\text{gps}}^2$)

Phase 1 — Predict

$$\mathbf{x}_{\text{pred}} = \mathbf{F}\,\hat{\mathbf{x}} + \mathbf{G}\,\mathbf{u}$$
$$\boldsymbol{\Sigma}_{\text{pred}} = \mathbf{F}\,\boldsymbol{\Sigma}\,\mathbf{F}^{\!\top} + \mathbf{Q}$$

The covariance grows — we became less certain, because we moved without looking.

Phase 2 — Correct

A new measurement $\mathbf{z}$ arrives. Compute the Kalman gain:

$$\mathbf{K} = \boldsymbol{\Sigma}_{\text{pred}}\,\mathbf{H}^{\!\top}\Big(\mathbf{H}\,\boldsymbol{\Sigma}_{\text{pred}}\,\mathbf{H}^{\!\top} + \mathbf{R}\Big)^{-1}$$

The term $\mathbf{z} - \mathbf{H}\,\mathbf{x}_{\text{pred}}$ is the innovation — how surprised the sensor reading made us. Update state and covariance:

$$\hat{\mathbf{x}} = \mathbf{x}_{\text{pred}} + \mathbf{K}\,(\mathbf{z} - \mathbf{H}\,\mathbf{x}_{\text{pred}})$$
$$\boldsymbol{\Sigma} = (\mathbf{I} - \mathbf{K}\mathbf{H})\,\boldsymbol{\Sigma}_{\text{pred}}$$

Matrices for a 2D GPS tracker

State: $\mathbf{x} = [x,\, y,\, v_x,\, v_y]^\top$

$$\mathbf{F} = \begin{bmatrix} 1 & 0 & \Delta t & 0 \\ 0 & 1 & 0 & \Delta t \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{bmatrix} \qquad \mathbf{H} = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 0 & 0 \end{bmatrix} \qquad \mathbf{R} = \begin{bmatrix} \sigma_{\text{gps}}^2 & 0 \\ 0 & \sigma_{\text{gps}}^2 \end{bmatrix}$$
Worked Example · One full predict–correct cycle with matrices

Two-variable state (position and velocity), $\Delta t = 1$:

$$\hat{\mathbf{x}} = \begin{bmatrix} 30 \\ 5 \end{bmatrix},\quad \boldsymbol{\Sigma} = \begin{bmatrix} 4 & 0 \\ 0 & 1 \end{bmatrix},\quad \mathbf{F} = \begin{bmatrix} 1 & 1 \\ 0 & 1 \end{bmatrix},\quad \mathbf{Q} = \begin{bmatrix} 1 & 0 \\ 0 & 1 \end{bmatrix}$$

1. Predict:

$$\mathbf{x}_{\text{pred}} = \mathbf{F}\,\hat{\mathbf{x}} = \begin{bmatrix} 35 \\ 5 \end{bmatrix}$$
$$\boldsymbol{\Sigma}_{\text{pred}} = \mathbf{F}\,\boldsymbol{\Sigma}\,\mathbf{F}^{\!\top} + \mathbf{Q} = \begin{bmatrix} 6 & 1 \\ 1 & 2 \end{bmatrix}$$

2. Gain — $\mathbf{H} = [\,1\ \ 0\,]$, $R = 4$:

$$S = \mathbf{H}\,\boldsymbol{\Sigma}_{\text{pred}}\,\mathbf{H}^{\!\top} + R = 6 + 4 = 10$$
$$\mathbf{K} = \boldsymbol{\Sigma}_{\text{pred}}\,\mathbf{H}^{\!\top} S^{-1} = \begin{bmatrix} 0.6 \\ 0.1 \end{bmatrix}$$

3. Correct — GPS reading $z = 38$, innovation $= 38 - 35 = 3$:

$$\hat{\mathbf{x}} = \begin{bmatrix} 35 \\ 5 \end{bmatrix} + \begin{bmatrix} 0.6 \\ 0.1 \end{bmatrix}(3) = \begin{bmatrix} 36.8 \\ 5.3 \end{bmatrix}$$
$$\boldsymbol{\Sigma} = \begin{bmatrix} 2.4 & 0.4 \\ 0.4 & 1.9 \end{bmatrix}$$

Position variance fell from 6 to 2.4 as the GPS pinned it down. A non-zero off-diagonal (0.4) appeared — the filter now knows position and velocity errors are correlated. That single matrix update is the entire Kalman Filter, in numbers.

10 · Quick Reference — All Equations

Notation

  • F — state transition matrix (n×n)
  • H — observation matrix (m×n)
  • Q — process noise covariance (n×n)
  • R — measurement noise covariance (m×m)
  • x̂ — state estimate (n×1)
  • Σ — state covariance (n×n)
  • z — measurement vector (m×1)
  • K — Kalman gain (n×m)

Predict step

$$\mathbf{x}_{\text{pred}} = \mathbf{F}\,\hat{\mathbf{x}} + \mathbf{G}\,\mathbf{u}$$
$$\boldsymbol{\Sigma}_{\text{pred}} = \mathbf{F}\,\boldsymbol{\Sigma}\,\mathbf{F}^{\!\top} + \mathbf{Q}$$

Update step

$$\mathbf{K} = \boldsymbol{\Sigma}_{\text{pred}}\,\mathbf{H}^{\!\top}\bigl(\mathbf{H}\,\boldsymbol{\Sigma}_{\text{pred}}\,\mathbf{H}^{\!\top} + \mathbf{R}\bigr)^{-1}$$
$$\hat{\mathbf{x}} = \mathbf{x}_{\text{pred}} + \mathbf{K}\,\underbrace{(\mathbf{z} - \mathbf{H}\,\mathbf{x}_{\text{pred}})}_{\text{innovation}}$$
$$\boldsymbol{\Sigma} = \bigl(\mathbf{I} - \mathbf{K}\,\mathbf{H}\bigr)\,\boldsymbol{\Sigma}_{\text{pred}}$$

Tuning

  • Increase Q → filter trusts the model less, follows measurements more closely
  • Increase R → filter trusts measurements less, relies more on the model (smoother output)
  • Large initial P → filter starts uncertain, converges quickly as measurements arrive

11 · Python Implementation

The accompanying Jupyter notebook (kalman_filter.ipynb) contains runnable code for every concept in this guide. Here is the core KalmanFilter class:

import numpy as np

class KalmanFilter:
    """
    Linear Kalman Filter.

    Parameters
    ----------
    F  : state transition matrix       (n x n)
    H  : observation matrix            (m x n)
    Q  : process noise covariance      (n x n)
    R  : measurement noise covariance  (m x m)
    x0 : initial state estimate
    P0 : initial covariance estimate
    """

    def __init__(self, F, H, Q, R, x0, P0):
        self.F = np.array(F, dtype=float)
        self.H = np.array(H, dtype=float)
        self.Q = np.array(Q, dtype=float)
        self.R = np.array(R, dtype=float)
        self.x = np.array(x0, dtype=float).reshape(-1, 1)
        self.P = np.array(P0, dtype=float)

    def predict(self):
        self.x = self.F @ self.x
        self.P = self.F @ self.P @ self.F.T + self.Q
        return self.x.flatten().copy(), self.P.copy()

    def update(self, z):
        z = np.array(z, dtype=float).reshape(-1, 1)
        innovation = z - self.H @ self.x
        S = self.H @ self.P @ self.H.T + self.R
        K = self.P @ self.H.T @ np.linalg.inv(S)
        self.x = self.x + K @ innovation
        self.P = (np.eye(self.P.shape[0]) - K @ self.H) @ self.P
        return self.x.flatten().copy(), self.P.copy(), innovation.flatten()

    def step(self, z):
        """Predict then update in one call."""
        self.predict()
        return self.update(z)

Usage: 2D GPS tracking

dt = 1.0

F = [[1, 0, dt,  0],
     [0, 1,  0, dt],
     [0, 0,  1,  0],

for gps_x, gps_y in gps_readings:
