NGÀY 1 — CÀI UBUNTU + 10 LỆNH TERMINAL ĐẦU ĐỜI

Chọn cách cài Ubuntu · Làm quen prompt · 10 lệnh sống còn · man và --help

🎯 Mục đích ngày 1 — tại sao phải làm: Mọi JD robot (RTC, Phenikaa-X, Modern System) đều yêu cầu Ubuntu/Linux. Nhưng lý do thực dụng hơn: từ tuần 7 trở đi bạn sẽ cài ROS2 trên Ubuntu — nếu môi trường chưa sẵn, tuần đó biến thành tuần chiến đấu với cài đặt thay vì học. Hôm nay 4 tiếng này quyết định: bạn là người "có môi trường sẵn sàng" hay "người mất 3 ngày cho mỗi lần cài đặt". Lệnh terminal là chữ cái của ngôn ngữ bạn sẽ nói 23 tuần nữa.

Dùng WSL2 nếu bạn đang dùng Windows và máy ≥ 8GB RAM. Lệnh trong toàn bộ tài liệu này chạy nguyên vẹn trên WSL2 — không có gì khác biệt với Ubuntu thật. Cài nhanh nhất: mở PowerShell (Run as administrator) và gõ:

wsl --install -d Ubuntu-22.04

Sau đó khởi động lại máy, tạo tên người dùng + mật khẩu khi được hỏi. Kiểm tra bằng lệnh cat /etc/os-release — nếu thấy VERSION="22.04.x" là xong. (Ubuntu 22.04 = bản đi kèm ROS2 Humble, bản dùng trong JD Phenikaa-X.)

1.2 — Terminal là gì? Làm quen prompt

🔎 Ẩn dụ: Terminal = phố chính của thành phố Ubuntu

Windows bạn bấm chuột vào icon. Ubuntu cũng có chuột, nhưng mọi thứ quan trọng đều đi qua terminal: cài ROS2, chạy robot, đọc log — không có nút bấm nào cho những việc đó. Terminal là dòng chữ: bạn gõ lệnh, máy trả kết quả. Đọc prompt (dấu nhắc) như đọc biển báo đường:

danh@danh-pc:~$
  • danh — tên người dùng hiện tại.
  • @danh-pc — tên máy.
  • ~ — thư mục đang đứng (chỗ này đứng trong /home/danh).
  • $ — bạn đang là người thường. Nếu là # tức bạn đang là root (quyền tối cao) — nguy hiểm, thường xuyên gặp # là đang làm gì đó sai.
⚠️ Lỗi kinh điển người mới: "command not found"

Ví dụ gõ cd C:\Users\danh → bash: cd: C:\Users\danh: No such file or directory. Vì: (1) Windows dùng dấu gạch chéo ngược \, Linux dùng /; (2) Windows đường dẫn bắt đầu từ ổ đĩa C:, Linux từ gốc /. Ghi nhớ: ở Linux, mọi đường dẫn bắt đầu bằng /.

1.3 — 10 lệnh đầu đời (gõ tay từng lệnh, quan sát kết quả)

1

pwd — Print Working Directory (tôi đang đứng ở đâu?)

Lệnh đầu tiên ai cũng nên gõ khi mở terminal. Trả về đường dẫn tuyệt đối hiện tại.

danh@danh-pc:~$ pwd
/home/danh

Đường dẫn đọc từ phải sang: đang đứng trong thư mục danh, nằm trong home, nằm trong gốc /.

2

ls — List (trong thư mục này có gì?)

$ ls
Desktop  Documents  Downloads  ...
$ ls -la        # -l: chi tiết, -a: kể cả file ẩn (bắt đầu bằng dấu .)

ls -la là cặp lệnh bạn gõ nhiều nhất trong đời: thấy ngay quyền, chủ sở hữu, kích thước, ngày sửa. Cột đầu tiên (vd drwxr-xr-x) sẽ đọc kỹ ở ngày 2.

3

cd — Change Directory (đi đến thư mục khác)

$ cd /home/danh/Documents   # đi theo đường dẫn tuyệt đối
$ cd Documents               # đường dẫn tương đối (từ nơi đang đứng)
$ cd ..                      # lên một cấp
$ cd ~                       # về nhà (home)
$ cd -                       # về thư mục vừa đứng trước đó
4

mkdir — Make Directory (tạo thư mục)

$ mkdir dev                 # tạo thư mục dev
$ mkdir -p a/b/c             # -p: tạo luôn cả chuỗi cấp (b, c chưa tồn tại)

Quy ước của cả lộ trình: tất cả code để trong ~/dev — một chỗ duy nhất, dễ tìm, dễ đóng gói. Tạo ngay hôm nay: mkdir -p ~/dev.

5

touch — tạo file rỗng

$ touch hello.txt           # tạo file rỗng hello.txt
$ touch a.txt b.txt c.txt    # tạo nhiều file cùng lúc
6

cp — Copy (sao chép)

$ cp hello.txt hello2.txt   # copy file
$ cp -r dev dev_backup       # -r: copy cả thư mục (recursive)
7

mv — Move (di chuyển / đổi tên)

$ mv hello2.txt ~/dev/      # chuyển file vào thư mục dev
$ mv hello.txt greeting.txt  # đổi tên: dùng mv với 2 tên cùng chỗ
8

rm — Remove (xóa) — ⚠️ không có thùng rác

$ rm greeting.txt           # xóa file
$ rm -r dev_backup           # -r: xóa cả thư mục
$ rm -rf /somewhere          # ⚠️ -f: xóa không hỏi — TUYỆT ĐỐI CẨN THẬN
⚠️ Quy tắc sinh tử

rm -rf trên thư mục sai = mất dữ liệu vĩnh viễn, không có thùng rác, không có Ctrl+Z. Trước khi gõ rm: dừng 3 giây, đọc lại đường dẫn. Đặc biệt không bao giờ gõ rm -rf / hoặc rm -rf ~/.* khi chưa chắc chắn.

9

cat — đọc nội dung file ra màn hình

$ cat hello.txt

Ghi nhớ cặp: touch tạo file, cat đọc file, nano (lệnh 10) sửa file.

10

nano — trình soạn thảo trong terminal

$ nano hello.txt

Mở file để sửa. Gõ nội dung, rồi: Ctrl+O (lưu, Enter để xác nhận), Ctrl+X (thoát). Hai phím đó là đủ cho cả năm học — không cần học vim ở thời điểm này.

1.4 — Trợ giúp: man và --help (kỹ năng "tự học" sống còn)

🎯 Mục đích — vì sao phải biết: Không ai nhớ hết lệnh. Kỹ sư thật gõ man ls nhiều hơn là nhớ. Biết cách tra cứu = tự mình thoát được 50% lỗi mà không cần hỏi ai. JD nào cũng ghi "tự học" — đây là chứng cứ đầu tiên của bạn. 
$ man ls            # mở sách hướng dẫn của ls (phím q để thoát)
$ ls --help         # bản ngắn gọn hơn, in thẳng ra màn hình

NGÀY 2 — HỆ THỐNG FILE + QUYỀN + CÀI PHẦN MỀM

Cây thư mục Linux · rwx và chmod · sudo và PATH · apt — bộ não của mọi lỗi cài đặt

🎯 Mục đích ngày 2 — tại sao phải làm: Khoảng 60% lỗi người mới gặp trên Linux là 1 trong 3 thứ hôm nay: permission denied (quyền), command not found (PATH), lỗi khi cài gói (apt). Tuần 7 cài ROS2 — gõ một dòng apt install là đụng cả ba. Học 4 tiếng hôm nay = tự xử lý được những lỗi mà người học khác phải lên Google 30 phút mỗi lần. Ngoài ra: hiểu cây thư mục là biết "đồ vật để ở đâu" trong thành phố Ubuntu — /etc (cấu hình), /var/log (nhật ký hệ thống) sẽ là nơi bạn soi lỗi ROS2 hàng ngày từ tuần 7.

2.1 — Bản đồ thành phố: cây thư mục Linux

🔎 Ẩn dụ: thư mục gốc / là "trung tâm hành chính"

Linux không có ổ C:, D:. Tất cả bắt đầu từ / (gốc) và phân theo CHỨC NĂNG, không theo ổ đĩa. Nhớ vai trò 6 thư mục quan trọng nhất — đủ dùng cho cả lộ trình:

Thư mục Vai trò Bạn đụng khi nào
/ Gốc — đỉnh của mọi thứ Mọi đường dẫn tuyệt đối bắt đầu ở đây
/home/<user> Nhà của bạn (có ký hiệu ~) Code, tài liệu, mọi thứ cá nhân
/usr Phần mềm hệ thống + thư viện apt install đặt gói vào đây
/etc Cấu hình của hệ thống Sửa file config (vd /etc/os-release)
/var/log Nhật ký của hệ thống Soi lỗi: tail -f /var/log/syslog — thói quen sống còn với ROS2
/tmp File tạm — tự xóa khi khởi động lại Thử nghiệm vô thưởng vô phạt
📖 Ví dụ đọc đường dẫn

/var/log/syslog đọc từ trái: "trong gốc / → thư mục var → thư mục log → file syslog". Lệnh tail -n 20 /var/log/syslog in 20 dòng cuối — nơi mọi lỗi phần cứng/driver hiện ra.

2.2 — Quyền: vì sao "Permission denied"

🎯 Mục đích — vì sao phải hiểu sâu: Lỗi Permission denied là lỗi phổ biến #1 của người mới. Nhưng hơn thế: quyền là tường thành của robot thật — xe tự hành KHÔNG cho ROS2 node chạy với quyền root (một lỗi trong node = hacker điều khiển cả xe). JD Phenikaa-X yêu cầu "Security" mindset; JD nào cũng đánh giá kỹ sư biết quyền vì người đó không tạo ra lỗ hổng.

Mỗi file/thư mục có 9 bit quyền, chia 3 nhóm × 3 quyền. Đọc cột đầu của ls -l:

$ ls -l notes/nhat-ky-ngay1.md
-rw-r--r-- 1 danh danh 45 Feb  1 10:00 nhat-ky-ngay1.md
│└┬┘└┬┘└┬┘  └┬─┘└┬─┘
│ │   │   │   │   └── chủ sở hữu (danh) — nhóm (danh)
│ │   │   │   └──────── kích thước, ngày
│ └───┴───┴──────────── 3 nhóm: chủ (u) | nhóm (g) | người khác (o)
└────────────────────── d: thư mục, -: file thường, l: liên kết
Ký tự Quyền Ý nghĩa với file Ý nghĩa với thư mục
r Đọc (read, =4) Xem nội dung Liệt kê tên file (ls)
w Ghi (write, =2) Sửa nội dung Tạo/xóa file trong đó
x Chạy (execute, =1) Chạy như chương trình Đi VÀO thư mục (cd)

2.2.1 — chmod: đổi quyền bằng số (học cách này là đủ)

Mỗi nhóm có tổng điểm: r=4, w=2, x=1. Ví dụ 755 = chủ 7 (4+2+1: đọc, ghi, chạy) · nhóm 5 (4+1: đọc, chạy) · người khác 5. Cách ghi số này được dùng trong MỌI tài liệu cài đặt robot — biết đọc nó là biết đọc hướng dẫn.

$ chmod 755 script.sh        # script của bạn: chủ đầy đủ, người khác đọc+chạy
$ chmod 644 file.txt          # file dữ liệu: chủ ghi, người khác chỉ đọc
$ chmod +x script.sh          # chỉ thêm quyền chạy (nhanh, dùng nhiều)
⚠️ Lỗi kinh điển: script không chạy

$ ./script.sh → Permission denied. Vì file chưa có bit x (cột quyền hiện -rw-r--r--). Sửa: chmod +x script.sh rồi chạy lại. ./ nghĩa là "file ở ngay đây" — bắt buộc khi chạy script tại chỗ, vì Linux không tìm lệnh trong thư mục hiện tại (bảo mật).

2.3 — sudo: quyền tối cao có kiểm soát

sudo = "superuser do" — chạy 1 lệnh với quyền root, sau đó trả lại quyền thường. Đúng cách dùng: chỉ dùng khi lệnh đó cần (cài phần mềm, sửa file hệ thống).

$ sudo apt update            # ✅ đúng
⚡ Quy tắc vàng: đừng lạm dụng sudo

Nếu bạn gõ sudo cho lệnh không cần — bạn đang mất lớp bảo vệ. Với ROS2: không bao giờ chạy node với sudo (nút bấm dừng khẩn cấp của xe chạy với quyền thường — nếu node của bạn root, nó có thể chặn luôn nút dừng). Dấu hiệu nhận biết: prompt hiện $ là thường, # là root.

2.4 — PATH: vì sao "command not found"

🔎 Ẩn dụ: PATH = danh bạ điện thoại của hệ thống

Gõ ls — máy tính phải tìm chương trình ls ở ĐÂU? Nó tìm trong từng thư mục liệt kê trong biến PATH, theo thứ tự. Không tìm thấy → command not found. Xem danh bạ: echo $PATH. Thường gồm /usr/bin, /bin, ~/.local/bin... vì vậy python3, git chạy được từ bất kỳ đâu. Còn ./script.sh thì phải gõ rõ đường dẫn vì . 2.5 — apt: siêu thị phần mềm của Ubuntu

3 lệnh là đủ cho cả lộ trình:

4.4 — Branch: đường ray riêng cho thí nghiệm

🔎 Ẩn dụ: branch = làn đường riêng, merge = nhập làn

Đường cao tốc chính là main. Muốn thử điều mới (viết thuật toán, đổi cấu trúc) mà không làm kẹt xe cho người khác → rẽ vào làn riêng (branch). Làn riêng xong việc, hợp lưu về lại đường chính (merge). Trong đội robot: mỗi người một branch tính năng, không ai giẫm lên code của ai.

git branch thu-nghiem-markdown   # tạo nhánh mới (từ nơi đang đứng)

# — sửa file, commit như bình thường —
git checkout main              # quay về nhánh chính
git merge thu-nghiem-markdown  # hợp lưu thay đổi vào main

4.5 — Conflict: khi hai đường ray đâm nhau (sẽ gặp, phải biết xử)

🎯 Mục đích — vì sao phải học conflict ngay hôm nay: Conflict KHÔNG phải lỗi — nó là cơ chế bảo vệ của Git: "hai bản sửa cùng một chỗ, tao không biết giữ cái nào, mày quyết đi". Ai làm việc nhóm cũng gặp. Không biết xử = tê liệt; biết xử = chuyện thường. Hôm nay học trong môi trường giả lập an toàn, tuần 11+ khi làm việc thật với team thì chỉ là lặp lại.

Khi merge mà Git báo conflict, file chứa cả 2 phiên bản:

<<<<<<< HEAD
phiên bản trên nhánh main
=======
phiên bản trên nhánh kia
>>>>>>> thu-nghiem-markdown

Việc của bạn: chọn giữ cái nào (hoặc kết hợp cả hai), xóa 6 dòng đánh dấu <<<<<<< ... >>>>>>>, rồi commit lại:

git add conflicted.txt
git commit -m "Giai quyet conflict: giu phien ban ket hop"
⚠️ Quy tắc trước khi merge

Luôn git status để chắc working tree sạch; commit mọi thứ trên nhánh đang làm TRƯỚC khi checkout/merge — Git không cho merge khi còn thay đổi chưa commit (hoặc sẽ đòi stash). Quy tắc nằm lòng: dọn bàn trước khi chuyển làn.

🎯 Mục đích ngày 5 — tại sao phải làm: (1) JD Phenikaa-X ghi thẳng "Docker" vào yêu cầu; (2) từ tuần 7, bạn sẽ chạy ROS2 Humble TRONG container — không phá hệ thống, dọn dẹp dễ; (3) tư duy cốt lõi của ngành: "chạy được trên máy tôi" không có giá trị — phải "chạy được trên máy bất kỳ ai". Docker chính là công cụ biến câu đó thành hiện thực: đóng gói môi trường + code vào một "kiện hàng" (image), ai kéo về cũng chạy y hệt. Nhà tuyển dụng nào cũng thích người biết Docker vì họ đỡ tốn 2 tuần setup cho bạn.

5.1 — Image vs Container: bản vẽ và căn hộ

🔎 Ẩn dụ: image = bản vẽ căn hộ, container = căn hộ xây ra
Image (bản vẽ) Container (căn hộ)
Là gì Tệp đóng gói MÔI TRƯỜNG: OS + phần mềm + cấu hình Một "căn hộ" chạy từ bản vẽ — có thể nhiều căn từ 1 bản vẽ
Thay đổi Bất biến — không sửa trực tiếp Chạy được, sửa được — nhưng sửa xong nếu không lưu thì mất
Lệnh docker build (xây), docker pull (kéo bản vẽ về) docker run (dựng căn từ bản vẽ), docker rm (phá căn)

Người ta thường nói: "container là process (tiến trình) chạy trong phòng cách ly" — vì container KHÔNG có hệ điều hành riêng, nó dùng chung kernel với máy chủ nhưng cách ly hoàn toàn về file, mạng, tiến trình. Đó là vì sao container nhẹ (khởi động trong vài giây) so với máy ảo.

5.2 — Bốn lệnh sống còn

$ docker pull ubuntu:22.04        # kéo image Ubuntu 22.04 về máy (từ Docker Hub)
$ docker images                   # xem danh sách image đã có
$ docker run --rm -it ubuntu:22.04 bash
#   --rm: tự xóa container khi thoát (dọn dẹp tự động)
#   -it: mở terminal tương tác bên trong container
#   bash: lệnh khởi động — mở shell trong "căn hộ"
# → bạn đang ĐỨNG BÊN TRONG Ubuntu của container. Gõ thử:
#   cat /etc/os-release    → thấy Ubuntu 22.04
#   ls /                   → đây là hệ thống riêng, KHÔNG phải máy bạn
#   exit                   → thoát, container tự xóa (nhờ --rm)
⚠️ Lỗi "permission denied" khi chạy docker

Trên Ubuntu: chạy docker cần quyền root hoặc nhóm docker. Nếu gặp lỗi, chạy: sudo usermod -aG docker $USER rồi đăng xuất/đăng nhập lại (hoặc reboot WSL). Lệnh này thêm bạn vào nhóm docker — không cần sudo mỗi lần. Kiểm tra: docker run --rm hello-world.

5.3 — Làm việc bên trong: exec + mount

🎯 Mục đích — vì sao mount là kỹ năng bắt buộc: Container bị "cách ly": file tạo trong container --rm sẽ BIẾN MẤT khi thoát. Vậy làm sao chạy code của mình trong container? — mount: treo thư mục máy bạn vào bên trong container. Code nằm ở máy, container "nhìn thấy" qua cửa sổ mount, chỉnh sửa 2 chiều. Từ tuần 7: bạn sẽ mount thư mục ROS2 workspace của mình vào container — không có mount là không có gì. 
$ docker run -it --rm -v /home/danh/dev:/workspace ubuntu:22.04 bash
#   -v /home/danh/dev:/workspace: thư mục máy bạn trái → chỗ container phải
# Bên trong container:
#   cd /workspace && ls    → thấy chính các file của bạn!
#   touch test.txt         → tạo file trong container...
# exit
$ ls /home/danh/dev        # ...file vẫn còn ở máy! (2 chiều đồng bộ)

Còn docker exec: container đang chạy nền (không gắn terminal) → chui vào nó:

$ docker run -d --name ubuntu-nen ubuntu:22.04 sleep infinity
#   -d: chạy nền (background), sleep infinity: giữ container sống
$ docker ps                 # danh sách container đang chạy
$ docker exec -it ubuntu-nen bash   # chui vào container đang chạy
# ...làm gì thì làm...
$ exit
$ docker stop ubuntu-nen    # dừng
$ docker rm ubuntu-nen      # xóa

5.4 — Dockerfile: bản vẽ của CHÍNH BẠN

Thay vì chạy container rồi cài tay từng thứ (và quên mất đã cài gì), ghi mọi bước vào file Dockerfile — tái tạo được y hệt bất cứ máy nào. Đây là cách ROS2 images chính thức được xây.

# Dockerfile — môi trường C++ của lộ trình
FROM ubuntu:22.04

RUN apt-get update && apt-get install -y \
    build-essential gdb git cmake \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /workspace

CMD ["bash"]

4 chỉ thị đầu tiên (chỉ học 4 này là đủ cả năm): FROM (nền từ image nào), RUN (chạy lệnh khi XÂY image), WORKDIR (thư mục mặc định khi chạy), CMD (lệnh khởi động khi chạy container). Xây và chạy:

mkdir -p ~/dev/docker-cpp && cd ~/dev/docker-cpp
nano Dockerfile        # gõ nội dung trên
docker build -t cpp-dev .
#   -t cpp-dev: đặt tên image là cpp-dev
docker run --rm -it -v ~/dev:/workspace cpp-dev
# bên trong: g++ --version, git --version → thấy đủ công cụ
# kiểm tra mount: ls /workspace → thấy notes của bạn
⚡ Lời khuyên thực chiến về dung lượng

Mỗi RUN apt-get install tạo "lớp" (layer) trong image. Nhiều lớp = image to. Lệnh rm -rf /var/lib/apt/lists/* ngay sau install xóa bộ nhớ đệm gói — giảm kích thước đáng kể. Nhìn vào Dockerfile của ROS2 (github.com/ros/docker) để thấy kỹ thuật này dùng ở quy mô thật.

Trang lỗi là bệnh án: ghi LẠNH LÙNG nguyên nhân + cách sửa — không cảm xúc, không tự trách. 6 tháng nữa, trang lỗi là thứ bạn đọc trước khi phỏng vấn: nó chứa 20 câu chuyện "tôi gặp lỗi X, tự sửa bằng Y" — vàng cho phần "kể về một lỗi khó" (câu hỏi phỏng vấn gần như chắc chắn có).

⚡ 2>/dev/null là gì?

Mỗi lệnh có 2 ngõ ra: 1 = kết quả thường, 2 = thông báo lỗi. 2>/dev/null = "bỏ thông báo lỗi vào thùng rác" (vì /dev/null là hố đen của Linux). Dùng khi bạn BIẾT lỗi nhỏ vô hại đang xảy ra và không muốn màn hình rác. Đọc kỹ: đây là "nuốt lỗi có chủ đích" — KHÔNG dùng để che lỗi mình không hiểu.

Ô9 Một image Docker gồm nhiều "lớp" (layer). Khi nào lớp mới được thêm và vì sao nên gộp lệnh apt?
