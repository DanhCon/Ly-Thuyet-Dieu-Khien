PHẦN 1 — TRẮC NGHIỆM TÌNH HUỐNG LÝ THUYẾT

10 câu trắc nghiệm kiểm tra tư duy môi trường & công cụ (2.5 điểm/câu)

Câu 1.1: Tại sao các công ty phát triển Xe tự hành (Phenikaa-X, Avride, RTC) bắt buộc sử dụng Ubuntu Linux thay vì Windows làm môi trường phát triển chính?

  • A. Vì Ubuntu Linux là hệ điều hành miễn phí nên tiết kiệm chi phí bản quyền.
  • B. Vì Ubuntu Linux cung cấp tính năng Real-time Determinism tốt hơn, không có rác hệ thống gây giật lag ngẫu nhiên và là môi trường duy nhất hỗ trợ ROS2 nguyên bản.
  • C. Vì Windows không thể cài đặt được ngôn ngữ C++ và Python.
  • D. Vì các công tắc phần cứng của robot chỉ nhận diện được dòng lệnh Terminal của Linux.

Câu 1.2: Khi thực thi lệnh ls -l, bạn nhìn thấy dòng -rwxr-xr-- 1 danh danh ... script.sh. Quyền thực thi (x) đang được trao cho những ai?

  • A. Chỉ trao cho Chủ sở hữu (User) và Nhóm (Group). Người khác (Others) không có quyền chạy.
  • B. Trao cho tất cả mọi người (User, Group, Others).
  • C. Chỉ trao cho quyền Root.
  • D. Chỉ trao cho Người khác (Others), Chủ sở hữu bị cấm.

Câu 1.3: Sự khác biệt căn bản giữa sudo apt update và sudo apt upgrade là gì?

  • A. update dùng cho C++, upgrade dùng cho Python.
  • B. update tải danh sách thông tin phiên bản gói mới nhất về máy; upgrade mới thực sự tải và cài đặt bản cập nhật phần mềm.
  • C. update chỉ cập nhật hệ thống Linux, upgrade cập nhật phần cứng.
  • D. Hai lệnh này hoàn toàn giống hệt nhau về tác dụng.

Câu 1.4: Khái niệm biến môi trường PATH trong Linux đóng vai trò gì?

  • A. Lưu trữ đường dẫn đến thư mục chứa file hình ảnh của Robot.
  • B. Lưu danh sách các thư mục mà Terminal sẽ tìm kiếm chương trình thực thi khi bạn gõ tên lệnh.
  • C. Quy định đường đi cho thuật toán rẽ nhánh A* / Dijkstra.
  • D. Quản lý dung lượng bộ nhớ RAM của Docker Container.

Câu 1.5: Khi làm việc với Git, lệnh git commit -m "Message" làm nhiệm vụ gì?

  • A. Gửi ngay lập tức code lên trang web GitHub.com.
  • B. Lưu lại trạng thái của các thay đổi đã được add (Staging Area) vào lịch sử Repository cục bộ (Local Repo) kèm lời nhắn.
  • C. Đổi tên branch hiện tại thành "Message".
  • D. Xóa các file thừa trong dự án.

Câu 1.6: Khi hai kỹ sư cùng sửa chung một dòng code trong file robot_params.yaml trên hai branch khác nhau rồi merge lại, Git sẽ xử lý thế nào?

  • A. Tự động lấy file của người push sau và đè lên người trước.
  • B. Tự động xóa cả hai file để đảm bảo an toàn.
  • C. Báo lỗi Merge Conflict và yêu cầu kỹ sư tự mở file ra đối soát và quyết định giữ lại dòng code nào.
  • D. Tự động gọi trí tuệ nhân tạo để sửa code.

Câu 1.7: Phân biệt sự khác nhau giữa Docker Image và Docker Container?

  • A. Image là container đang chạy, Container là bản lưu trên ổ đĩa.
  • B. Image là "bản thiết kế/khuôn mẫu" tĩnh read-only; Container là một "thể hiện (Instance)" đang thực thi được tạo ra từ bản thiết kế đó.
  • C. Image dùng cho Linux, Container dùng cho Windows.
  • D. Image là file video mô phỏng, Container là code C++.

Câu 1.8: Cờ -v ~/dev:/workspace trong lệnh docker run có ý nghĩa gì?

  • A. Đổi tên thư mục ~/dev thành workspace.
  • B. Gắn (Mount) thư mục ~/dev trên máy thật (Host) vào thư mục /workspace bên trong Container, giúp dữ liệu đồng bộ 2 chiều tức thì.
  • C. Xóa thư mục /workspace bên trong container.
  • D. Giới hạn dung lượng RAM của workspace là 1GB.

Câu 1.9: Lệnh tail -f /var/log/syslog dùng để làm gì trong công việc bảo trì robot?

  • A. In ra toàn bộ nội dung file log từ đầu đến cuối rồi dừng.
  • B. Theo dõi liên tục theo thời gian thực các dòng thông báo lỗi/sự kiện phần cứng mới nhất nảy ra trong hệ thống.
  • C. Xóa toàn bộ file log để giải phóng ổ cứng.
  • D. Đổi tên file log thành syslog.bak.

Câu 1.10: Tại sao khi viết script Bash, người ta luôn đặt dòng #!/bin/bash ở dòng đầu tiên (Shebang)?

  • A. Để ghi chú đây là file bản quyền của tác giả.
  • B. Để báo cho trình thông dịch của hệ điều hành biết chính xác chương trình nào (ở đây là Bash Shell) sẽ chịu trách nhiệm biên dịch/thực thi file script này.
  • C. Để script tự động cấp quyền chmod +x.
  • D. Để chương trình tự động đẩy lên GitHub.

PHẦN 3 — KỊCH BẢN GỠ LỖI THỰC TẾ (DEBUGGING SCENARIOS)

Giải quyết các sự cố môi trường kinh điển mà kỹ sư Robot gặp phải (6.25 điểm/kịch bản)

🐛

Kịch bản 1: Lỗi "Permission denied" khi nạp code xuống STM32 / Arduino

Mô tả sự cố: Kỹ sư Nam kết nối mạch STM32/Arduino qua cổng USB vào Ubuntu. Khi chạy lệnh nạp code st-flash write build/firmware.bin 0x08000000 hoặc mở cổng Serial cat /dev/ttyUSB0, màn hình báo lỗi:

cat: /dev/ttyUSB0: Permission denied

Yêu cầu:

  1. Giải thích nguyên nhân vì sao User hiện tại lại bị báo lỗi Permission denied với thiết bị phần cứng /dev/ttyUSB0.
  2. Đưa ra 2 cách khắc phục (Cách tạm thời ngắn hạn và Cách khắc phục triệt để dài hạn chuẩn kỹ sư Linux bằng usermod / dialout group).
🐛

Kịch bản 2: Lỗi "command not found: ros2" sau khi mở Terminal mới

Mô tả sự cố: Kỹ sư An vừa cài xong ROS2 Humble theo tài liệu. Ở terminal vừa cài xong, lệnh ros2 topic list chạy rất mượt. Tuy nhiên, khi An mở một cửa sổ Terminal mới (hoặc khởi động lại máy) và gõ ros2 topic list, màn hình báo lỗi:

ros2: command not found

Yêu cầu:

  1. Giải thích nguyên nhân tại sao Terminal mới lại không tìm thấy lệnh ros2.
  2. Chỉ ra chính xác file cấu hình nào trong thư mục ~ cần được chỉnh sửa và gõ câu lệnh Bash nào để từ nay về sau mọi Terminal mở ra đều tự động nhận diện lệnh ros2.
🐛

Kịch bản 3: Xử lý Git Merge Conflict trên file cấu hình Robot

Mô tả sự cố: Bạn vừa gõ git merge feature/ekf-filter vào branch main thì Git chặn lại và thông báo:

AUTO-MERGING config/robot_params.yaml
CONFLICT (content): Merge conflict in config/robot_params.yaml
Automatic merge failed; fix conflicts and then commit the result.

Mở file config/robot_params.yaml ra, bạn thấy nội dung như sau:

<<<<<<< HEAD
max_speed: 2.0 # m/s (Cấu hình cu trên main)
=======
max_speed: 3.5 # m/s (Cấu hình moi tren feature branch)
>>>>>>> feature/ekf-filter

Yêu cầu: Trình bày từng bước (Step-by-step commands) để bạn chọn mức tốc độ tối đa là 3.5 m/s, xóa bỏ các ký hiệu xung đột Git và hoàn tất việc merge sạch đàng hoàng.

🐛

Kịch bản 4: Docker Container không thấy file code vừa sửa trên VS Code

Mô tả sự cố: Kỹ sư Bình chạy Docker Container chứa ROS2 bằng lệnh: docker run -it ros:humble bash. Bình mở VS Code trên máy thật sửa file main.cpp trong thư mục ~/dev/ros_ws, nhưng khi vào trong container gõ ls /workspace thì không thấy file đâu.

Yêu cầu: Giải thích lý do Bình thiếu cờ (flag) quan trọng nào khi chạy docker run và viết lại câu lệnh docker run đúng chuẩn để gắn thư mục máy thật vào container.

PHẦN 5 — ĐÁP ÁN CHI TIẾT & THANG ĐIỂM TỰ ĐÁNH GIÁ

Đối chiếu câu trả lời để chấm điểm năng lực Tuần 1 của bạn

🔑 ĐÁP ÁN PHẦN 1: TRẮC NGHIỆM LÝ THUYẾT

1.1: B — Ubuntu Linux có tính xác định thời gian tốt, không bị Garbage Collector ngắt quãng ngẫu nhiên và là chuẩn nguyên bản của ROS2.

1.2: A — -rwxr-xr--: Owner có rwx (đọc/ghi/chạy), Group có r-x (đọc/chạy), Others chỉ có r-- (chỉ đọc, không có x).

1.3: B — update tải menu/danh sách gói; upgrade mới thực sự tải và nâng cấp phần mềm.

1.4: B — PATH lưu danh sách thư mục chứa các file thực thi mà terminal sẽ tìm kiếm.

1.5: B — git commit chốt trạng thái Staging vào lịch sử Git CỤC BỘ trên máy, chưa push lên mạng.

1.6: C — Git báo Merge Conflict và đánh dấu file để con người tự đối soát chỉnh sửa.

1.7: B — Image là bản vẽ/khuôn mẫu tĩnh; Container là căn hộ đang sống/thực thi được tạo từ bản vẽ đó.

1.8: B — Cờ -v dùng để Mount thư mục máy host vào container đồng bộ 2 chiều.

1.9: B — tail -f theo dõi liên tục dòng dữ liệu log mới nhất theo thời gian thực.

1.10: B — Shebang #!/bin/bash chỉ định trình thông dịch Bash sẽ thực thi script.

🔑 ĐÁP ÁN PHẦN 2: ĐỌC HIỂU LỆNH

2.1: Màn hình in ra: /home/danh/dev. Lý do: Lệnh cd ~/dev đã chuyển thư mục hiện tại thành ~/dev. Các lệnh sau mkdir và touch thao tác với đường dẫn tương đối test_dir/... nên vị trí đứng của terminal vẫn là ~/dev.

2.2: 600 = rw-------. Chỉ có duy nhất Chủ sở hữu (Owner) có quyền đọc và sửa file. Tất cả mọi người khác (Group & Others) bị cấm hoàn toàn.

2.3: Màn hình báo lỗi: ls: cannot access 'pid.cpp': No such file or directory. Vì file pid.cpp mới được tạo và commit trên branch feature/pid-controller, khi chuyển về branch main, Git tự động dọn dẹp làm sạch không gian làm việc tương ứng với trạng thái của main.

2.4: Có hiển thị trong docker ps vì container đang chạy ngầm với cờ -d và lệnh sleep 1000. Muốn chui vào trong container tương tác gõ lệnh: docker exec -it my_ros_container bash.

2.5: Lệnh cp -r tạo ra một bản sao (Copy) mới độc lập của thư mục notes sang notes_backup (thư mục cũ vẫn còn). Lệnh mv thực hiện Đổi tên hoặc Di chuyển (Move) thư mục gốc sang tên mới (thư mục gốc notes không còn nữa).

🔑 ĐÁP ÁN PHẦN 3: KỊCH BẢN GỠ LỖI

Kịch bản 1 (STM32 USB Permission):

1. Nguyên nhân: Cổng thiết bị USB Serial /dev/ttyUSB0 thuộc sở hữu của nhóm dialout hoặc root. User thường không nằm trong nhóm dialout nên bị từ chối truy cập.

2. Khắc phục chuẩn dài hạn: Thêm user hiện tại vào nhóm dialout bằng lệnh: sudo usermod -aG dialout $USER sau đó đăng xuất khởi động lại máy hoặc gõ newgrp dialout.

Kịch bản 2 (Missing ROS2 Command):

1. Nguyên nhân: Các biến môi trường và đường dẫn thi hành của ROS2 nằm trong file setup script /opt/ros/humble/setup.bash chưa được load vào môi trường Shell của Terminal mới.

2. Khắc phục triệt để: Gõ lệnh thêm dòng source vào ~/.bashrc:

echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
source ~/.bashrc

Kịch bản 3 (Git Merge Conflict):

Các bước xử lý chuẩn:

  1. Mở file config/robot_params.yaml bằng trình biên soạn (nano/VS Code).
  2. Sửa nội dung file thành duy nhất 1 dòng chuẩn mong muốn: max_speed: 3.5 và xóa các dòng đánh dấu <<<<<<<, =======, >>>>>>>.
  3. Lưu file lại và gõ lệnh: git add config/robot_params.yaml.
  4. Hoàn tất merge bằng lệnh: git commit -m "Fix merge conflict: set max_speed to 3.5".

Kịch bản 4 (Docker Volume Mount):

1. Nguyên nhân: Bình chưa truyền cờ -v (Volume Mount) để liên kết thư mục trên máy host với thư mục bên trong container.

2. Câu lệnh chuẩn đúng:

docker run -it -v ~/dev/ros_ws:/workspace ros:humble bash

🔑 ĐÁP ÁN PHẦN 4: HANDS-ON LABS

Thử thách 1 (Script Bash):

#!/bin/bash
# Code chuẩn cho backup_logs.sh
BACKUP_DIR="$HOME/dev/robot_backups"
SOURCE_DIR="$HOME/dev/notes"
TIMESTAMP=$(date +%Y_%m_%d_%H%M%S)

mkdir -p "$BACKUP_DIR"
tar -czf "$BACKUP_DIR/backup_$TIMESTAMP.tar.gz" -C "$SOURCE_DIR" .
echo "Sao luu thanh cong vao: $BACKUP_DIR/backup_$TIMESTAMP.tar.gz"

Thử thách 2 (Dockerfile chuẩn):

# Dockerfile
FROM ubuntu:22.04

# Tránh hỏi timezone khi install
ENV DEBIAN_FRONTEND=noninteractive

RUN apt update && apt install -y \
    build-essential \
    cmake \
    git \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

CMD ["g++", "--version"]

Lệnh Terminal để build và run:

cd ~/dev/my_cpp_env
docker build -t my_cpp_robot:v1 .
docker run --rm my_cpp_robot:v1
