Thứ 2: Math Derivation Drill (Tự Giải Tay Mô Hình)

Mục tiêu: Rèn trực giác Vật lý & Đại số tuyến tính từ bản chất

📝 Đề Bài: Hệ Đệm Từ (Magnetic Levitation System — MagLev)

Một hòn bi thép khối lượng $m$ được nâng bởi một nam châm điện thẳng đứng. Vị trí $x$ đo từ nam châm điện xuống bi ($x > 0$). Dòng điện cuộn dây là $i(t)$.

┌──────────────────┐ │ Nam Châm Điện │ └────────┬─────────┘ │ Dòng điện i(t) ▼ ┌──────────────────┐ │ Lực hút F_mag(x,i)│ └────────┬─────────┘ │ ▼ x (vị trí bi, x > 0) ● Bi thép khối lượng m │ ▼ Trọng lực mg

Phương trình chuyển động phi tuyến của bi thép:

$$m \ddot{x} = m g - F_{\text{mag}}(x, i) \quad \text{với } F_{\text{mag}}(x, i) = k \frac{i^2}{x^2} \quad (k > 0)$$

Nhiệm vụ của bạn:

  1. Tìm dòng điện cân bằng $i_0$ để giữ hòn bi đứng yên tại vị trí mong muốn $x_0$.
  2. Tuyến tính hóa $F_{\text{mag}}(x, i)$ quanh điểm cân bằng $(x_0, i_0)$ bằng khai triển Taylor bậc 1.
  3. Đặt các độ lệch trạng thái: $x_1 = \Delta x = x - x_0$, $x_2 = \Delta \dot{x} = \dot{x}$, và đầu vào $u = \Delta i = i - i_0$.
  4. Lập ma trận State Space $A, B$ của hệ tuyến tính hóa $\dot{\mathbf{x}} = A \mathbf{x} + B u$.
  5. Tính trị riêng của ma trận $A$. Hệ cân bằng MagLev này ban đầu (hệ mở) là ổn định hay bất ổn định? Giải thích ý nghĩa vật lý.

✅ Lời Giải Bài Tập Thứ 2:

1. Điểm cân bằng: Đứng yên $\implies \ddot{x} = 0 \implies mg - k \frac{i_0^2}{x_0^2} = 0 \implies \mathbf{i_0 = x_0 \sqrt{\frac{mg}{k}}}$.

2. Tuyến tính hóa Taylor bậc 1 cho $F_{\text{mag}}(x, i) = k i^2 x^{-2}$ quanh $(x_0, i_0)$:

$$\frac{\partial F}{\partial x} = -2k \frac{i_0^2}{x_0^3} = -2 \frac{mg}{x_0}, \quad \frac{\partial F}{\partial i} = 2k \frac{i_0}{x_0^2} = 2 \frac{\sqrt{k mg}}{x_0}$$ $$F_{\text{mag}}(x, i) \approx F_{\text{mag}}(x_0, i_0) + \left(-2\frac{mg}{x_0}\right)\Delta x + \left(2\frac{\sqrt{kmg}}{x_0}\right)\Delta i$$

3. Phương trình chuyển động tuyến tính hóa:

$$m \Delta \ddot{x} = mg - \left[ mg - 2\frac{mg}{x_0}\Delta x + 2\frac{\sqrt{kmg}}{x_0}\Delta i \right] = 2\frac{mg}{x_0}\Delta x - 2\frac{\sqrt{kmg}}{x_0}\Delta i$$ $$\Delta \ddot{x} = \frac{2g}{x_0} \Delta x - \frac{2}{x_0}\sqrt{\frac{kg}{m}} \Delta i$$

4. Ma trận State Space $A, B$:

$$A = \begin{bmatrix} 0 & 1 \\ \frac{2g}{x_0} & 0 \end{bmatrix}, \quad B = \begin{bmatrix} 0 \\ -\frac{2}{x_0}\sqrt{\frac{kg}{m}} \end{bmatrix}$$

5. Trị riêng của $A$: $\det(\lambda I - A) = \lambda^2 - \frac{2g}{x_0} = 0 \implies \lambda_{1,2} = \pm \sqrt{\frac{2g}{x_0}}$.

Có 1 trị riêng dương $\lambda_1 = +\sqrt{\frac{2g}{x_0}} > 0 \implies$ **Hệ mở MagLev BẤT ỔN ĐỊNH mạnh!** (Ý nghĩa vật lý: Nếu bi nhích xuống dưới một chút, lực hút giảm $\rightarrow$ bi rơi luôn; nếu bi nhích lên trên một chút, lực hút tăng mạnh $\rightarrow$ bi bị dính chặt vào nam châm. Bắt buộc phải có bộ điều khiển LQR/PID hồi tiếp âm để giữ bi!).

Thứ 3: From-Scratch Coding Drill (C++ Thuần)

Mục tiêu: Code bộ tích phân số Runge-Kutta 4 (RK4) không dùng thư viện ngoài

💻 Đề Bài: Tự viết RK4 Simulator cho Con lắc Đơn trong C++

Phương trình con lắc đơn có ma sát nhớt:

$$\ddot{\theta} = -\frac{g}{l} \sin\theta - \frac{b}{m l^2} \dot{\theta} + \frac{1}{m l^2} u(t)$$

Cho $m = 0.5\text{ kg}$, $l = 0.4\text{ m}$, $g = 9.81\text{ m/s}^2$, $b = 0.05\text{ N}\cdot\text{s}\cdot\text{m}$.

Nhiệm vụ của bạn:

  1. Viết class/struct C++ `PendulumState` đại diện cho $[\theta, \omega]$.
  2. Viết hàm `rk4_step(state, dt, u)` tự tính 4 hệ số $k_1, k_2, k_3, k_4$ bằng số mà không dùng bất kỳ thư viện ngoài nào ngoại trừ `` và ``.
  3. Mô phỏng 5 giây chuyển động khi thả con lắc từ góc $\theta_0 = 45^\circ$ ($0.785\text{ rad}$) với $u = 0$. In tọa độ từng bước $50\text{ms}$ ra console.

✅ Lời Giải Code C++ Thuần RK4 Simulator:

#include <iostream>
#include <cmath>
#include <iomanip>

struct State {
    double theta; // Góc (rad)
    double omega; // Tốc độ góc (rad/s)
};

// Thông số vật lý
const double m = 0.5;
const double l = 0.4;
const double g = 9.81;
const double b = 0.05;

// Hàm đạo hàm trạng thái dx/dt = f(x, u)
State dynamics(const State& s, double u) {
    State ds;
    ds.theta = s.omega;
    ds.omega = -(g / l) * std::sin(s.theta) - (b / (m * l * l)) * s.omega + (1.0 / (m * l * l)) * u;
    return ds;
}

// Tích phân số Runge-Kutta 4th Order (RK4)
State rk4_step(const State& s, double dt, double u) {
    State k1 = dynamics(s, u);
    
    State s_k2 = { s.theta + 0.5 * dt * k1.theta, s.omega + 0.5 * dt * k1.omega };
    State k2 = dynamics(s_k2, u);
    
    State s_k3 = { s.theta + 0.5 * dt * k2.theta, s.omega + 0.5 * dt * k2.omega };
    State k3 = dynamics(s_k3, u);
    
    State s_k4 = { s.theta + dt * k3.theta, s.omega + dt * k3.omega };
    State k4 = dynamics(s_k4, u);
    
    State next_s;
    next_s.theta = s.theta + (dt / 6.0) * (k1.theta + 2.0*k2.theta + 2.0*k3.theta + k4.theta);
    next_s.omega = s.omega + (dt / 6.0) * (k1.omega + 2.0*k2.omega + 2.0*k3.omega + k4.omega);
    return next_s;
}

int main() {
    State s = { 45.0 * M_PI / 180.0, 0.0 }; // 45 độ
    double dt = 0.01; // 10ms
    double total_time = 5.0;
    
    std::cout << std::fixed << std::setprecision(4);
    std::cout << "Time(s)\tTheta(deg)\tOmega(rad/s)\n";
    std::cout << "------------------------------------\n";
    
    for (double t = 0; t <= total_time; t += dt) {
        if (std::fmod(t, 0.5) < dt) { // In mỗi 0.5s
            std::cout << t << "\t" << s.theta * 180.0 / M_PI << "\t\t" << s.omega << "\n";
        }
        s = rk4_step(s, dt, 0.0); // u = 0
    }
    return 0;
}

Thứ 4: Fault Injection & Troubleshooting Drill

Mục tiêu: Tiêm lỗi vật lý vào simulator & phân tích nguyên nhân hư hỏng

🔍 Đề Bài: Chẩn đoán 3 Hiện tượng Lỗi Vật lý trong Mô Phỏng LQR

Bạn có một simulator LQR cho Robot 2 Bánh Tự Cân Bằng đang chạy ổn định mượt mà. Lần lượt tiêm 3 loại lỗi vào code và quan sát đồ thị đáp ứng $\theta(t)$ và $u(t)$:

  • Sự cố A: Thêm nhiễu trắng Gauss $\mathcal{N}(0, \sigma^2)$ với $\sigma = 0.05\text{ rad}$ vào tín hiệu cảm biến góc $\theta$.
  • Sự cố B: Làm trễ tín hiệu điều khiển $2$ chu kỳ lấy mẫu ($u[k] = -K x[k-2]$ tại $T_s = 10\text{ms}$).
  • Sự cố C: Áp dụng bão hòa điện áp nghiêm trọng $|u| \le 3\text{V}$ (trong khi LQR yêu cầu đỉnh $12\text{V}$).

Nhiệm vụ của bạn: Hãy nối mỗi **Hiện tượng Đồ thị** dưới đây với **Nguyên nhân Sự cố** tương ứng và giải thích cơ chế vật lý:

  1. Đồ thị lực $u(t)$ bị xé rách, dao động với tần số cực cao, động cơ nóng xả rác nhiễu nhưng góc $\theta$ vẫn xấp xỉ đứng yên.
  2. Robot bị dao động điều hòa tự do với tần số cố định $\sim 2-3\text{Hz}$ và biên độ tăng dần cho đến khi ngã hẳn.
  3. Robot chịu được nhiễu nhẹ, nhưng khi bị đẩy nhẹ một cái là ngã ngay lập tức, lực $u(t)$ bị bẹt phẳng ở mép $\pm 3\text{V}$.

✅ Kết Quả Chẩn Đoán Sự Cố:

  • Hiện tượng a $\rightarrow$ Sự cố A (Nhiễu Cảm Biến): Do Gain $K$ nhân trực tiếp với góc $\theta$ bị nhiễu. Nhất là thành phần tốc độ góc $\dot{\theta}$ (hoặc khâu D trong PID) khuếch đại nhiễu tần số cao lên cực đại, làm tín hiệu PWM $u(t)$ giật liên tục giữa các đỉnh, gây nóng động cơ và cháy cầu H. Khắc phục: Dùng Complementary Filter hoặc Kalman Filter để lọc $\theta$.
  • Hiện tượng b $\rightarrow$ Sự cố B (Trễ Pha do Delay): Trễ $2 T_s = 20\text{ms}$ làm xoay pha của đáp ứng vòng kín đi một góc $\Delta \phi = -\omega \cdot T_{\text{delay}}$. Khi Phase Margin bị sụt giảm về $0^\circ$, hệ đi vào điểm tự do phân kỳ Nyquist quanh điểm $-1$. Khắc phục: Tăng tần số lấy mẫu (giảm $T_s$) hoặc dùng Smith Predictor.
  • Hiện tượng c $\rightarrow$ Sự cố C (Bão Hòa Lực Actuator): Khi bão hòa ở $3\text{V}$, động cơ không đủ mô-men để tạo gia tốc đẩy bánh xe vượt qua góc đổ của trọng lực. Vòng lặp phản hồi bị bẻ gãy (Open-loop) tại ngưỡng $3\text{V}$. Khắc phục: Tăng $R$ trong LQR để hạn chế LQR đòi hỏi lực quá lớn, hoặc dùng động cơ mô-men lớn hơn.

Thứ 5: Embedded C++ Optimization Drill

Mục tiêu: Viết C++ Class chuẩn Nhúng Real-Time (Zero-Allocation)

⚙️ Đề Bài: Thiết kế Class `PIDController` C++17 Zero-Allocation

Hãy viết một Class C++ `PIDController` dành riêng cho hệ thống nhúng STM32/ESP32 đáp ứng các tiêu chuẩn nghiêm ngặt của ngành Automotive/Robotics:

  1. Zero Heap Allocation: Không dùng `new`, `malloc`, `std::vector`, `std::shared_ptr`. Tất cả bộ nhớ nằm trên Stack/Data segment.
  2. Anti-Windup: Tích hợp Clamp cho khâu tích phân (Integral Clamping) khi đầu ra bị bão hòa $u_{\max}$.
  3. Derivative Filter: Áp dụng lọc thông thấp (Low-Pass Filter) cho khâu đạo hàm với hằng số $T_f$.
  4. Sử dụng `constexpr`, `noexcept`, và đóng gói trong `namespace control`.

✅ Lời Giải Code C++17 Embedded Zero-Allocation:

#include <iostream>
#include <algorithm>

namespace control {

class PIDController {
public:
    struct Config {
        float kp{0.0f};
        float ki{0.0f};
        float kd{0.0f};
        float tf{0.02f};    // Hằng số lọc D-term (s)
        float u_min{-12.0f}; // Bão hòa tối thiểu (V)
        float u_max{12.0f};  // Bão hòa tối đa (V)
    };

    explicit PIDController(const Config& config) noexcept : cfg_(config) {}

    // Reset trạng thái (dùng khi bắt đầu chạy)
    void reset() noexcept {
        integrator_ = 0.0f;
        prev_error_ = 0.0f;
        d_filtered_ = 0.0f;
    }

    // Vòng lặp tính toán Real-time (Zero Heap Allocation!)
    float update(float setpoint, float measurement, float dt) noexcept {
        if (dt <= 0.0f) return 0.0f;

        float error = setpoint - measurement;

        // 1. Khâu P
        float p_term = cfg_.kp * error;

        // 2. Khâu D với Low-Pass Filter: D_filter = (error - prev_error)/dt * (dt / (dt + Tf))
        float d_raw = (error - prev_error_) / dt;
        float alpha = dt / (dt + cfg_.tf);
        d_filtered_ = d_filtered_ + alpha * (d_raw - d_filtered_);
        float d_term = cfg_.kd * d_filtered_;

        // 3. Khâu I tạm tính
        float i_term_next = integrator_ + cfg_.ki * error * dt;

        // 4. Tổng đầu ra thô
        float u_raw = p_term + i_term_next + d_term;

        // 5. Anti-Windup Clamping: Chỉ cộng tích phân nếu KHÔNG bị bão hòa
        float u_sat = std::clamp(u_raw, cfg_.u_min, cfg_.u_max);
        if (u_raw == u_sat || (error * u_raw < 0.0f)) {
            integrator_ = i_term_next; // Cập nhật tích phân nếu không bão hòa
        }

        prev_error_ = error;
        return u_sat;
    }

private:
    Config cfg_;
    float integrator_{0.0f};
    float prev_error_{0.0f};
    float d_filtered_{0.0f};
};

} // namespace control

int main() {
    control::PIDController::Config cfg{ 10.0f, 2.0f, 0.5f, 0.01f, -12.0f, 12.0f };
    control::PIDController pid(cfg);

    float setpoint = 1.0f;
    float measurement = 0.0f;
    float dt = 0.005f; // 5ms (200Hz)

    for (int step = 0; step < 10; ++step) {
        float u = pid.update(setpoint, measurement, dt);
        std::cout << "Step " << step << " | u = " << u << " V\n";
        measurement += u * 0.01f; // Giả lập đáp ứng hệ thống
    }
    return 0;
}

Thứ 6: Tuning & Analysis Drill

Mục tiêu: Tuning $Q, R$ LQR trên Mô hình Phi tuyến có Bão hòa

📊 Đề Bài: Tuning LQR cho Robot 2 Bánh Tự Cân Bằng bị Bão Hòa $V_{\max} = 12\text{V}$

Cho Robot tự cân bằng có ma trận $A, B$ đã trích xuất từ Tuần 1-2. Đầu ra điều khiển là điện áp động cơ bị bão hòa nghiêm trọng tại $u \in [-12\text{V}, 12\text{V}]$.

Thực hiện các thử nghiệm Tuning trên script Python mô phỏng phi tuyến:

  1. Thử nghiệm 1 (Phạt góc quá bé): Chọn $Q = \text{diag}(1, 0.1, \mathbf{1}, 0.1), R = 0.1$. Thả robot từ $\theta_0 = 8^\circ$. Quan sát đáp ứng.
  2. Thử nghiệm 2 (Lái hung hãn — Phạt điện áp quá bé): Chọn $Q = \text{diag}(1, 0.1, 200, 0.1), R = \mathbf{0.0001}$. Thả robot từ $\theta_0 = 8^\circ$. Quan sát xem lực $u(t)$ có bị bão hòa mép $\pm 12\text{V}$ không và hệ bị dao động ra sao.
  3. Thử nghiệm 3 (Tuning tối ưu bằng Bryson's Rule): Áp dụng Bryson's Rule với sai lệch vị trí tối đa $x_{\max} = 0.2\text{m}$, góc tối đa $\theta_{\max} = 0.05\text{rad} \approx 3^\circ$, và điện áp tối đa $u_{\max} = 12\text{V}$. Tìm $Q, R$ chuẩn và chạy mô phỏng.

✅ Kết Quả Thử Nghiệm Tuning LQR:

  • Thử nghiệm 1 ($Q_{\theta} = 1$ quá bé): Gain $K_\theta$ tính ra quá nhỏ. Bộ điều khiển không đủ lực để chống lại mô-men trọng lực $mgl\sin\theta$. Robot ngã đổ ngay lập tức sau 0.3 giây.
  • Thử nghiệm 2 ($R = 0.0001$ quá bé): Gain $K$ tính ra cực lớn ($K_\theta > 100$). Tín hiệu $u(t)$ bị va dập liên tục vào ngưỡng bão hòa $\pm 12\text{V}$ (Saturated). Hệ rơi vào trạng thái dao động chập chờn (Chattering) và mất ổn định do bão hòa vòng kín.
  • Thử nghiệm 3 (Tuning Bryson's Rule tối ưu): $$Q_{11} = \frac{1}{0.2^2} = 25, \quad Q_{33} = \frac{1}{0.05^2} = 400, \quad R = \frac{1}{12^2} \approx 0.00694$$ Kết quả: $u(t)$ vừa đúng chạm ngưỡng $10-11\text{V}$ ở thời điểm ban đầu mà **không bị bão hòa mép**, góc $\theta$ về $0^\circ$ mượt mà sau $1.2$ giây mà không bị vượt quá (overshoot). Đây là bộ tham số Tuning hoàn hảo!
